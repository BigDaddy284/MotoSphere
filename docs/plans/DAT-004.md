# DAT-004 – The migration runner

**Phase:** 2 – Data store and published data
**Depends on:** DAT-021, DAT-022 and DAT-003 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §11, §12, `docs/WORKFLOW.md`, `DATABASE.md`
("Opening the store", "Units of work", "Where the store is kept between
runs"), `ARCHITECTURE.md` §5, `TESTING.md` ("A data store of its own for
every test"), `backend/src/motosphere/db/store.py`,
`backend/tests/conftest.py`

## Objective

The store's schema is built and changed only by numbered migrations, each
kept as a whole with the store's new version or not at all.

## Why

The store has no table yet. From DAT-006 on, nearly every task of this
phase adds one, and the store that exists by then must be changed to match.
Three things must be settled before the first table:

1. **One way to change the schema.** If tables were simply created from the
   models, a store that already holds records could not be brought to a new
   schema, and nobody could say which schema a given file has.
2. **A change that is half done is worse than none.** A migration that
   fails after its first statement must leave the store exactly as it was,
   and the store must not claim a version it does not have.
3. **A store from the future must not be touched.** A snapshot written by
   newer code, rebuilt and then "migrated" by older code, would be damaged
   without a word.

This is the first fifth of the old "DAT-004 – Schema migrations"
(PLAN-014, in `PROGRESS.md`).

## Design in short

- **A small runner of the project's own, not Alembic.** Alembic would add
  three packages (alembic, Mako and MarkupSafe) for abilities this store
  does not use: several lines of history, ways back, SQL scripts for a
  database someone administers by hand. The store has one writer and one
  line of history, and is rebuilt from its text snapshot on every run. The
  comparison is in `DATABASE.md` ("How the schema changes").
- One new module, `motosphere.db.migrations`.
  - A **migration** is a function that is given a connection and changes
    the schema.
  - The migrations stand in one tuple, `MIGRATIONS`, oldest first. **The
    place of a migration in the tuple is its number**, so a number can be
    neither wrong nor used twice. The tuple is empty in this task: the
    first table comes with DAT-006.
  - `schema_version(store)` reads the number of the last migration the
    store has had. It is kept in the file itself, in the field SQLite gives
    applications for this (`PRAGMA user_version`). A new store is at 0.
  - `migrate(store)` applies the migrations the store lacks, in order, and
    returns their numbers.
- **A migration and its version are one transaction** (`store.begin()`).
  DAT-021 made changes to the schema part of the transaction, and the
  planner checked that `PRAGMA user_version` is too: a migration that fails
  takes its version back with it.
- **A version the list does not know is refused** with `SchemaError` and
  one plain sentence, before anything is written: a store newer than the
  code, or a version below zero, which no migration gives.
- **The error of a failed migration is the caller's.** Nothing catches or
  wraps it.
- **There is no way back.** No migration has a second function that undoes
  it. An earlier state of the store is an earlier snapshot in the `data`
  branch, and a mistake in a merged migration is put right by a new one.
- `migrate` takes the list as an optional second argument, so the tests
  can bring migrations of their own. Without it, `MIGRATIONS` is read at
  that moment, not when the module is loaded.
- No command (DAT-024, DAT-025), no check that the file is a store of
  MotoSphere's at all (DAT-023), no model (DAT-005), no new package.

  on GitHub's SQLite builds too.

## Implementation detail

### 1. `backend/src/motosphere/db/migrations.py` – new, the whole file

```python
"""Migrations: the one way the data store's schema is built and changed.

A migration is a function that changes the schema of a store. The
migrations stand in one list, oldest first, and the place of a migration in
that list is its number. A store records the number of the last migration
it has had (its schema version), and ``migrate`` gives it those it lacks.
"""

from collections.abc import Callable, Sequence

from sqlalchemy import Connection, Engine

__all__ = ["MIGRATIONS", "Migration", "SchemaError", "migrate", "schema_version"]

type Migration = Callable[[Connection], None]

# The history of the store's schema, oldest first. It only ever grows at
# its end: a migration that has been merged is not changed, moved or taken
# out, because stores and snapshots at its version exist.
MIGRATIONS: tuple[Migration, ...] = ()


class SchemaError(Exception):
    """The store's schema cannot be brought up to date. One plain sentence for the user."""


def schema_version(store: Engine) -> int:
    """Say which schema the store has: the number of the last migration it has had.

    A store that has had none is at version 0. The number is kept in the
    file itself, in the field SQLite gives applications for this
    (``user_version``).
    """
    with store.connect() as connection:
        return int(connection.exec_driver_sql("PRAGMA user_version").scalar_one())


def migrate(store: Engine, migrations: Sequence[Migration] | None = None) -> list[int]:
    """Give the store every migration it lacks, in order, and return their numbers.

    Each migration is one transaction together with the store's new
    version: it is kept as a whole or not at all. When one fails, the store
    stays at the version before it, those before it stay applied, and the
    error reaches the caller as it was raised. A migration does not commit;
    this function does.

    ``migrations`` is the whole history, oldest first; by default the
    store's own, ``MIGRATIONS``.

    Raises ``SchemaError``, and leaves the store as it is, when the store's
    version is not one the history knows: the store is newer than this
    code, or it is not a store of MotoSphere's.
    """
    history = MIGRATIONS if migrations is None else migrations
    version = schema_version(store)
    if not 0 <= version <= len(history):
        raise SchemaError(
            f"The data store cannot be brought up to date: its schema is version {version}, "
            f"and this MotoSphere knows only the versions 0 to {len(history)}."
        )
    applied: list[int] = []
    for number, migration in enumerate(history[version:], start=version + 1):
        with store.begin() as connection:
            migration(connection)
            connection.exec_driver_sql(f"PRAGMA user_version = {number}")
        applied.append(number)
    return applied
```

### 2. `backend/tests/integration/test_migrations.py` – new, the whole file, 17 tests

```python
"""Tests of the migration runner, against a real SQLite file of the test's own."""

from pathlib import Path

import pytest
from sqlalchemy import Connection, Engine, event
from sqlalchemy.exc import IntegrityError, InvalidRequestError

from motosphere.db import migrations
from motosphere.db.migrations import Migration, SchemaError, migrate, schema_version
from motosphere.db.store import open_store


def tables(store: Engine) -> list[str]:
    with store.connect() as connection:
        found = connection.exec_driver_sql("SELECT name FROM sqlite_master ORDER BY name")
        return [str(name) for (name,) in found]


def make(table: str) -> Migration:
    """A migration that makes a table. It fails when it is applied a second time."""

    def migration(connection: Connection) -> None:
        connection.exec_driver_sql(f"CREATE TABLE {table} (id INTEGER PRIMARY KEY)")

    return migration


def rename(old: str, new: str) -> Migration:
    """A migration that needs the one before it."""

    def migration(connection: Connection) -> None:
        connection.exec_driver_sql(f"ALTER TABLE {old} RENAME TO {new}")

    return migration


def make_and_fail(table: str, error: BaseException) -> Migration:
    def migration(connection: Connection) -> None:
        connection.exec_driver_sql(f"CREATE TABLE {table} (id INTEGER PRIMARY KEY)")
        raise error

    return migration


def make_and_commit(table: str) -> Migration:
    def migration(connection: Connection) -> None:
        connection.exec_driver_sql(f"CREATE TABLE {table} (id INTEGER PRIMARY KEY)")
        connection.commit()

    return migration


THREE = [make("first"), rename("first", "second"), rename("second", "third")]


def a_parent_and_its_children(connection: Connection) -> None:
    """A migration that makes a table, another that points to it, and rows in both."""
    connection.exec_driver_sql("CREATE TABLE parent (id INTEGER PRIMARY KEY, name TEXT) STRICT")
    connection.exec_driver_sql(
        "CREATE TABLE child (id INTEGER PRIMARY KEY,"
        " parent_id INTEGER NOT NULL REFERENCES parent (id)) STRICT"
    )
    connection.exec_driver_sql("INSERT INTO parent VALUES (1, 'one'), (2, 'two')")
    connection.exec_driver_sql("INSERT INTO child VALUES (10, 1), (11, 2)")


EVERY_ROW = "INSERT INTO parent (id, name) SELECT id, name FROM parent_before"
ALL_BUT_ONE_ROW = "INSERT INTO parent (id, name) SELECT id, name FROM parent_before WHERE id = 1"


def build_parent_anew(fill_it_again: str) -> Migration:
    """A migration that makes a change SQLite cannot make in place.

    The table is copied aside, dropped, made anew under its own name and
    filled again, while other rows point to it. Foreign keys stay on; they
    are only checked later, when the transaction ends.
    """

    def migration(connection: Connection) -> None:
        connection.exec_driver_sql("PRAGMA defer_foreign_keys = ON")
        connection.exec_driver_sql("CREATE TABLE parent_before AS SELECT * FROM parent")
        connection.exec_driver_sql("DROP TABLE parent")
        connection.exec_driver_sql(
            "CREATE TABLE parent (id INTEGER PRIMARY KEY, name TEXT NOT NULL, added TEXT) STRICT"
        )
        connection.exec_driver_sql(fill_it_again)
        connection.exec_driver_sql("DROP TABLE parent_before")

    return migration


def columns_of_parent(store: Engine) -> list[str]:
    with store.connect() as connection:
        found = connection.exec_driver_sql("SELECT name FROM pragma_table_info('parent')")
        return [str(name) for (name,) in found]


def test_a_new_store_is_at_version_zero(store: Engine) -> None:
    assert schema_version(store) == 0


def test_migrating_applies_every_migration_in_order(store: Engine) -> None:
    applied = migrate(store, THREE)

    assert applied == [1, 2, 3]
    assert schema_version(store) == 3
    assert tables(store) == ["third"]


def test_migrating_twice_changes_nothing(store: Engine) -> None:
    migrate(store, THREE)

    applied = migrate(store, THREE)

    assert applied == []
    assert schema_version(store) == 3
    assert tables(store) == ["third"]


def test_only_the_migrations_a_store_lacks_are_applied(store: Engine) -> None:
    migrate(store, THREE[:1])

    applied = migrate(store, THREE)

    assert applied == [2, 3]
    assert schema_version(store) == 3
    assert tables(store) == ["third"]


def test_the_version_is_there_when_the_store_is_opened_again(store: Engine) -> None:
    migrate(store, THREE[:2])

    opened_again = open_store(Path(str(store.url.database)))

    assert schema_version(opened_again) == 2
    assert migrate(opened_again, THREE) == [3]


@pytest.mark.parametrize(
    "error",
    [RuntimeError("the migration failed part-way"), KeyboardInterrupt()],
    ids=["an error", "Ctrl+C"],
)
def test_a_migration_that_fails_leaves_the_store_at_the_version_before_it(
    store: Engine, error: BaseException
) -> None:
    with pytest.raises(type(error)) as caught:
        migrate(store, [make("first"), make_and_fail("second", error), make("third")])

    assert caught.value is error
    assert schema_version(store) == 1
    assert tables(store) == ["first"]


def test_a_store_goes_on_from_where_a_migration_failed(store: Engine) -> None:
    error = RuntimeError("the migration failed part-way")
    with pytest.raises(RuntimeError):
        migrate(store, [make("first"), make_and_fail("second", error), make("third")])

    applied = migrate(store, [make("first"), make("second"), make("third")])

    assert applied == [2, 3]
    assert tables(store) == ["first", "second", "third"]


def test_each_migration_is_one_transaction_with_its_version(store: Engine) -> None:
    commits: list[object] = []
    event.listen(store, "commit", commits.append)

    migrate(store, THREE)

    assert len(commits) == 3


def test_a_store_newer_than_the_history_is_refused_and_left_as_it_is(store: Engine) -> None:
    migrate(store, THREE)

    with pytest.raises(SchemaError) as refusal:
        migrate(store, THREE[:2])

    assert str(refusal.value) == (
        "The data store cannot be brought up to date: its schema is version 3, "
        "and this MotoSphere knows only the versions 0 to 2."
    )
    assert schema_version(store) == 3
    assert tables(store) == ["third"]


def test_a_version_no_migration_gave_is_refused_and_the_store_left_as_it_is(store: Engine) -> None:
    with store.begin() as connection:
        connection.exec_driver_sql("PRAGMA user_version = -1")

    with pytest.raises(SchemaError) as refusal:
        migrate(store, THREE)

    assert str(refusal.value) == (
        "The data store cannot be brought up to date: its schema is version -1, "
        "and this MotoSphere knows only the versions 0 to 3."
    )
    assert schema_version(store) == -1
    assert tables(store) == []


def test_a_migration_that_commits_by_itself_fails(store: Engine) -> None:
    with pytest.raises(InvalidRequestError):
        migrate(store, [make_and_commit("first"), make("second")])

    assert schema_version(store) == 0
    assert tables(store) == ["first"]


def test_the_stores_own_history_is_used_when_none_is_given(
    store: Engine, monkeypatch: pytest.MonkeyPatch
) -> None:
    monkeypatch.setattr(migrations, "MIGRATIONS", tuple(THREE))

    applied = migrate(store)

    assert applied == [1, 2, 3]
    assert tables(store) == ["third"]


def test_the_stores_own_history_brings_an_empty_store_to_the_newest_schema(store: Engine) -> None:
    newest = len(migrations.MIGRATIONS)

    applied = migrate(store)

    assert applied == list(range(1, newest + 1))
    assert schema_version(store) == newest
    assert migrate(store) == []


def test_a_migration_can_build_anew_a_table_that_rows_point_to(store: Engine) -> None:
    applied = migrate(store, [a_parent_and_its_children, build_parent_anew(EVERY_ROW)])

    assert applied == [1, 2]
    assert tables(store) == ["child", "parent"]
    assert columns_of_parent(store) == ["id", "name", "added"]
    with store.connect() as connection:
        assert connection.exec_driver_sql("SELECT id, parent_id FROM child").all() == [
            (10, 1),
            (11, 2),
        ]
        assert connection.exec_driver_sql("PRAGMA foreign_key_check").all() == []


def test_foreign_keys_are_enforced_again_after_such_a_migration(store: Engine) -> None:
    migrate(store, [a_parent_and_its_children, build_parent_anew(EVERY_ROW)])

    with pytest.raises(IntegrityError), store.begin() as connection:
        connection.exec_driver_sql("INSERT INTO child VALUES (12, 99)")


def test_such_a_migration_is_refused_when_it_loses_a_row_that_is_pointed_to(store: Engine) -> None:
    with pytest.raises(IntegrityError):
        migrate(store, [a_parent_and_its_children, build_parent_anew(ALL_BUT_ONE_ROW)])

    assert schema_version(store) == 1
    assert tables(store) == ["child", "parent"]
    assert columns_of_parent(store) == ["id", "name"]
    with store.connect() as connection:
        assert connection.exec_driver_sql("SELECT id FROM parent").all() == [(1,), (2,)]
```

## Acceptance criteria

1. A new store is at version 0. `migrate` applies every migration in order
   and returns their numbers; the store is then at the newest version, and
   still is when it is opened again.
2. Migrating a second time applies nothing and changes nothing. A store
   that has had some of the migrations is given only those it lacks.
3. A migration that fails, with an ordinary error or one that is not (as
   Ctrl+C is), leaves the store at the version before it, with nothing of
   the failed migration kept; the migrations before it stay applied; the
   error reaches the caller as the same object; and the store goes on from
   there once the migration is mended.
4. Each migration is one transaction together with its version: three
   migrations are three commits.
5. A store newer than the list, or at a version below zero, is refused with
   `SchemaError` and "The data store cannot be brought up to date: its
   schema is version N, and this MotoSphere knows only the versions 0 to
   M.", and is left as it is.
6. `migrate(store)` without a list uses `MIGRATIONS` as it is at that
   moment, and one test brings an empty store to the newest schema with the
   real list.
7. A migration that commits by itself fails, and the store's version does
   not move.
8. A migration can build anew a table that rows of another table point to,
   inside its transaction and with foreign keys on; foreign keys are
   enforced afterwards; and if it loses a row that is pointed to, it is
   refused and the store is as it was before.
9. The type check passes with SQLAlchemy's own types and no `ignore`, and
   the lint passes with no `noqa`.
10. No existing test changed, and all pass. The full run reports 19 of 19
    gates and 851 tests (backend tests 221).
11. On the pull request, "All gates (Linux)" and "All gates (Windows)" are
    green with those numbers, and the three jobs after the gates are
    skipped.
12. Only the files under "Scope" changed.
