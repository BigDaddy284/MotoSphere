## Objective

A Python project under `backend/` that installs reproducibly from a lock file
on Windows 11 and Linux, exposes an importable `motosphere` package with a
version, and runs a pytest suite. Nothing else: no web framework, no linting,
no type checking, no settings. Those are FND-003 onwards.

## Implementation detail

### 1. `backend/pyproject.toml`

```toml
[project]
name = "motosphere"
version = "0.1.0"
description = "MotoSphere backend: API, data layer and collection workers."
requires-python = ">=3.12"
dependencies = []

[dependency-groups]
dev = [
    "pytest>=8.3",
]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/motosphere"]

[tool.pytest.ini_options]
minversion = "8.0"
testpaths = ["tests"]
addopts = ["-ra", "--strict-markers", "--strict-config", "--import-mode=importlib"]
xfail_strict = true
filterwarnings = ["error"]
```

Notes:

- The build system is what makes `uv sync` install the project itself
  (editable) into the virtual environment, so tests import the real installed
  package from `src/`, not a path hack. Do not add `pythonpath` to the pytest
  configuration and do not manipulate `sys.path` anywhere.
- `--import-mode=importlib` lets test files live in sub-directories without
  `__init__.py` files and without name clashes.
- `filterwarnings = ["error"]` turns any warning during tests into a failure,
  so deprecations are dealt with when they appear.
- The `dev` dependency group is installed by `uv sync` by default.
- This layout was trial-run by the planner with uv 0.11 and pytest 9: it
  syncs, installs `motosphere==0.1.0` and runs tests cleanly.

### 2. `backend/uv.lock`

Generate with `uv lock` (or the first `uv sync`) from inside `backend/`.
Commit it exactly as generated. Do not hand-edit it.

### 3. `backend/src/motosphere/__init__.py`

A module docstring (one line saying what the package is) and:

```python
from importlib.metadata import version

__version__ = version("motosphere")
```

The version has one source of truth, `pyproject.toml`. Do not write a version
literal in Python code. Export `__version__` via `__all__`.

### 4. `backend/src/motosphere/py.typed`

Empty file.

### 5. `backend/tests/unit/test_package.py`

Exactly these four tests. Locate `backend/` from the test file
(`Path(__file__).resolve().parents[2]`), never from the current directory.
Read `pyproject.toml` with the standard-library `tomllib`. Add full type
annotations (`-> None`) so the file is ready for strict type checking in
FND-004.

1. `test_package_imports` – `import motosphere` succeeds and the module has a
   non-empty docstring.
2. `test_version_matches_pyproject` – `motosphere.__version__` equals
   `project.version` read from `backend/pyproject.toml`.
3. `test_version_is_well_formed` – `motosphere.__version__` is a `str` that
   fully matches `MAJOR.MINOR.PATCH` with numeric parts
   (`^\d+\.\d+\.\d+$`).
4. `test_package_is_loaded_from_src` – the resolved parent directory of
   `motosphere.__file__` equals `backend/src/motosphere` (proves the tests run
   against this checkout's source and not some other installed copy).

## Acceptance criteria

1. `uv sync --locked` succeeds from a clean checkout and installs the project
   itself.
2. `uv run pytest` collects and passes exactly the four tests above.
3. `motosphere.__version__` equals the version in `pyproject.toml`, which is
   its only source.
4. `uv.lock` is committed and current (`uv lock --check` passes); no virtual
   environment, cache or build output is tracked or left untracked-but-visible
   (`git status` is clean after a full run).
5. README, TESTING.md and CHANGELOG.md describe the new gate, and the
   repository checks still pass 9/9.
6. Only the files listed under "Scope" are added or modified.

## Verification

From a clean state (delete `backend/.venv` first if it exists):

```
cd backend
uv lock --check
uv sync --locked
uv run pytest -v
cd ..
python -m unittest discover -s tests/repo -v
git status --short
```

Expected: lock check passes; sync installs `motosphere` and pytest; pytest
reports `4 passed` with no warnings and no errors; repository checks report
`Ran 9 tests` and `OK`; `git status --short` prints nothing once your work is
committed.

If more than one Python is available, also run the tests on the other one,
for example `uv run --python 3.12 pytest` and `uv run --python 3.13 pytest`.

Then prove the suite can fail (do not commit these changes):

1. Temporarily replace the `__version__` assignment with the literal
   `"9.9.9"` → `test_version_matches_pyproject` must fail. Restore it.
2. Temporarily add `import warnings; warnings.warn("x")` inside one test →
   that test must fail because warnings are errors. Restore it.

Finish with `git status` clean and both suites green.
