## Objective

Component tests for the frontend that run with one command, using Vitest,
jsdom and Testing Library, with the first tests covering what exists today:
the `App` component and the entry point.

## Implementation detail

vitest 5.1, jsdom 31, @testing-library/react 16.3 and

reported no vulnerabilities.

### Dependencies and scripts

Add as dev dependencies (`npm install -D`): `vitest`, `jsdom`,
`@testing-library/react`, `@testing-library/jest-dom`. Nothing else.

Add to `scripts` in `package.json`:

| Script | Command | Purpose |
|---|---|---|
| `test` | `vitest run` | Run every test once and exit (the gate) |
| `test:watch` | `vitest` | Re-run on change while developing |

### `vitest.config.ts`

```ts
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vitest/config'

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    include: ['src/**/*.test.{ts,tsx}'],
    setupFiles: ['./src/test/setup.ts'],
    restoreMocks: true,
    passWithNoTests: false,
  },
})
```

Keep it separate from `vite.config.ts` so the application build configuration
stays free of test concerns. Do not enable `globals`: tests import `describe`,
`it`, `expect` and `vi` explicitly from `vitest`, which keeps them fully
typed without extra type configuration.

Add `"vitest.config.ts"` to the `include` array of `tsconfig.node.json` so
the configuration file is type-checked. Test files live under `src/`, so
`tsconfig.app.json` already type-checks them.

### `src/test/setup.ts`

Imports `@testing-library/jest-dom/vitest` (adds matchers such as
`toBeVisible` with their types) and registers an `afterEach` that calls
Testing Library's `cleanup()`.

### `src/App.test.tsx` – exactly 3 tests

Query by role and text, the way a user perceives the page. Import `APP_NAME`
and `APP_TAGLINE` from `./App.tsx` for the expected values.

1. `shows the application name as the main heading` – a level-1 heading
   named `APP_NAME` is visible.
2. `shows the tagline` – the text `APP_TAGLINE` is visible.
3. `has exactly one main landmark` – there is exactly one element with the
   role `main`.

### `src/main.test.tsx` – exactly 2 tests

`main.tsx` runs when it is imported, so each test imports it dynamically after
preparing the document. Call `vi.resetModules()` before each test so every
import runs the module again, and empty `document.body` after each test.

1. `renders the application into the root element` – with
   `<div id="root"></div>` in the body, `await import('./main.tsx')`, then the
   level-1 heading named `APP_NAME` appears (use `findByRole`, which waits for
   React to render).
2. `fails with a clear message when the root element is missing` – with an
   empty body, `import('./main.tsx')` rejects with an error whose message
   contains `no element with id "root"`.

## Acceptance criteria

1. `npm test` runs once, passes exactly the five tests above and exits 0; it
   exits non-zero when an assertion fails.
2. Tests query the page by role and text.
3. Test files are type-checked by `npm run typecheck` and are not part of the
   production bundle.
4. README, TESTING.md and CHANGELOG.md describe the new gate.
5. Type check, build, repository checks (9/9) still pass; the backend is
   untouched; no file outside "Scope" is touched.

## Verification

From a clean state (delete `frontend/node_modules` and `frontend/dist` first
if they exist):

```
cd frontend
npm ci
npm test
npm run typecheck
npm run build
npm audit
cd ..
python -m unittest discover -s tests/repo -v
git status --short
```

Expected: `Test Files  2 passed (2)` and `Tests  5 passed (5)` with no
warnings printed; type check exits 0; the build output lists one script
bundle and its size is the same as before this task (test code is not
bundled; confirm by searching `dist/` for the text `vitest` and finding
nothing); `npm audit` finds 0 vulnerabilities; `Ran 9 tests` / `OK`; clean
status once committed.

Then prove the tests can fail (do not commit these changes), recording the
exit code of `npm test` each time:

1. In `src/App.tsx`, temporarily change the `<h1>` to an `<h2>` → test 1 of
   `App.test.tsx` and test 1 of `main.test.tsx` must fail, exit code non-zero.
   Restore it.
2. In `src/main.tsx`, temporarily change the error message text → test 2 of
   `main.test.tsx` must fail. Restore it.
3. Temporarily add a type error to `src/App.test.tsx` (for example
   `const n: number = 'x'`) → `npm run typecheck` must exit non-zero, proving
   test files are type-checked. Restore it.

Finish with `git status` clean.
