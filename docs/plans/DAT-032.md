# DAT-032 – A table without its timestamps is named

**Phase:** 2 – Data store and published data
**Depends on:** DAT-031 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §11, §12, `docs/WORKFLOW.md`, `DATABASE.md`
("The rules every table keeps", "When a row was stored and changed"),
`TESTING.md` ("The rules every table keeps"),
`backend/src/motosphere/db/base.py`,
`backend/tests/unit/test_db_base.py`

## Objective

`broken_rules` names a table that does not have the two times every table
has, and so the test that holds the real schema to the rules fails on such
a table.

## Why

A model gets `created_at` and `updated_at` from `Base` without naming them
(DAT-031). But a model can name them itself and get them wrong, and a table
can be made without a model, as a table that only links two others often
is. Such a table would have rows that do not say when they were stored or
changed, or that say it wrongly, and nothing would notice. `broken_rules`
already names a table that is not strict or is without the key every table
has; this task makes it name a table without the two times too, before the
first table is made (DAT-006).

This is the second half of what PLAN-018 called "DAT-031 – Every table's
timestamps" (PLAN-019, in `PROGRESS.md`).

## Design in short

- **One more rule in `broken_rules`, and one more sentence.** A table has
  the two times if it has the columns `created_at` and `updated_at`, and
  - each is a time as the store keeps one (`UtcDateTime`);
  - each must be there in every row (not nullable);
  - the table gives neither a value of its own (no server default);
  - the store's code gives each its value by calling a function when the
    statement runs (a Python-side default that is callable: not none, not
    one fixed value, and not an expression SQLite is asked for);
  - `created_at` is not set anew when a row is changed (no `onupdate`);
  - `updated_at` is, by calling a function (a callable `onupdate`).
- **The sentence** names the table and is the same for every way of being
  without the times:
  `The table X does not have the times every table has: created_at and
  updated_at, which the store's code sets when a row is first stored and
  whenever it is changed.` (one line in the list).
- **The order of a table's sentences**: not strict, the key, the times,
  then the names given by hand. Tables stay in the order of their names.
- **What the rule does not see**: which function the store's code calls.
  That it is the store's clock is what a model gets from `Base` by not
  naming the two columns, and `DATABASE.md` says so. The rule does not
  look at the place of the two columns in the table either.
- **The tables the unit tests make by hand get the two times**, from two
  new helpers of the test file, `a_time` and `the_times`, as they got the
  key from `the_key` in DAT-029.
- No new package, no model, no table, no migration. `Base` does not
  change: only the function `_has_the_times` and the six lines of
  `broken_rules` that ask it are new in `base.py`.

## Existing tests that change, and why

Only `backend/tests/unit/test_db_base.py` changes. Its tables made by hand
have no time columns today, so every one of them would break the new rule.
Nothing is taken out to get a pass; each test still asks what it asked,
and one asks for more. They are 12 tests in five functions, the
12 that failed in the trial with only `base.py` changed.

  tables get the two times, so each still breaks the rule of the key only.

## Acceptance criteria

1. `broken_rules` gives one sentence, the one under "Design in short", for
   a table without the two times, in each of these ways: neither column;
   one of the two missing; and for each of the two: of another type, one
   that may be empty, one the table sets itself, one the store's code does
   not set, one that is one fixed moment, one that SQLite is asked for; a
   `created_at` that is set anew at a change; an `updated_at` that is not,
   one that a change sets to one fixed moment, and one that a change asks
   SQLite for.
2. A table that has the two times and keeps the other rules gives an empty
   list, and so do the real schema and the models of the integration
   tests.
3. A table that breaks all four rules gets its sentences in this order:
   not strict, the key, the times, the names given by hand.
4. The type check passes with no `ignore`, and the lint with no `noqa`.
5. The full run reports 19 of 19 gates and 1032 tests (backend tests
   402).
6. On the pull request, "All gates (Linux)" and "All gates (Windows)" are
   green with those numbers, and the three jobs after the gates are
   skipped.
7. Only the files under "Scope" changed.
