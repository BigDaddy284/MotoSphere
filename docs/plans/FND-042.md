# FND-042 – Phones: the layout follows the visible height

**Phase:** 1 – Foundation
**Depends on:** FND-041 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §8, `docs/WORKFLOW.md`, `TESTING.md`

## Objective

On a phone the layout is as tall as the part of the screen the browser
really shows, so its lower edge is never under the browser's own bars.

## Why

A phone's browser shows and hides its own bars (the address bar, the
buttons at the bottom) as the visitor scrolls or taps. The layout is
`100vh` tall today, and on a phone `vh` is measured as if those bars were
hidden: while they are shown, the lower part of the layout lies under them.
For an application whose whole screen is one fixed layout, and later a
globe with controls at its edges, that part would be out of reach. This is
the last of five small tasks (PLAN-009).

## Design in short

- The layout's height and the page's least height become `100dvh`: the
  "dynamic" height, which follows the browser's bars as they come and go.
  On a desktop browser the two heights are the same, so nothing changes
  there.
- **No `100vh` line as a fallback.** The task's first wording asked for
  one, and the planner's trial showed why not: the build is made for
  Vite's default list of browsers (Chrome and Edge 111, Firefox 114, Safari
  and iOS 16.4), all of which know `dvh`, so the build's own minifier
  removes a `100vh` line that is followed by `100dvh` as dead code. A
  browser old enough to need the fallback would not run the application's
  script either. One line, then, and `TASKS.md` says so.
- A unit test rejects `vh` in any style sheet under `frontend/src`, so a
  style sheet added later cannot bring the old height back unnoticed.
- Style sheets only. No change to any component, no script.

**What no test here can show.** The test browser is a desktop browser: it
has no bars that come and go, and `100dvh` and `100vh` are the same number
in it. The tests show that the style sheets, as the browser received them,
ask for the right height, that the layout is exactly as tall as the screen
at every tested size, and that nothing else changed. The effect on a real
phone is confirmed by the owner on the published site, and recorded as
that, not as a test result.

## Implementation detail

### 1. `frontend/e2e/height.spec.ts` – new, the whole file, 5 tests

```ts
import type { Page } from '@playwright/test'
import { expect, test } from './fixtures'

// The height that follows the bars a phone's browser shows and hides.
const VISIBLE_HEIGHT = '100dvh'

/**
 * What the style sheets, as the browser received them, ask for a property of
 * an element: the value of the last rule that matches the element and sets it.
 */
async function asked(page: Page, selector: string, property: string): Promise<string> {
  return page.evaluate(
    ([chosen, name]) => {
      const element = document.querySelector(chosen)
      if (element === null) {
        throw new Error(`${chosen} is not on the page`)
      }
      let value = ''
      for (const sheet of document.styleSheets) {
        for (const rule of sheet.cssRules) {
          if (rule instanceof CSSStyleRule && element.matches(rule.selectorText)) {
            value = rule.style.getPropertyValue(name) || value
          }
        }
      }
      return value
    },
    [selector, property] as const,
  )
}

test('the layout asks for the height of the visible screen', async ({ page }) => {
  await page.goto('./')

  expect(await asked(page, '#root > div', 'height')).toBe(VISIBLE_HEIGHT)
})

test('the page asks for at least the height of the visible screen', async ({ page }) => {
  await page.goto('./')

  expect(await asked(page, 'body', 'min-height')).toBe(VISIBLE_HEIGHT)
})

for (const viewport of [
  { width: 390, height: 844 },
  { width: 844, height: 390 },
  { width: 1366, height: 768 },
]) {
  test.describe(`at ${viewport.width}×${viewport.height}`, () => {
    test.use({ viewport })

    test('the layout is exactly as tall as the screen', async ({ page }) => {
      await page.goto('./')

      const layout = await page.locator('#root > div').boundingBox()
      expect(layout).toEqual({ x: 0, y: 0, width: viewport.width, height: viewport.height })
    })
  })
}
```

The helper `asked` reads the rules the browser holds for the page, not the
computed value: the computed height is a number of pixels and would be the
same for `100vh` and `100dvh` in this browser.
