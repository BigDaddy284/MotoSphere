## Objective

A helper of the browser tests gives the colour of one point of the
page as the browser shows it, a 3D picture too, without the page
reading its own picture.

## Why

That the Earth is drawn will be proven from its pixels (GLB-003): a
test has to know what a person sees. In the planner's trial for
PLAN-053 a page that read its own 3D picture back (`gl.readPixels`)
made the browser log a warning, and every browser test fails on a
warning. So the picture is read from outside the page: Playwright takes
a picture of one pixel, and the helper reads the colour from that PNG
with what Node.js brings. The task has no globe in it. The helper is
tested with colours the test itself puts on the page, flat in the
project of the other tests and in 3D in the project of the globe.

## What this task is, and what it is not

- **It is** one new module, `frontend/e2e/pixel.ts`, with two
  functions: `colourOfOnePixel(png)` and `colourAt(page, x, y)`.
- **It is** 18 new browser tests: 17 in `frontend/e2e/pixel.spec.ts`
  (project `chromium`) and 1 in `frontend/e2e/globe/pixel.spec.ts`
  (project `globe`).
- **It is** the documents: `TESTING.md`, `ARCHITECTURE.md` and
  `CHANGELOG.md`.
- **It is not** a change to the page. Nothing under `frontend/src`
  changes.
- **It is not** a globe, and not a test of one: that is GLB-002 and
  GLB-003.
- **It is not** a new package. `node:zlib` comes with Node.js, and the
  lock files are unchanged.
- **It is not** a change to any test that is there, to the fixtures, to
  the settings of Playwright, to `scripts/check.py` or to the workflow.

## Design in short

`frontend/e2e/pixel.ts`:

- `Colour` is red, green and blue, each from 0 to 255:
  `readonly [red: number, green: number, blue: number]`.
- `colourAt(page, x, y)` asks the page how large it is
  (`window.innerWidth`, `window.innerHeight`), refuses a point that is
  not a point of the page, has Playwright take a picture of that one
  pixel (`page.screenshot` with `clip` and `scale: 'css'`), and gives
  what `colourOfOnePixel` reads from it.
- `colourOfOnePixel(png)` reads a PNG of one pixel: its chunks, each
  against its checksum; its header, which must be the first chunk, and
  its end, which must be the last; the data of all its `IDAT` chunks
  together, unpacked with `inflateSync`; and from the one line its
  filter and its pixel. Read are the two kinds a browser makes: eight
  bits for each of red, green and blue (colour type 2), with or without
  a fourth byte for how opaque the pixel is (colour type 6), not
  interlaced.

| What is asked | What is said |
|---|---|
| A point that is not a point of the page: left of it, above it, at or beyond its width or height, between two pixels, or no number | `(1280, 0) is not a point of the page, which is 1280 by 720 pixels.` |
| What is no PNG | `This is not a PNG picture.` |
| A PNG that is cut short, has a chunk whose checksum is wrong, does not begin with its header or end with its end, has data that cannot be unpacked, or a line that is not as long as one pixel or is filtered in a way there is none of | `The PNG picture is damaged.` |
| A PNG of more or fewer pixels than one | `The PNG picture is 2 by 1 pixels, not one pixel.` |
| A PNG of another kind | `The PNG picture is of a kind that is not read here (bit depth 16, colour type 2, interlace 0). Read are bit depth 8, colour type 2 or 6, interlace 0.` |
| A pixel that is not opaque | `The pixel of the PNG picture is not opaque (128 of 255), so its colour is not what is seen.` |

## What the trial settled

- **A picture of one pixel, taken by Playwright, is read exactly.** A
  flat picture of known colours is read at eighteen points of a page of
  1280 by 720 pixels, the one pixel in each corner among them, and each
  colour is the colour that was drawn, to the number. A 3D picture
  whose upper half is cleared to one colour and whose lower half to
  another is read exactly at ten points in the project `globe`, and the
  browser says nothing on the console.
- **What the browser makes.** The PNG the browser of the tests made of
  one pixel was 87 bytes: eight bits, colour type 2 (red, green and
  blue), not interlaced, with its data in two `IDAT` chunks. So the
  data of all `IDAT` chunks is put together before it is unpacked; a
  reader that takes the first alone fails on the browser's own picture.
  That picture is kept in the tests, byte for byte, as
  `FROM_THE_BROWSER`.
- **Colour type 6 is read too, and only when opaque.** A browser can
  give a picture with a fourth byte. A pixel that is not opaque has a
  colour that is not what a person sees, so it is refused and says how
  opaque it is.
- **Every filter leaves the one pixel as it is.** A line of a PNG
  begins with the way it is filtered, one of five. By the rules of the
  format each of them changes a byte by what stands left of it or
  above it, and the first pixel of the first line has neither. So the
  pixel is read as it stands under each of the five, and a sixth is
  refused. The tests give a line under each of the five; the line of
  the browser's own picture says the fifth of them (filter 4).
- **Nothing is guessed.** A PNG is refused when it is cut short after
  any of its bytes, and when any one of its bytes is another: two tests
  go through every byte of a picture made in the test and of the
  browser's own, and no changed picture is read as a colour. Every
  chunk has a checksum, so a changed byte is found wherever it stands.
- **The page is asked how large it is.** Playwright knows the size only
  of a page it gave one (`page.viewportSize()`), and a test of this
  project cannot make a page without one. The page itself always knows
  (`window.innerWidth`, `window.innerHeight`), so there is one way and
  no branch that no test can reach.
- **One pixel of the page is one pixel of the picture.** On a screen
  that is twice as sharp Playwright would give a picture of two by two
  pixels for one pixel of the page; with `scale: 'css'` it gives one.
  A test makes a page of 200 by 100 pixels on a screen of 1920 by 1080
  that is twice as sharp and reads it pixel for pixel of the page.
- **What it costs.** On the planner's Linux machine a point took about
  35 thousandths of a second. A test asks for the points it needs.
- **No package.** `inflateSync` and `crc32` of `node:zlib` are all that
  is used. Both are in the Node.js the tests ran on, 22.23.4 here and
  22.23.5 on GitHub's two machines (below).

## The new tests

`frontend/e2e/pixel.spec.ts`, 17 tests, in the project `chromium`.

Thirteen give `colourOfOnePixel` a picture and need no page. The
pictures are made in the test, chunk by chunk (`chunk`, `header`,
`lineOf`, `png`), so that each can be wrong in exactly one way:

- `is read from red, green and blue`, also black and white;
- `is read from red, green, blue and a fourth that says the pixel is
  opaque`;
- `is the same however the line is filtered`: each of the five, in
  both kinds;
- `is read from data in several pieces, with other chunks between`;
- `is read from a picture as the browser made it`;
- `is not read from what is no PNG`: nothing, a text, the first bytes
  of a JPEG, and the first seven bytes of a PNG;
- `is not read from a picture of more or fewer pixels than one`;
- `is not read from a picture of another kind`: six kinds, each with
  its sentence;
- `is not read from a pixel that is not opaque`;
- `is not read from a picture whose parts are not as a PNG has them`:
  thirteen pictures;
- `says what the unpacking said of data that cannot be unpacked`;
- `is not read from a picture that is cut short anywhere`;
- `is not read from a picture in which any one byte is another`.

Four ask a page:

- `is the colour the page shows there, at its corners and edges too`:
  a flat picture of four quarters over a page of the site, with a
  colour of its own for the one pixel in each corner, read at eighteen
  points;
- `is what the page shows when it is asked for`: the answer changes
  when what the page shows changes;
- `is not given for a point that is not a point of the page`: nine
  points, each with its sentence;
- `is one pixel for one pixel of the page on a screen with more`.

`frontend/e2e/globe/pixel.spec.ts`, 1 test, in the project `globe`:

- `is read from outside the page, without a word of the browser`: a
  page of the site shows a 3D picture, its upper half in one colour and
  its lower half in another; both are read exactly at ten points, the
  four corners among them. The rule of every browser test hears
  nothing on the console.

The browser tests go from 273 to 291.

+  checksum.writeUInt32BE(crc32(kindAndData))
+  return Buffer.concat([length, kindAndData, checksum])

+/**
+ * Reading what the page shows, from outside the page.
+ *
+ * A test that wants to know whether the globe is drawn has to look at the
+ * picture. A page that reads its own 3D picture makes the browser log a
+ * warning, and every browser test fails on a warning. So the picture is read
+ * from outside: Playwright takes a picture of one pixel of the page as the
+ * browser shows it, and the colour is read from that PNG here, with what
+ * Node.js brings (FND-060; TESTING.md, "Reading what the page shows").
+ */
+
+/** A colour as the page shows it: red, green and blue, each from 0 to 255. */
+export type Colour = readonly [red: number, green: number, blue: number]
+
+/** What every PNG begins with. */
+const SIGNATURE = Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a])
+
+/** How many bytes a pixel has, for the kinds of PNG that are read here. */
+const BYTES_OF_A_PIXEL = new Map([
+  [2, 3], // red, green, blue
+  [6, 4], // red, green, blue, and how opaque
+])
+
+/** The highest of the five ways a line of a PNG can be filtered. */
+const LAST_FILTER = 4
+
+const DAMAGED = 'The PNG picture is damaged.'
+
+type Chunk = { readonly kind: string; readonly data: Buffer }
+
+/** The chunks a PNG is made of, each checked against its checksum. */
+function chunksOf(png: Buffer): Chunk[] {
+  if (!png.subarray(0, SIGNATURE.length).equals(SIGNATURE)) {
+    throw new Error('This is not a PNG picture.')
+  }
+  const chunks: Chunk[] = []
+  let at = SIGNATURE.length
+  while (at < png.length) {
+    // A chunk is its length, its kind, its data and its checksum.
+    if (at + 12 > png.length) {
+      throw new Error(DAMAGED)
+    }
+    const end = at + 8 + png.readUInt32BE(at)
+    if (end + 4 > png.length) {
+      throw new Error(DAMAGED)
+    }
+    const kindAndData = png.subarray(at + 4, end)
+    if (crc32(kindAndData) !== png.readUInt32BE(end)) {
+      throw new Error(DAMAGED)
+    }
+    chunks.push({ kind: kindAndData.toString('latin1', 0, 4), data: kindAndData.subarray(4) })
+    at = end + 4
+  }
+  return chunks
+}
+
+/**
+ * The colour of a PNG picture of one pixel.
+ *
+ * Read are the two kinds a browser makes: eight bits for each of red, green
+ * and blue, with or without a fourth for how opaque the pixel is, not
+ * interlaced. Any other picture is refused with a sentence, and so is a
+ * pixel that is not opaque: its colour is not what a person sees.
+ */
+export function colourOfOnePixel(png: Buffer): Colour {
+  const chunks = chunksOf(png)
+  // A PNG begins with its header and ends with its end.
+  const header = chunks[0]
+  if (
+    header === undefined ||
+    header.kind !== 'IHDR' ||
+    header.data.length !== 13 ||
+    chunks.at(-1)?.kind !== 'IEND'
+  ) {
+    throw new Error(DAMAGED)
+  }
+  const width = header.data.readUInt32BE(0)
+  const height = header.data.readUInt32BE(4)
+  if (width !== 1 || height !== 1) {
+    throw new Error(`The PNG picture is ${width} by ${height} pixels, not one pixel.`)
+  }
+  const depth = header.data.readUInt8(8)
+  const kind = header.data.readUInt8(9)
+  const interlaced = header.data.readUInt8(12)
+  const bytes = BYTES_OF_A_PIXEL.get(kind)
+  if (depth !== 8 || bytes === undefined || interlaced !== 0) {
+    throw new Error(
+      `The PNG picture is of a kind that is not read here (bit depth ${depth}, colour type ${kind}, interlace ${interlaced}). Read are bit depth 8, colour type 2 or 6, interlace 0.`,
+    )
+  }
+  const packed = Buffer.concat(
+    chunks.filter((chunk) => chunk.kind === 'IDAT').map((chunk) => chunk.data),
+  )
+  let line: Buffer
+  try {
+    line = inflateSync(packed)
+  } catch (error) {
+    throw new Error(DAMAGED, { cause: error })
+  }
+  // A line is the way it is filtered and then its pixels. Every filter
+  // leaves the first pixel of the first line as it is, so the one pixel of
+  // this picture is read as it stands.
+  if (line.length !== 1 + bytes || line.readUInt8(0) > LAST_FILTER) {
+    throw new Error(DAMAGED)
+  }
+  if (bytes === 4 && line.readUInt8(4) !== 255) {
+    throw new Error(
+      `The pixel of the PNG picture is not opaque (${line.readUInt8(4)} of 255), so its colour is not what is seen.`,
+    )
+  }
+  return [line.readUInt8(1), line.readUInt8(2), line.readUInt8(3)]
+}
+
+/**
+ * The colour of the point of the page that is `x` pixels from its left edge
+ * and `y` from its top, as the browser shows it.
+ */
+export async function colourAt(page: Page, x: number, y: number): Promise<Colour> {
+  // The page is asked how large it is: Playwright knows the size only of a
+  // page it gave one.
+  const [width, height] = await page.evaluate(
+    () => [window.innerWidth, window.innerHeight] as const,
+  )
+  const inside =
+    Number.isInteger(x) && Number.isInteger(y) && x >= 0 && y >= 0 && x < width && y < height
+  if (!inside) {
+    throw new Error(
+      `(${x}, ${y}) is not a point of the page, which is ${width} by ${height} pixels.`,
+    )
+  }
+  // One pixel of the picture for one pixel of the page, whatever the screen.
+  const png = await page.screenshot({ clip: { x, y, width: 1, height: 1 }, scale: 'css' })
+  return colourOfOnePixel(png)
+}
