# FND-051 – A licence file beneath the top folder of a package goes with the site

**Phase:** 1 – Foundation
**Track:** B (see `TASKS.md`, "Two tracks")
**Depends on:** FND-047 (merged), FND-050 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3 and §12, `docs/WORKFLOW.md`, `TASKS.md`
("Two tracks" and the entry of this task), `PROGRESS.md` (PLAN-039),
`ARCHITECTURE.md` §3, `TESTING.md` ("The licences that go with the
site"), `frontend/sitebuild/licences.ts`,
`frontend/sitebuild/licences.test.ts`, `frontend/e2e/licences.spec.ts`

## Objective

The site's file of licences holds every licence file a shipped package
brings, at any depth of its folder.

## Why

Since FND-047 the build writes one file, `licences.txt`, with the
licence of every package the site is built with. The step reads the
licence files in the top folder of an installed package. A package may
bring code of others in a folder of its own, with their licence beside
it. One shipped package does so today: `protobufjs` brings
`google/LICENSE`, Google's licence for the descriptions in its folder
`google`, and its own licence says that a folder with a licence file of
its own stands under that one. That text is not in the file. Nothing of
`protobufjs` is in the built site yet, so what is published is not
wrong today; it would be from the first task that builds the engine in
(GLB-022). A known defect does not wait for that (CLAUDE.md §3).

The trial also found a weak test of FND-047. Node.js gives the entries
of a folder by name on Linux already, so the test that the texts of a
package come in the order of the names passes there for a step that
does not sort at all. This task closes that too.

## What this task is, and what it is not

- **It is** one private function in `frontend/sitebuild/licences.ts`
  that lists the licence files of a package at any depth, and
  `textsOf` reading what it lists.
- **It is** 11 new unit tests, and a stand-in in the unit tests that
  makes every folder give its entries out of order.
- **It is not** a change to which names count as a licence file, to
  what is written for a package, to the lock file or to any package.
- **It is not** a change to the browser tests. They pass as they are:
  the built file grows by one text and nothing else.

## Design in short

- **Every folder of a package is looked into**, but not a folder named
  `node_modules`, at any depth: what is put there is another package,
  which the lock file names by itself and whose licence is written
  with that one.
- **A link to a folder is not followed.** The step asks the entry
  itself whether it is a folder (`Dirent.isDirectory()`), and a link
  is not one. So a folder that leads back to itself ends, and nothing
  outside the package is read through a link.
- **A text is given by the path of its file from the package's
  folder**, with `/` between the parts on every computer: `LICENSE`,
  `google/LICENSE`.
- **The order**: the files of a folder, by name, before those of the
  folders in it, each folder by name. So the licence of the package
  itself stays first, and the file is the same on every computer.
- **A file that is refused** (not text, or empty) is named by its
  whole path, as before.
- **In the unit tests** the one call of Node.js that lists a folder,
  `readdirSync`, is given a stand-in (`vi.mock('node:fs', …)`) that
  calls the real one and gives its entries with the first one last.
  Nothing but the order is changed. With it, a step that leaves the
  entries as the computer gives them fails on Linux too.

## What the task left open, and what the trial settled

- **How deep?** To any depth. A scan of all 32 shipped packages as
  installed finds one licence file beneath a top folder,
  `protobufjs/google/LICENSE`; a rule for "one folder deep" would hold
  today and be wrong for the next package.
- **Why not `readdirSync(…, { recursive: true })`?** It goes into
  `node_modules` and its order is the computer's. A test uses it, as
  the other way of finding the files, to hold the step against.
- **Is a folder left out whose name is only like `node_modules`?** No.
  `node_modules_of_old` and `my_node_modules` are read. A test holds
  it.
- **What of a file that is a link?** As before: a file by a licence
  name is read when what it leads to is a file.
- **Does the built file change?** Yes, by one text: `protobufjs` now
  has `google/LICENSE` after `LICENSE`. In the planner's trial the
  file grows from 170982 to 172646 bytes; no other package gains a
  text.
- **Do the unit tests of FND-047 still hold with the stand-in?** Yes.
  Of that task's 81 planted defects in the step, 78 still apply (three
  are in lines this task rewrites); they were run again and all are
  detected (see below).
