# FND-001 – Repository hygiene baseline

**Phase:** 1 – Foundation
**Depends on:** nothing (first task)
**Base branch:** `main`
**Read first:** `CLAUDE.md`, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §2, §9, §11

## Objective

Keep the repository clean and consistent on Windows 11 and Linux before any
application code lands, and give the 100%-pass rule its first automated suite:
a dependency-free set of repository checks that every later task must keep
green.

## Scope

In scope – create exactly these files:

| File | Purpose |
|---|---|
| `.gitignore` | Keep generated files, environments, caches and secrets out of Git |
| `.gitattributes` | Line-ending normalisation and binary markers |
| `.editorconfig` | Editor defaults matching the above |
| `README.md` | Project front page and document index |
| `DATA_SOURCES.md` | Required document, honest stub |
| `DATABASE.md` | Required document, honest stub |
| `TESTING.md` | Required document; documents the repository checks |
| `CHANGELOG.md` | Required document, Keep a Changelog format |
| `tests/repo/test_repo_hygiene.py` | The repository check suite |

Out of scope – do not do any of this here:

- No `backend/`, `frontend/` or `scripts/` directories, no `pyproject.toml`,
  no `package.json`, no CI workflow, no `.env.example`. Later tasks own them.
- No licence file. The owner has not chosen a licence.
- No edits to `CLAUDE.md`, `DESIGN.md`, `TASKS.md`, `PROGRESS.md`,
  `ARCHITECTURE.md`, `docs/WORKFLOW.md` or `docs/plans/*`.

## Implementation detail

### 1. `.gitignore`

Root-level file covering, at minimum:

- **Secrets and local config:** `.env`, `.env.*`, with `!.env.example`
  re-included; `*.pem`, `*.key`.
- **Python:** `__pycache__/`, `*.py[cod]`, `.venv/`, `venv/`, `*.egg-info/`,
  `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `.coverage`, `htmlcov/`,
  `build/`, `dist/`.
- **Node / frontend:** `node_modules/`, `*.tsbuildinfo`, `playwright-report/`,
  `test-results/`, `.vite/`.
- **Logs and local data:** `*.log`, `logs/`, `.cache/`.
- **Editors and OS:** `.idea/`, `.vscode/`, `*.swp`, `.DS_Store`, `Thumbs.db`,
  `Desktop.ini`.

Patterns must be written so they match at any depth (for example
`node_modules/`, not `/node_modules/`). Lock files (`uv.lock`,
`package-lock.json`) must **not** be ignored. Group the patterns under short
comment headings.

### 2. `.gitattributes`

- Default: `* text=auto eol=lf`.
- Windows scripts check out with CRLF: `*.ps1`, `*.bat`, `*.cmd` →
  `text eol=crlf`.
- Explicit binary for: `*.png *.jpg *.jpeg *.gif *.webp *.ico *.pdf *.woff
  *.woff2 *.ttf *.zip *.gz *.glb *.ktx2`.

### 3. `.editorconfig`

- `root = true`.
- `[*]`: `charset = utf-8`, `end_of_line = lf`, `insert_final_newline = true`,
  `trim_trailing_whitespace = true`, `indent_style = space`, `indent_size = 2`.
- `[*.py]`: `indent_size = 4`.
- `[*.md]`: `trim_trailing_whitespace = false`.
- `[*.{ps1,bat,cmd}]`: `end_of_line = crlf`.

### 4. `README.md`

Plain, short and honest. Sections:

1. `# MotoSphere` and the tagline "The World of Motocross, Connected."
2. One paragraph on what it is (from DESIGN.md §1: a global motocross
   information platform centred on an interactive 3D Earth).
3. **Status** – early development; nothing to run yet. Point to `TASKS.md` for
   the task list and `PROGRESS.md` for test reports.
4. **Documentation** – a list with a relative Markdown link and one-line
   description for each of: `DESIGN.md`, `CLAUDE.md`, `TASKS.md`,
   `PROGRESS.md`, `ARCHITECTURE.md`, `DATA_SOURCES.md`, `DATABASE.md`,
   `TESTING.md`, `CHANGELOG.md`, `docs/WORKFLOW.md`.
5. **Running the checks** – the exact command from "Verification" below and
   its only prerequisites (Python 3.12 or newer, Git).

Do not describe features as existing. Do not add badges, licence text or
installation steps for things that do not exist yet.

### 5. Document stubs

Each has a title, one or two sentences stating its purpose (take the wording
from CLAUDE.md §16), and an honest current state. No invented content.

- `DATA_SOURCES.md` – purpose; "No sources have been registered yet."; the
  column headings the registry will use (name, website, country, category,
  information types, collection method, licence/terms, restrictions, status)
  as an empty table.
- `DATABASE.md` – purpose; "No schema exists yet. Planned engine: PostgreSQL 16
  with PostGIS 3 (see ARCHITECTURE.md §5)."
- `TESTING.md` – purpose; the rule (100% of applicable tests must pass before a
  task is accepted); a "Gates" table currently holding one row, the repository
  checks, with its command; a "Latest results" section saying results are
  recorded per task in `PROGRESS.md`.
- `CHANGELOG.md` – Keep a Changelog layout: intro line, `## [Unreleased]`,
  `### Added` with one bullet for this task's repository baseline.

### 6. `tests/repo/test_repo_hygiene.py`

Python standard library only (`unittest`, `subprocess`, `pathlib`, `re`). It
must run with the system Python on Windows and Linux with nothing installed.
No `__init__.py` files are needed.

- Find the repository root from the test file's own location
  (`Path(__file__).resolve().parents[2]`), never from the current directory.
- Call Git with `subprocess.run([...], cwd=ROOT, capture_output=True,
  text=True)` and an argument list, never `shell=True`.
- `git check-ignore` and `git check-attr` work on paths that do not exist, so
  the tests use representative sample paths.

One `unittest.TestCase` class with exactly these nine tests:

1. `test_required_documents_exist` – each of `README.md`, `CLAUDE.md`,
   `DESIGN.md`, `TASKS.md`, `PROGRESS.md`, `ARCHITECTURE.md`,
   `DATA_SOURCES.md`, `DATABASE.md`, `TESTING.md`, `CHANGELOG.md` exists, is a
   file, and has non-whitespace content. Use `subTest` per document.
2. `test_generated_and_secret_paths_are_ignored` – `git check-ignore -q`
   returns 0 for each of: `.env`, `.env.local`, `backend/.env`,
   `backend/.venv/pyvenv.cfg`, `backend/src/motosphere/__pycache__/x.pyc`,
   `backend/.pytest_cache/README.md`, `backend/.mypy_cache/x.json`,
   `backend/.ruff_cache/x`, `backend/motosphere.egg-info/PKG-INFO`,
   `frontend/node_modules/react/index.js`, `frontend/dist/index.html`,
   `frontend/playwright-report/index.html`, `frontend/test-results/x.txt`,
   `frontend/tsconfig.tsbuildinfo`, `logs/app.log`, `server.pem`,
   `Thumbs.db`, `.DS_Store`, `.idea/workspace.xml`.
3. `test_source_paths_are_not_ignored` – `git check-ignore -q` returns 1 for
   each of: `.env.example`, `backend/.env.example`, `backend/pyproject.toml`,
   `backend/uv.lock`, `backend/src/motosphere/__init__.py`,
   `backend/tests/test_smoke.py`, `frontend/package.json`,
   `frontend/package-lock.json`, `frontend/src/main.tsx`,
   `frontend/e2e/smoke.spec.ts`, `scripts/start.ps1`, `docs/plans/FND-001.md`,
   `tests/repo/test_repo_hygiene.py`. Treat any exit code other than 0 or 1 as
   a test error, not a pass.
4. `test_no_secret_or_environment_files_tracked` – from `git ls-files`, no
   tracked path has a basename of `.env` or starting `.env.` (except
   `.env.example`), ends in `.pem` or `.key`, or is named `id_rsa` /
   `id_ed25519`.
5. `test_line_ending_attributes` – via `git check-attr text eol -- <path>`:
   `backend/src/app.py`, `frontend/src/main.tsx` and `README.md` resolve to
   `eol: lf`; `scripts/start.ps1`, `scripts/run.bat` and `scripts/run.cmd`
   resolve to `eol: crlf`; `frontend/public/logo.png` and
   `frontend/public/font.woff2` resolve to `text: unset`.
6. `test_tracked_text_files_are_lf_in_repository` – from `git ls-files --eol`,
   no tracked file has `i/crlf` or `i/mixed` in its index column. Report the
   offending paths in the failure message.
7. `test_editorconfig_baseline` – `.editorconfig` contains `root = true`,
   `charset = utf-8`, `end_of_line = lf` and `insert_final_newline = true`
   (tolerate spacing around `=`).
8. `test_readme_links_resolve` – every relative Markdown link target in
   `README.md` (ignore `http(s)://`, `mailto:` and `#anchor` links; strip any
   `#fragment`) points to an existing path, and the ten documents listed in
   README section 4 above are all linked.
9. `test_changelog_has_unreleased_section` – `CHANGELOG.md` contains a
   `## [Unreleased]` heading.

Tests that read tracked files (4 and 6) see only what is in the index, so
stage your files before running the suite.

## Acceptance criteria

1. Generated files, virtual environments, caches, build output and `.env`
   files are ignored; source files, lock files and `.env.example` are not.
2. Text files are normalised to LF in the repository; `.ps1`, `.bat` and
   `.cmd` check out as CRLF; common binary types are marked binary.
3. All nine documents required by CLAUDE.md §16, plus `README.md`, exist and
   are non-empty.
4. README links to every project document and every relative link resolves.
5. No secret or environment file is tracked.
6. The suite contains exactly the nine tests above and all nine pass.
7. Only the nine files listed under "Scope" are added; no existing file is
   modified.

## Verification

Run from the repository root, with your changes staged or committed:

```
python -m unittest discover -s tests/repo -v
```

Expected: `Ran 9 tests` and `OK`.

Then prove the suite can fail (do not commit these changes):

1. Temporarily remove the `node_modules/` line from `.gitignore` → test 2 must
   fail. Restore it.
2. Temporarily create and `git add` an empty file named `.env.production` →
   test 4 must fail (use `git add -f`). Unstage and delete it.

Finish with `git status` clean and the suite at 9/9 again.
