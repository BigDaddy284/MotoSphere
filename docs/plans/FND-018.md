# FND-018 – Continuous integration

**Phase:** 1 – Foundation
**Depends on:** FND-031 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §6, §14, `docs/WORKFLOW.md`, `TESTING.md`

## Objective

GitHub runs every gate for each pull request and each change to `main`, on a
Linux machine, with the same command a developer uses:
`python scripts/check.py`. From this task on, a pull request shows its own
result.

Windows is not part of this task. The first run on Windows is its own task
(FND-032), because it is expected to find things to fix and those fixes
should not be mixed with setting the workflow up.

## Design in short

- One workflow, `.github/workflows/checks.yml`, with one job. It installs
  Python, uv, Node.js and the browser for the browser tests, then runs
  `python scripts/check.py`. It has no logic of its own: what is checked
  stays in the check runner, so GitHub and a developer's machine cannot
  drift apart.
- Python 3.12, the oldest version the pipeline supports, so that nothing
  newer slips into the code unnoticed. Node.js 22 and uv 0.11.32, the
  versions every task so far was verified with.
- The browser is installed with the locked Playwright, so the frontend's
  dependencies are installed first (`npm ci`, then
  `npx playwright install --with-deps chromium`). The check runner installs
  them again in its own gate; that costs a few seconds and keeps the runner
  unchanged.
- The workflow is given as little as possible (`CLAUDE.md` §14): a token
  that can only read, no secret, no credentials left behind by the
  checkout, every action pinned to a full commit, and only four actions
  allowed. New repository checks hold it to this, and they apply to every
  workflow added later.
- The repository checks read the workflow as text, because they use the
  standard library only and it has no YAML reader. The file is kept plain
  for that reason: keep its layout exactly as given.
- While trying this out, the planner found that the existing check "source
  paths are not ignored" could not fail for a file Git already tracks. One
  option (`--no-index`) fixes it, and it is part of this task.

## What the planner could and could not try

Tried on Linux with Python 3.13.18 and 3.12.3, Node 22.23.4 and uv 0.11.32:

- The workflow file is valid YAML and has the structure intended.
- The 22 repository checks pass, and 32 planted defects in the workflow
  were all detected (listed under "Verification").
- The full run passes with the variables GitHub sets (`CI=true`,
  `GITHUB_ACTIONS=true`) and Python 3.12 throughout: 19 of 19 gates, 489
  tests.
- The four commits the actions are pinned to are the commits of the release
  tags named beside them, read from the actions' own repositories on
  2026-11-17, and every input the workflow sets exists in that release.

Not tried, because it can only happen on GitHub: the workflow itself. **The
first real run is yours, on your own pull request.** See "On GitHub" below
for what to do when it does not pass first time.

## Implementation detail

### 1. `.github/workflows/checks.yml` – new

```yaml
# Runs every gate of the project for each pull request and each change to
# `main`. The gates themselves are in `scripts/check.py`; this file only
# prepares a machine and starts them (TESTING.md, "Continuous integration").
name: Checks

on:
  pull_request:
  push:
    branches: [main]

# The job only reads the repository. It is given no secret and cannot write.
permissions:
  contents: read

# A newer commit on a pull request replaces a run that is still going. Runs
# for `main` are never cut short, so every commit there gets its result.
concurrency:
  group: checks-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  linux:
    name: All gates (Linux)
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    steps:
      # Every action is pinned to a commit, with its release beside it.
      - name: Check out the repository
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Install Python
        uses: actions/setup-python@6d4fd22b20465ccc0f7354476588e8df7c9ca0e0 # v7.1.0
        with:
          python-version: "3.12"

      - name: Install uv
        uses: astral-sh/setup-uv@68559e99cc807c1eb7e9238fd43a15bba460eec2 # v10.3.3
        with:
          version: "0.11.32"

      - name: Install Node.js
        uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: "22"

      # The browser tests need a browser, and the locked Playwright decides
      # which one, so the frontend's dependencies are installed first.
      - name: Install the browser for the browser tests
        working-directory: frontend
        run: |
          npm ci
          npx playwright install --with-deps chromium

      - name: Run every gate
        run: python scripts/check.py
```

### 2. `tests/repo/test_ci_workflow.py` – new, 13 tests

```python
"""Checks on the continuous integration workflows (task FND-018).

The workflows are read as text: the repository checks use the standard
library only, and it has no YAML reader. The files are kept plain enough for
that, and the checks are strict about their layout for the same reason.

Run from the repository root:

    python -m unittest discover -s tests/repo -v
"""

import json
import re
import tomllib
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
WORKFLOWS = ROOT / ".github" / "workflows"
CHECKS = WORKFLOWS / "checks.yml"

# The actions a workflow may use. Adding one is a decision about whose code
# runs with access to the repository, so it is made here and not in passing.
KNOWN_ACTIONS = (
    "actions/checkout",
    "actions/setup-node",
    "actions/setup-python",
    "astral-sh/setup-uv",
)

# The only expressions a workflow may contain. Text that comes from outside,
# such as the title of a pull request, must never reach a command.
KNOWN_EXPRESSIONS = (
    "github.event_name == 'pull_request'",
    "github.ref",
)

# An action pinned to a full commit, with the release it belongs to beside it.
PINNED = re.compile(r"^ +uses: ([\w.-]+/[\w.-]+)@[0-9a-f]{40} # v\d+\.\d+\.\d+$")


def workflows() -> dict[str, str]:
    """Return the text of every workflow, by file name."""
    files = sorted(WORKFLOWS.glob("*.y*ml")) if WORKFLOWS.is_dir() else []
    return {file.name: file.read_text(encoding="utf-8") for file in files}


def commands(text: str) -> list[str]:
    """Return every command the steps of a workflow run, in order."""
    found: list[str] = []
    lines = text.splitlines()
    for number, line in enumerate(lines):
        step = re.match(r"^( +)run: (.+)$", line)
        if step is None:
            continue
        if step.group(2) != "|":
            found.append(step.group(2))
            continue
        inside = step.group(1) + "  "
        for following in lines[number + 1 :]:
            if not following.startswith(inside):
                break
            found.append(following.strip())
    return found


class WorkflowSafetyTest(unittest.TestCase):
    """Rules that hold for every workflow in the repository."""

    def test_there_is_a_workflow_to_check(self) -> None:
        self.assertIn("checks.yml", workflows())

    def test_every_action_is_pinned_to_a_commit_with_its_release(self) -> None:
        for name, text in workflows().items():
            used = [line for line in text.splitlines() if re.search(r"\buses:", line)]
            self.assertTrue(used, f"{name} uses no action")
            for line in used:
                with self.subTest(workflow=name, line=line.strip()):
                    self.assertRegex(line, PINNED)

    def test_only_known_actions_are_used(self) -> None:
        for name, text in workflows().items():
            for action in re.findall(r"\buses: *([^@\s]+)", text):
                with self.subTest(workflow=name, action=action):
                    self.assertIn(action, KNOWN_ACTIONS)

    def test_no_workflow_runs_code_from_outside_with_the_rights_of_the_repository(self) -> None:
        for name, text in workflows().items():
            with self.subTest(workflow=name):
                self.assertNotIn("pull_request_target", text)
                self.assertNotIn("workflow_run", text)
                self.assertNotIn("secrets.", text)

    def test_every_workflow_limits_what_its_token_may_do(self) -> None:
        for name, text in workflows().items():
            with self.subTest(workflow=name):
                self.assertRegex(text, re.compile(r"^permissions:$", re.MULTILINE))
                self.assertNotIn("write-all", text)

    def test_no_text_from_outside_reaches_a_command(self) -> None:
        for name, text in workflows().items():
            for expression in re.findall(r"\$\{\{(.*?)\}\}", text):
                with self.subTest(workflow=name, expression=expression.strip()):
                    self.assertIn(expression.strip(), KNOWN_EXPRESSIONS)


class ChecksWorkflowTest(unittest.TestCase):
    """The workflow that runs every gate."""

    text: str

    @classmethod
    def setUpClass(cls) -> None:
        cls.text = CHECKS.read_text(encoding="utf-8")

    def test_runs_for_pull_requests_and_for_changes_to_main(self) -> None:
        self.assertIn("\non:\n  pull_request:\n  push:\n    branches: [main]\n\n", self.text)

    def test_its_token_can_only_read(self) -> None:
        self.assertEqual(self.text.count("permissions:"), 1)
        self.assertIn("\npermissions:\n  contents: read\n\n", self.text)

    def test_checkout_keeps_no_credentials(self) -> None:
        self.assertEqual(self.text.count("actions/checkout@"), 1)
        self.assertRegex(
            self.text,
            r"uses: actions/checkout@\S+ # \S+\n +with:\n +persist-credentials: false\n",
        )

    def test_runs_the_check_runner_and_nothing_in_its_place(self) -> None:
        self.assertEqual(
            commands(self.text),
            [
                "npm ci",
                "npx playwright install --with-deps chromium",
                "python scripts/check.py",
            ],
        )

    def test_nothing_lets_a_failing_step_pass(self) -> None:
        self.assertNotIn("continue-on-error", self.text)
        self.assertNotRegex(self.text, re.compile(r"^ +(- )?if:", re.MULTILINE))
        self.assertNotRegex(self.text, re.compile(r"^ +(- )?shell:", re.MULTILINE))

    def test_runs_on_a_named_linux_image_with_a_time_limit(self) -> None:
        self.assertEqual(
            re.findall(r"^ +runs-on: (.+)$", self.text, re.MULTILINE), ["ubuntu-24.04"]
        )
        self.assertRegex(self.text, re.compile(r"^ +timeout-minutes: \d+$", re.MULTILINE))

    def test_tools_are_the_versions_the_project_supports(self) -> None:
        with (ROOT / "backend" / "pyproject.toml").open("rb") as file:
            oldest_python = tomllib.load(file)["project"]["requires-python"]
        package = json.loads((ROOT / "frontend" / "package.json").read_text(encoding="utf-8"))
        oldest_node = package["engines"]["node"]

        python = re.findall(r'^ +python-version: "(.+)"$', self.text, re.MULTILINE)
        node = re.findall(r'^ +node-version: "(.+)"$', self.text, re.MULTILINE)
        uv = re.findall(r'^ +version: "(.+)"$', self.text, re.MULTILINE)

        # The oldest Python the pipeline supports, so that nothing newer
        # slips into the code unnoticed.
        self.assertEqual([f">={version}" for version in python], [oldest_python])
        self.assertEqual(len(node), 1)
        self.assertTrue(oldest_node.startswith(f">={node[0]}."), (node, oldest_node))
        self.assertEqual(len(uv), 1)
        self.assertRegex(uv[0], r"^\d+\.\d+\.\d+$")


if __name__ == "__main__":
    unittest.main()
```

## Continuous integration

GitHub runs every gate for each pull request and for each change to `main`.
The workflow is `.github/workflows/checks.yml`. It does nothing of its own: it

  only actions on a short list may be used. To update one, change the commit

## Verification

### Locally

From a clean state (delete `frontend/node_modules`, `frontend/dist`,
`frontend/test-results`, `frontend/public/data` and `backend/.venv` first if
they exist). Stage your changes first (`git add -A`).

```
python -m unittest discover -s tests/repo -v
python -m unittest discover -s tests/scripts -v
python scripts/check.py
git status --short
```

Expected: `Ran 22 tests` / `OK`; `Ran 73 tests` / `OK`; the full run ends
with `19 of 19 gates passed.` and `Tests: 489 passed, 0 failed, 0 skipped.`,
exit code 0. Paste the whole summary into the report. Port 4173 must be
free. In this development environment the browser is already installed: do
**not** run `npx playwright install` here. (The workflow runs it on GitHub's
machine, which starts without a browser.)

Then prove the tests can fail (do not commit these changes; restore each one
before the next). After each of steps 1 to 11 run
`python -m unittest discover -s tests/repo` and report which tests fail.

1. **An action named by a tag that can be moved.**
   `uses: actions/checkout@v7` in place of the pinned line → 2 tests fail.
2. **An action nobody decided on.** Add a step
   `- uses: someone/other-action@` followed by forty `a` characters and
   ` # v1.0.0` → 2 tests fail.
3. **Runs outside code with the repository's rights.**
   `pull_request_target:` in place of `pull_request:` → 2 tests fail.
4. **The token may write.** `contents: write` → "its token can only read"
   fails.
5. **The title of a pull request reaches a command.** Add a step
   `- run: echo "${{ github.event.pull_request.title }}"` → "no text from
   outside reaches a command" fails.
6. **Checkout leaves credentials behind.** Remove the two lines `with:` /
   `persist-credentials: false` → "checkout keeps no credentials" fails.
7. **A failing run is forgiven.** `run: python scripts/check.py || true` →
   "runs the check runner and nothing in its place" fails.
8. **A failing step may pass.** Add `continue-on-error: true` to the last
   step → "nothing lets a failing step pass" fails.
9. **A newer Python than the oldest supported.** `python-version: "3.13"` →
   "tools are the versions the project supports" fails.
10. **A second workflow that breaks the rules.** Create
    `.github/workflows/other.yml` with a job that has the one step
    `- uses: actions/checkout@v7` and no `permissions:` → 2 tests fail.
    Delete the file afterwards.
11. **The workflows folder is ignored by Git.** Add the line `.github/` at
    the end of `.gitignore` → "source paths are not ignored" fails. (Before
    this task's change to `check_ignore` it passed, because the file is
    tracked.)

### On GitHub

Commit, push your branch and open the pull request. The workflow starts by
itself. Read its result with the GitHub tools you have (the pull request's
check runs and the job's log); do not poll in a tight loop.

- **If the push is refused because of the workflow file**, or **no run
  starts at all** (GitHub Actions switched off for the repository): stop.
  That is a setting only the owner can change. Report exactly what GitHub
  answered.
- **If the run fails in a preparation step** (an action, the browser
  install): make the smallest change to the workflow that fixes it, keep
  every rule the repository checks pin, and report what you changed and
  why. If a check has to change with it, change it without making it
  weaker, and say so.
- **If a gate fails on GitHub that passes locally**: that is a real
  difference between the two machines. Find the cause and fix the cause.
  Never skip a test, loosen an assertion or mark a step as allowed to fail.
  A fix outside the files under "Scope" is a deviation to report, with the
  reason.

When the run is green, paste the end of the job's log (the summary and the
two closing lines) into the report.

Then prove that the job can fail:

12. **A failing test on GitHub.** Push one extra commit, titled
    `TEMPORARY: a failing test, to prove the job fails`, that changes one
    expected value in one frontend unit test so that it fails. Expected: the
    job fails, and its log shows `FAILED  Frontend unit tests` with
    `198 passed, 1 failed` and `18 of 19 gates passed.` Paste those lines
    into the report. Then push a commit that undoes it (`git revert`), and
    wait for the green run on the final commit. Do not force-push; the
    pull request is merged as one commit, so neither commit reaches `main`.

## Deliver

- The commit `FND-018: Continuous integration` on your task branch (plus the
  two commits of step 12, which cancel each other out).
- A pull request to `main` with the same title and a **Test report** in the

  summary of the full local run, the prove-it results, links to the green
  run on the final commit and to the red run of step 12 with the lines

- The pull request's final diff must hold only the files under "Scope".
- Do not merge it. Reply in your thread with the pull request link, the

GitHub, merges, checks the run for `main`, and records the result in
