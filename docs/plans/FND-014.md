# FND-014 – Application shell layout

**Phase:** 1 – Foundation
**Depends on:** FND-023 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §8, `DESIGN.md` §12.1, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §3

## Objective

The final screen regions, with the globe area dominant: a top bar, the
sections panel on the left, the globe stage in the centre and the details
panel on the right, as accessible landmarks, in the owner's Graphite
surfaces, filling the screen without page scrollbars.

This task builds the regions only. What goes inside them comes later: the
section list (FND-025), collapsing (FND-015), the data status (FND-016) and
the globe (Phase 3). The sections panel and the stage are therefore empty for
now, on purpose. No placeholder controls and no "coming soon" text.

### 1. Layout tokens

In `frontend/src/styles/tokens.css`, add this block directly before the
`/* Shape */` block:

```css
  /* Layout */
  --size-top-bar: 3rem;
  --size-sections-panel: 13.75rem;
  --size-details-panel: 22.5rem;
```

In `frontend/src/styles/tokens.test.ts`, add the three names to the expected
token list. Nothing else in that file changes; the suite then expects 49
tokens.

At 1366 pixels wide this gives the panels 220 and 360 pixels and the stage
786 (58% of the width); at 1920 the stage gets 1340 (70%).

### 2. `frontend/src/layout/AppShell.tsx`

Exactly this content:

```tsx
import styles from './AppShell.module.css'

interface AppShellProps {
  /** The application name, shown as the page's main heading. */
  name: string
  /** One line under the name. */
  tagline: string
}

/**
 * The fixed regions of the screen: a top bar, the sections panel on the left,
 * the globe stage in the centre and the details panel on the right. The stage
 * always gets the largest share of the screen.
 */
export function AppShell({ name, tagline }: AppShellProps) {
  return (
    <div className={styles.shell}>
      <header className={styles.topBar}>
        <h1 className={styles.name}>{name}</h1>
        <p className={styles.tagline}>{tagline}</p>
      </header>
      <nav className={styles.sections} aria-label="Sections" />
      <main className={styles.stage} aria-label="Globe" />
      <aside className={styles.details} aria-label="Details">
        <p className={styles.hint}>Select something on the globe to see its details here.</p>
      </aside>
    </div>
  )
}
```

Landmarks, for reference: `header` is the banner, `nav` is the navigation
landmark named "Sections", `main` is named "Globe", `aside` is the
complementary landmark named "Details". They appear in the document in the
order a reader meets them.

### 3. `frontend/src/layout/AppShell.module.css`

Exactly this content:

```css
.shell {
  display: grid;
  grid-template-areas:
    'top top top'
    'sections stage details';
  grid-template-columns: var(--size-sections-panel) minmax(0, 1fr) var(--size-details-panel);
  grid-template-rows: var(--size-top-bar) minmax(0, 1fr);
  height: 100vh;
  overflow: hidden;
}

.topBar {
  grid-area: top;
  display: flex;
  align-items: baseline;
  gap: var(--space-4);
  padding: 0 var(--space-4);
  background-color: var(--color-bar);
  border-bottom: 1px solid var(--color-border);
  line-height: var(--size-top-bar);
  white-space: nowrap;
  overflow: hidden;
}

.name {
  font-size: var(--font-size-lg);
  line-height: inherit;
}

.tagline {
  color: var(--color-subtext);
  font-size: var(--font-size-sm);
  overflow: hidden;
  text-overflow: ellipsis;
}

.sections {
  grid-area: sections;
  background-color: var(--color-panel);
  border-right: 1px solid var(--color-border);
  overflow-y: auto;
}

.stage {
  grid-area: stage;
  position: relative;
  background-color: var(--color-canvas);
  overflow: hidden;
}

.details {
  grid-area: details;
  padding: var(--space-4);
  background-color: var(--color-panel);
  border-left: 1px solid var(--color-border);
  overflow-y: auto;
}

.hint {
  color: var(--color-subtext);
  font-size: var(--font-size-sm);
}
```

`minmax(0, 1fr)` matters: it lets the stage shrink instead of pushing the
page wider than the screen. The shell is exactly one screen high and hides
its own overflow, so the page never scrolls; the two panels scroll inside
themselves when their content grows.

### 5. `frontend/src/layout/AppShell.test.tsx` – 6 tests

Render `<AppShell name="Test name" tagline="Test tagline" />` and query by
role, using `within` for content inside a region.

1. `shows the name as the main heading, with the tagline, in the top bar` –
   inside the banner: a level-1 heading named `Test name` and the text
   `Test tagline`, both visible.
2. `has a sections panel` – a navigation landmark named `Sections`.
3. `has the globe stage as the main region` – a main landmark named `Globe`.
4. `has a details panel that says how to fill it` – inside the complementary
   landmark named `Details`: the text
   `Select something on the globe to see its details here.`, visible.
5. `has exactly one of each region` – one banner, one navigation, one main,
   one complementary.
6. `puts the regions in reading order: top bar, sections, globe, details` –
   the `header`, `nav`, `main` and `aside` elements appear in the document in
   that order.

### 6. `frontend/e2e/layout.spec.ts` – 7 browser tests

Import `test` and `expect` from `./fixtures`. Measure regions with
`locator.boundingBox()` (fail clearly if it returns `null`).

For each of the two viewports 1366×768 and 1920×1080 (use
`test.use({ viewport })` inside a `test.describe` per viewport, named
`layout at 1366×768` and `layout at 1920×1080`):

1. `the four regions fill the screen without overlapping` –
   - the banner starts at x 0, y 0 and is as wide as the viewport;
   - sections, stage and details each start at the banner's bottom edge and
     end at the bottom of the viewport;
   - sections starts at x 0; the stage starts where sections ends; details
     starts where the stage ends; details ends at the viewport's right edge.
2. `the globe stage is the largest region` – the stage is wider than half
   the viewport and wider than the two panels together.
3. `the page itself does not scroll` – for `document.documentElement`,
   `scrollWidth - clientWidth` and `scrollHeight - clientHeight` are both 0.

And once, at the default viewport:

4. `the regions use the Graphite surfaces` – background colours: banner
   `rgb(27, 28, 31)`, sections `rgb(34, 35, 39)`, stage `rgb(29, 30, 33)`,
   details `rgb(34, 35, 39)`.

### 7. `frontend/e2e/theme.spec.ts`
