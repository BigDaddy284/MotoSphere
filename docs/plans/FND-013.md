# FND-013 – Dark theme design tokens

**Phase:** 1 – Foundation
**Depends on:** FND-012 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §8, `DESIGN.md` §12.2, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §3, §9

## Objective

One source of truth for colour, type, spacing, shape and motion (design
tokens as CSS custom properties), base styles that apply the dark theme to
the whole page, and tests that prove the theme is readable: every text colour
is checked against every surface for WCAG contrast, and the real page is
checked in the browser.

### 5. `frontend/src/test/contrast.ts`

A small, dependency-free helper implementing the WCAG 2 definitions
(<https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio>):

- `relativeLuminance(colour: string): number` accepts a six-digit hex colour
  (`#rrggbb`, either case) and throws
  `Error('Not a six-digit hex colour: "<input>"')` for anything else. Each
  channel `c = value / 255` becomes `c / 12.92` when `c <= 0.04045`,
  otherwise `((c + 0.055) / 1.055) ** 2.4`; luminance is
  `0.2126 R + 0.7152 G + 0.0722 B`.
- `contrastRatio(first: string, second: string): number` returns
  `(lighter + 0.05) / (darker + 0.05)`.

It lives under `src/test/` because only tests use it; it must not be imported
by application code.

### 6. `frontend/src/test/contrast.test.ts` – 6 tests, 10 cases

1. `gives black on white the maximum ratio of 21` (`toBeCloseTo(21, 5)`).
2. `gives identical colours the minimum ratio of 1`.
3. `does not depend on the order of the colours`.
4. `matches the published ratio for grey #767676 on white`: 4.54 to two
   decimal places.
5. `accepts upper-case hex digits`.
6. `rejects %j`: `it.each` over `'red'`, `'#fff'`, `'#12345g'`,
   `'rgb(0, 0, 0)'` and `''`; each throws the error above.

### 7. `frontend/src/styles/tokens.test.ts` – 7 tests, 31 cases

Read the style sheets as text: `import tokensCss from './tokens.css?raw'` for
the tokens, and
`import.meta.glob('../**/*.css', { query: '?raw', import: 'default', eager: true })`
for every style sheet under `src/`, so style sheets added by later tasks are
checked automatically. Strip CSS comments before matching. Parse
declarations with a pattern equivalent to `(--[a-z0-9-]+)\s*:\s*([^;]+);`.

`describe('design tokens')`:

1. `defines exactly the agreed set of tokens`: the sorted token names equal
   the 38 names in the file above, written out in the test.
2. `defines each token only once`: the number of declarations equals the
   number of distinct names.
3. `writes every colour as a six-digit hex value`: there are exactly 13
   `--color-*` tokens and each matches `^#[0-9a-f]{6}$`.
4. `%s on %s has a contrast of at least %d`: `it.each` over 25 cases:
   - on each of the three surfaces (`--color-bg`, `--color-surface`,
     `--color-surface-raised`): `--color-text` ≥ 7; `--color-text-muted`,
     `--color-accent`, `--color-success`, `--color-warning`,
     `--color-danger`, `--color-info` ≥ 4.5; `--color-focus` ≥ 3
     (8 × 3 = 24 cases);
   - `--color-on-accent` on `--color-accent` ≥ 4.5.

   7 is WCAG AAA for text ("high-contrast information" in `DESIGN.md`), 4.5
   is AA for text, 3 is AA for non-text parts such as the focus ring.

`describe('style sheets')`:

5. `finds the style sheets to check`: the glob result contains
   `./tokens.css` and `./base.css` (guards against the glob silently matching
   nothing).
6. `keep raw colours in the token file only`: no style sheet other than
   `tokens.css` contains a hex colour or a colour function (`rgb`, `rgba`,
   `hsl`, `hsla`, `hwb`, `lab`, `lch`, `oklab`, `oklch`, `color`,
   `color-mix`).
7. `only use tokens that exist`: every `var(--name` in every style sheet
   names a token defined in `tokens.css`. (CSS ignores a misspelt variable
   silently; this test does not.)

Lint note: `expect(value, 'message')` with two arguments is rejected by the
linter. For tests 6 and 7 collect the offenders into an array and assert
`expect(offenders).toEqual([])`, so a failure names the file and token.

### 8. `frontend/e2e/theme.spec.ts` – 5 browser tests

Import `test` and `expect` from `./fixtures`. Use `toHaveCSS`, which reads
the computed style in the real browser. Expected values are written out.

1. `uses the dark background and light text`: `body` has `background-color`
   `rgb(11, 13, 16)` and `color` `rgb(242, 244, 247)`; `html` has
   `color-scheme` `dark`.
2. `uses the system font at a readable size, with no page margin`: `body` has
   `font-family` matching `/^system-ui/`, `font-size` `16px`, `line-height`
   `24px`, `margin` `0px`; the level-1 heading has `font-size` `32px` and
   `font-weight` `700`.
3. `shows a focus ring when an element is reached by keyboard`: the page has
   nothing focusable yet, so the test adds a `<button>` to `document.body`
   with `page.evaluate`, checks its `outline-style` is `none`, presses `Tab`,
   then expects the button to be focused with `outline-style` `solid`,
   `outline-width` `2px`, `outline-color` `rgb(138, 180, 255)` and
   `outline-offset` `2px`.
4. `removes motion for people who ask for reduced motion`:
   `page.emulateMedia({ reducedMotion: 'reduce' })` before `goto`; add a
   `<div>` with inline `transition: opacity 2s` and `animation: none 2s`; its
   computed `transitionDuration` and `animationDuration` both parse
   (`Number.parseFloat`) to `0.00001` seconds.
5. `keeps motion for everyone else`: with `reducedMotion: 'no-preference'`,
   the same kind of `<div>` has a computed `transitionDuration` of `2s`.

## Acceptance criteria

1. Tokens are defined once, in `tokens.css`; base styles and all future style
   sheets take every colour from them, enforced by tests.
2. Contrast: main text ≥ 7:1, all other text and status colours ≥ 4.5:1, and
   the focus ring ≥ 3:1, on all three surfaces.
3. In the browser the page has the dark background, light text, system font,
   no page margin, a visible keyboard focus ring, and no motion when reduced
   motion is requested.
4. `npm test` reports 46 passed; `npm run e2e` reports 9 passed.
5. Only the files under "Scope" changed; all earlier gates pass.
