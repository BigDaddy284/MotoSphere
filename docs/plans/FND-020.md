# FND-020 – Replace the API server with the pipeline command line

**Phase:** 1 – Foundation
**Depends on:** FND-008 (merged); the hosting decision of 2026-11-17
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §12, §14, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §1, §2, §4

## Objective

MotoSphere is hosted on GitHub Pages with no server. This task removes the
API server that earlier tasks built, with its settings and dependencies, and
turns `python -m motosphere` into the command line of the data pipeline. The
first command is `version`. The settings and logging modules stay and are
used by the command line.

## Design in short

- `motosphere.cli` is a package. `cli/app.py` builds the argument parser,
  loads the settings, sets up logging and runs the chosen command. Each
  command is its own module with an `add_parser` function; `cli/version.py`
  is the first.
- The parser comes from the standard library (`argparse`): no new
  dependency.
- Arguments are parsed **before** the settings are loaded, so `--help` works
  even when a setting is wrong.
- Results go to standard output. Log lines and error messages go to standard
  error.
- Exit codes: 0 success; 2 for wrong arguments (argparse's own behaviour)
  and for invalid settings (unchanged from FND-008).

### 2. `backend/src/motosphere/cli/app.py`

Exactly this content:

```python
"""Argument parsing and start-up shared by every MotoSphere command.

A command is a module with an ``add_parser`` function that registers its
sub-command and names the function that runs it. :func:`main` parses the
arguments, loads the settings, sets up logging and then runs the command.

Results are written to standard output. Log lines and error messages go to
standard error, so output can be piped or saved without them.
"""

import argparse
import sys
from collections.abc import Callable, Sequence

from pydantic import ValidationError

from motosphere.cli import version
from motosphere.core.logging_config import configure_logging
from motosphere.core.settings import Settings, get_settings

__all__ = ["EXIT_CONFIGURATION_ERROR", "EXIT_OK", "PROGRAM", "build_parser", "main"]

PROGRAM = "python -m motosphere"
EXIT_OK = 0
# argparse also exits with 2 when the arguments are wrong.
EXIT_CONFIGURATION_ERROR = 2

type CommandHandler = Callable[[argparse.Namespace, Settings], int]


def build_parser() -> argparse.ArgumentParser:
    """Return the parser for ``python -m motosphere`` with every command registered."""
    parser = argparse.ArgumentParser(
        prog=PROGRAM,
        description="MotoSphere data pipeline.",
        allow_abbrev=False,
    )
    commands = parser.add_subparsers(
        title="commands",
        dest="command",
        metavar="<command>",
        required=True,
    )
    version.add_parser(commands)
    return parser


def _describe_configuration_error(error: ValidationError) -> str:
    """Return one line naming every invalid setting and what is wrong with it."""
    problems = "; ".join(
        f"{'.'.join(str(part) for part in problem['loc'])}: {problem['msg']}"
        for problem in error.errors()
    )
    return f"Configuration error: {problems}"


def main(argv: Sequence[str] | None = None) -> int:
    """Run one MotoSphere command and return the process exit code.

    ``argv`` is the argument list without the program name; ``None`` means the
    arguments of the running process. Wrong arguments, and ``--help``, end the
    process through :class:`SystemExit`, as is usual for argparse. Invalid
    settings give a one-line message on standard error and exit code 2.
    """
    arguments = build_parser().parse_args(argv)

    try:
        settings = get_settings()
    except ValidationError as error:
        sys.stderr.write(_describe_configuration_error(error) + "\n")
        return EXIT_CONFIGURATION_ERROR

    configure_logging(settings)
    handler: CommandHandler = arguments.handler
    return handler(arguments, settings)
```

### 3. `backend/src/motosphere/cli/version.py`

Exactly this content:

```python
"""The ``version`` command: print the installed MotoSphere version."""

import argparse
import sys

import motosphere
from motosphere.core.settings import Settings

__all__ = ["add_parser", "run"]


def add_parser(commands: "argparse._SubParsersAction[argparse.ArgumentParser]") -> None:
    """Register the ``version`` command."""
    parser = commands.add_parser(
        "version",
        help="print the MotoSphere version",
        description="Print the installed MotoSphere version.",
        allow_abbrev=False,
    )
    parser.set_defaults(handler=run)


def run(_arguments: argparse.Namespace, _settings: Settings) -> int:
    """Write ``motosphere <version>`` to standard output."""
    sys.stdout.write(f"motosphere {motosphere.__version__}\n")
    return 0
```

`sys.stdout.write` is used because the linter forbids `print` (rule T20).

## Acceptance criteria

1. `python -m motosphere version` prints `motosphere 0.1.0` on standard
   output and exits 0.
2. With no command, an unknown command or an unexpected argument it prints
   the usage and an error on standard error and exits 2. `--help` exits 0,
   even when a setting is invalid.
3. An invalid setting gives exactly one line on standard error starting
   `Configuration error: ` and exit code 2, however many settings are wrong.
4. No server code, server setting or server dependency remains: the `api`
   package is gone, `uv.lock` no longer contains `fastapi`, `uvicorn`,
   `starlette` or `httpx2`, and the old settings are rejected as unknown.
5. README, TESTING.md, `.env.example` and the changelog no longer describe a
   server.
6. `uv run pytest` reports 61 passed; the lock check, mypy, ruff check and
   ruff format check pass; repository checks pass (9); the frontend is
   untouched.
7. Only the files under "Scope" changed.
