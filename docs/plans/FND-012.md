# FND-012 – Browser test infrastructure

**Phase:** 1 – Foundation
**Depends on:** FND-011 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §18, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §3, §9

## Objective

Verify the real, built application in a real browser with one command,
`npm run e2e`: Playwright builds the frontend, serves the build, opens it in
headless Chromium and checks what a user would see. Every browser test, now
and in future, also fails automatically if the page logs an error or warning,
throws, or has a failed request.

## Implementation detail

The planner trial-ran this exact set-up on the merged frontend: 4 browser
tests passed in about 3 seconds, and lint, format check, type check, the
5 unit tests and `npm audit` all still passed.

### 1. Dependency and script

From `frontend/`:

```
npm install -D --save-exact @playwright/test@1.63.0
```

The version is pinned exactly, on purpose. Each Playwright release works with
one specific browser build, so an exact pin means every machine tests with
the same Chromium. 1.63.0 is the release whose Chromium is installed in the
build environment. Upgrading later is a deliberate change: new version, then
`npx playwright install chromium`.

Add to `scripts` in `frontend/package.json`, after `format:check`:

```json
"e2e": "playwright test"
```

### 2. `frontend/playwright.config.ts`

Exactly this content:

```ts
import { defineConfig, devices } from '@playwright/test'

const HOST = '127.0.0.1'
const PORT = 4173
const BASE_URL = `http://${HOST}:${PORT}`

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  forbidOnly: true,
  retries: 0,
  reporter: 'list',
  use: {
    baseURL: BASE_URL,
    trace: 'off',
  },
  projects: [{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }],
  webServer: {
    command: `npm run build && npm run preview -- --host ${HOST} --port ${PORT} --strictPort`,
    url: BASE_URL,
    reuseExistingServer: false,
    timeout: 120_000,
  },
})
```

Why:

- `webServer` builds first and serves the fresh build, so the tests always
  exercise the production bundle, never a stale one and never the development
  server. `reuseExistingServer: false` and `--strictPort` make the run fail
  with a clear message if port 4173 is already in use, instead of silently
  testing something else.
- `retries: 0`: a test that only passes sometimes is a failing test.
- `forbidOnly: true`: a forgotten `test.only` fails the run.
- The server listens on the loopback address only.

type-checked as strictly as everything else and may use DOM types inside

{
  "compilerOptions": {

    "target": "es2023",
    "lib": ["ES2023", "DOM"],
    "types": ["node"],

### 4. `frontend/e2e/fixtures.ts`

Exactly this content. Every browser test in the project imports `test` and
`expect` from this file, never directly from `@playwright/test`.

```ts
import { expect, test as base } from '@playwright/test'

/**
 * Every browser test uses this `test`. It records anything that shows the page
 * is unhealthy and fails the test if there was any, even when the test's own
 * assertions passed.
 */
export const test = base.extend<{ pageProblems: string[] }>({
  pageProblems: [
    async ({ page }, use) => {
      const problems: string[] = []
      page.on('console', (message) => {
        const type = message.type()
        if (type === 'error' || type === 'warning') {
          problems.push(`console ${type}: ${message.text()}`)
        }
      })
      page.on('pageerror', (error) => {
        problems.push(`uncaught error: ${error.message}`)
      })
      page.on('requestfailed', (request) => {
        problems.push(`request failed: ${request.method()} ${request.url()}`)
      })
      page.on('response', (response) => {
        if (response.status() >= 400) {
          problems.push(`HTTP ${response.status()}: ${response.url()}`)
        }
      })
      await use(problems)
      expect(problems, 'the page reported problems').toEqual([])
    },
    { auto: true },
  ],
})

export { expect }
```

### 5. `frontend/e2e/smoke.spec.ts`

Exactly these four tests, inside `test.describe('built application', ...)`,
importing from `./fixtures`. Each starts with `await page.goto('/')`.

1. `has the application title and language` – the page title is `MotoSphere`
   and `<html>` has `lang="en"`.
2. `shows the application name and tagline` – a level-1 heading named
   `MotoSphere` is visible, and the text
   `The World of Motocross, Connected.` is visible.
3. `has exactly one main landmark` – `page.getByRole('main')` has count 1.
4. `serves the icon the page links to` – `link[rel="icon"]` has
   `href="/favicon.svg"`; a request for `/favicon.svg` (the `request`
   fixture) returns status 200 with a content type containing
   `image/svg+xml`. The content-type check matters: the preview server
   answers unknown paths with the page itself and status 200, so a status
   check alone would not notice a missing file.

Use role and text locators, as the unit tests do. The expected strings are
written out in the test on purpose (not imported from `src/`): the browser
tests describe the product from the outside.

## Acceptance criteria

1. `npm run e2e` builds, serves and tests the application headlessly and
   reports `4 passed`; it exits non-zero when a browser test fails.
2. A console error, console warning, uncaught error, failed request or HTTP
   error status fails the test it happens in.
3. Browser test files pass lint, format check and the type check; the unit
   test run still collects exactly 5 tests.
4. Nothing under `frontend/src/` changed; `git status` is clean after a run
   (no report or result files visible).
5. README, TESTING.md and CHANGELOG.md describe the new gate; all earlier
   gates still pass.

## Verification

From a clean state (delete `frontend/node_modules`, `frontend/dist` and
`frontend/test-results` first if they exist):

```
cd frontend
npm ci
npm run lint
npm run format:check
npm test
npm run typecheck
npm run build
npm run e2e
npm audit
npx oxlint --debug=files
cd ..
python -m unittest discover -s tests/repo -v
git status --short
```

Expected: lint exits 0; `All matched files use Prettier code style!`;
`Tests  5 passed (5)`; type check and build exit 0; `4 passed`;
`found 0 vulnerabilities`; the lint file list is the 7 earlier files plus
`e2e/fixtures.ts`, `e2e/smoke.spec.ts` and `playwright.config.ts`;
`Ran 9 tests` / `OK`; clean status once committed.

Then prove the browser tests can fail (do not commit these changes; restore
each one before the next):

1. **Console error.** Append `console.error('boom')` to `src/main.tsx` →
   `npm run e2e` exits non-zero and every test reports
   `the page reported problems` with `console error: boom`.
2. **Uncaught error.** Append
   `setTimeout(() => { throw new Error('late') }, 0)` to `src/main.tsx` →
   fails with `uncaught error: late`.
3. **Wrong title.** Change the `<title>` in `index.html` → exactly one test
   fails.
4. **Missing icon.** Temporarily move `public/favicon.svg` away → exactly one
   test fails.
5. **Type error.** Append `const n: number = 'x'; void n` to
   `e2e/smoke.spec.ts` → `npm run typecheck` exits non-zero and names the
   file.
6. **Focused test.** Change the first `test(` in `e2e/smoke.spec.ts` to
   `test.only(` → `npm run e2e` exits non-zero and mentions `forbidOnly`.

Finish with every gate passing again and `git status` clean.
