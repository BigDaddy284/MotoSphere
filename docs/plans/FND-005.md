## Objective

One typed, validated, immutable settings object for the backend, loaded from
environment variables and an optional `.env` file, with safe defaults and no
secrets in source control. This is the first application code in the project.

## Implementation detail

### 1. Dependencies

In `backend/pyproject.toml`:

```toml
dependencies = [
    "pydantic>=2.9",
    "pydantic-settings>=2.6",
]
```

Both are listed because both are imported directly. Run `uv lock`.

### 2. `motosphere/core/settings.py`

Public names (set `__all__`): `ENV_PREFIX`, `Environment`, `LogLevel`,
`Settings`, `get_settings`.

- `ENV_PREFIX = "MOTOSPHERE_"`.
- `Environment(StrEnum)`: `DEVELOPMENT = "development"`, `TEST = "test"`,
  `PRODUCTION = "production"`.
- `LogLevel(StrEnum)`: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`, each
  with its own upper-case name as value.
- `Settings(BaseSettings)` with
  `SettingsConfigDict(env_prefix=ENV_PREFIX, env_file=".env",
  env_file_encoding="utf-8", extra="forbid", frozen=True)` and these fields:

  | Field | Type | Default | Constraint | Environment variable |
  |---|---|---|---|---|
  | `environment` | `Environment` | `development` | one of the enum values | `MOTOSPHERE_ENVIRONMENT` |
  | `api_host` | `str` | `127.0.0.1` | not empty | `MOTOSPHERE_API_HOST` |
  | `api_port` | `int` | `8000` | 1 to 65535 | `MOTOSPHERE_API_PORT` |
  | `log_level` | `LogLevel` | `INFO` | one of the enum values | `MOTOSPHERE_LOG_LEVEL` |

  Give every field a `description` (via `Field`) written in plain language;
  the README table reuses that wording.
- Friendly input: before validation, strip surrounding whitespace from
  `environment` and `log_level` string values and normalise case
  (`environment` to lower case, `log_level` to upper case), so `debug` and
  ` Production ` are accepted. Do this with `field_validator(..., mode="before")`.
- `get_settings() -> Settings`: returns `Settings()`, cached with
  `functools.lru_cache(maxsize=1)`. Application code will obtain settings
  through this function; tests clear it with `get_settings.cache_clear()`.

Behaviour to understand and preserve (the planner trial-ran this design with
pydantic 2.14 and pydantic-settings 2.16):

- The default host is the loopback address on purpose: nothing listens on the
  network unless the user asks for it.
- `.env` is looked up in the current working directory. All backend commands
  run from `backend/`, so the file is `backend/.env`. It is already ignored by
  Git.
- Real environment variables take precedence over `.env`.
- With `extra="forbid"`, **any** key in `.env` that is not a known setting is
  rejected at load time, including a misspelt `MOTOSPHERE_` name. That is
  intended: `backend/.env` holds MotoSphere settings only, and a typo must
  fail loudly instead of being silently ignored. Unknown variables in the real
  environment are simply not read.
- mypy strict passes on this design without the pydantic mypy plugin. Do not
  add the plugin.

### 3. `backend/.env.example`

A short header comment (copy this file to `.env` in the same folder to change
a setting; never commit `.env`), then one line per setting, each preceded by a
one-line comment, with the default value:

```
MOTOSPHERE_ENVIRONMENT=development
MOTOSPHERE_API_HOST=127.0.0.1
MOTOSPHERE_API_PORT=8000
MOTOSPHERE_LOG_LEVEL=INFO
```

The settings lines are active (not commented out), so a test can load the
file and prove it is valid.

### 4. `backend/tests/conftest.py`

One autouse, function-scoped fixture that makes every backend test independent
of the machine it runs on:

1. Remove every environment variable whose upper-cased name starts with
   `MOTOSPHERE_` (use `monkeypatch.delenv`; upper-casing matters on Windows).
2. `monkeypatch.chdir(tmp_path)` so no real `.env` is ever picked up.
3. Clear the `get_settings` cache before the test and again after it.

Without this, a developer's own `backend/.env` would change test results,
because tests run with `backend/` as the working directory.

### 5. `backend/tests/unit/test_settings.py`

Exactly these 14 test functions (18 test cases, because one is parametrised
with 5 values). Fully type-annotated. Each test that expects a failure asserts
on `pydantic.ValidationError` **and** that the error text names the setting.
Write `.env` files into `tmp_path` (the working directory, thanks to the
fixture) with `encoding="utf-8"`.

1. `test_defaults_without_environment` – all four fields equal the defaults in
   the table.
2. `test_environment_variables_override_defaults` – set all four variables;
   all four fields reflect them, with the right types (`api_port` is `int`,
   enums are enum members).
3. `test_dotenv_file_overrides_defaults` – values from `.env` are used.
4. `test_environment_variable_beats_dotenv_file` – same setting in both; the
   environment variable wins.
5. `test_values_are_normalised` – `MOTOSPHERE_LOG_LEVEL=debug` and
   `MOTOSPHERE_ENVIRONMENT=" Production "` load as `LogLevel.DEBUG` and
   `Environment.PRODUCTION`.
6. `test_invalid_port_is_rejected` – parametrised over
   `"0"`, `"65536"`, `"-1"`, `"abc"`, `""`; error names `api_port`.
7. `test_invalid_log_level_is_rejected` – `LOUD`; error names `log_level`.
8. `test_invalid_environment_is_rejected` – `staging`; error names
   `environment`.
9. `test_empty_host_is_rejected` – empty string; error names `api_host`.
10. `test_unknown_key_in_dotenv_file_is_rejected` – `.env` containing
    `MOTOSPHERE_API_PROT=9000`; error names `api_prot`.
11. `test_settings_are_immutable` – assigning to a field after creation
    raises `ValidationError` and the value is unchanged. Write it so that ruff
    and mypy pass without suppressions (for example, assign through `setattr`
    with the field name held in a variable).
12. `test_get_settings_is_cached_and_clearable` – two calls return the same
    object; after changing an environment variable the cached value is still
    returned; after `get_settings.cache_clear()` the new value is returned.
13. `test_env_example_lists_every_setting` – the set of variable names on the
    active (non-comment, non-blank) lines of `backend/.env.example` equals
    `{ENV_PREFIX + name.upper() for name in Settings.model_fields}`. Locate the
    file from the test file's path, not the working directory.
14. `test_env_example_values_equal_defaults` – copy `backend/.env.example` to
    `tmp_path / ".env"`; `Settings()` loaded from it equals a `Settings()`
    loaded with no file (compare `model_dump()`).

## Acceptance criteria

1. Defaults load with no environment and no `.env` file.
2. Environment variables override defaults; `.env` overrides defaults; real
   environment overrides `.env`.
3. Invalid values and unknown keys in `.env` fail at load with an error naming
   the setting.
4. Settings are immutable; `get_settings()` is cached and clearable.
5. `backend/.env.example` lists every setting with its default and no secret,
   and is proven valid by a test.
6. Tests are isolated from the developer's real environment and `.env`.
7. README documents configuration.
8. All gates pass with no suppressions, and no file outside "Scope" is
   touched.

## Verification

From a clean state (delete `backend/.venv` first if it exists):

```
cd backend
uv lock --check
uv sync --locked
uv run mypy
uv run ruff check .
uv run ruff format --check .
uv run pytest -v
cd ..
python -m unittest discover -s tests/repo -v
git status --short
```

Expected: lock check passes; mypy `Success: no issues found in 6 source
files`; ruff clean; `22 passed` (18 new + 4 existing) with no warnings;
`Ran 9 tests` / `OK`; clean status once committed.

Then prove the isolation and the tests are real (do not commit these changes):

1. **Isolation.** Create `backend/.env` containing `MOTOSPHERE_API_PORT=9999`
   and also run with the variable `MOTOSPHERE_LOG_LEVEL=LOUD` set in your
   shell: `uv run pytest` must still show `22 passed`. Delete the file.
2. **Real behaviour.** With `backend/.env` containing
   `MOTOSPHERE_API_PORT=9999`, run from `backend/`:
   `uv run python -c "from motosphere.core.settings import get_settings; print(get_settings().api_port)"`
   → prints `9999`. Change the file to `MOTOSPHERE_API_PROT=9999` and run the
   same command → it must fail with a validation error naming `api_prot`.
   Delete the file.
3. **Tests can fail.** Temporarily change the `api_port` default to `8001` →
   `test_defaults_without_environment` and
   `test_env_example_values_equal_defaults` must fail. Restore it.

Finish with `git status` clean and every gate green.
