## Objective

The list of the countries of ISO 3166-1 is in the repository, unchanged
from a source whose licence allows it, with that source and its licence
recorded, and a reader gives its countries or refuses the file whole.

## Why

Since DAT-011 the store has a table of the countries, and it is empty.
Everything that is somewhere in the world (a source, a track, an event,
a rider) will point to a row of it. The rows must be real: the project
never makes up a country, a code or a name (`CLAUDE.md` §11), and takes
nothing it may not pass on (§10). So the list comes from a named source
under a licence that was read, and it comes as a file of the project,
so that nothing has to be fetched when the pipeline runs and every
change to it is a change somebody made on purpose.

## What this task is, and what it is not

- **It is** three files in a new folder of the pipeline,
  `backend/src/motosphere/reference/iso-codes/`: the countries file of
  the project iso-codes, `iso_3166-1.json`, and the licence of that
  project, `LGPL-2.1-or-later.txt`, both unchanged from release 4.20.1,
  and a note, `README.md`, that says where they came from.
- **It is** a reader, `motosphere.reference.countries`: it gives the
  countries of such a file, each with its two codes and its name, or
  refuses the file whole with a sentence that says what is wrong.
- **It is** the record of the source and of its licence in
  `DATA_SOURCES.md`, with what was checked and what else was looked at.
- **It is** 143 unit tests in a new file,
  `backend/tests/unit/test_reference_countries.py`.
- **It is not** the countries in the store. No row is written, no source
  is registered, no command is added, and nothing under
  `backend/src/motosphere/db/` or `cli/` changes. Loading is DAT-059, and
  before it DAT-058 gives the list of the kinds of source a kind for a
  publisher of reference lists, which it lacks (`TASKS.md`, "The
  countries' list, in three steps").
- **It is not** published data. Nothing of the list reaches the site.

## The source, as the planner found and read it

All of this is in `DATA_SOURCES.md` after this task ("The countries:
iso-codes"); read it there in full. In short:

- **iso-codes** is a project of Debian that keeps the lists of several
  ISO standards (<https://salsa.debian.org/iso-codes-team/iso-codes>).
  Its file `data/iso_3166-1.json` is the list of ISO 3166-1: 249
  entries.
- **Its licence**, read in the release itself: the release's
  `REUSE.toml` says of `data/*json` "2016 Dr. Tobias Quathamer" and
  `LGPL-2.1-or-later`. The licence permits copying and passing on. It
  asks that every copy keeps the notice and comes with the licence, that
  a changed copy says so, and that a work which takes over part of the
  list is passed on under the same licence.
- **How it was fetched:** the release as its makers published it,
  `iso-codes_4.20.1.orig.tar.xz`, once, from the Ubuntu archive; its
  SHA-256 is the one the description of the source package there names.
  The two files were copied out of it unchanged.
- **What was checked:** 249 entries; no code, number or name twice;
  every code in capitals of the 26 letters; and every entry's code of
  three letters and number are those that Unicode's Common Locale Data
  Repository gives for its code of two letters. A second list, kept by
  other people, agrees with all of it.

**Do not fetch the files yourself and do not write them by hand.** They
are in the diff below, byte for byte, and two tests hold each to its
SHA-256.

## Design in short

- **The file is the source's, unchanged.** Nothing is taken out of it,
  reordered or reformatted, although MotoSphere reads three of the up to
  seven values of an entry. An unchanged copy with its notice and its
  licence beside it is what the licence asks, and a test can hold it to
  the release. A newer release is taken by a person: both files are
  replaced, and the note and the two values in the test are changed
  with them.
- **It is inside the package.** `motosphere.reference` is a package of
  the pipeline, and the folder `iso-codes` lies in it, so the reader
  finds the file wherever the pipeline is installed
  (`importlib.resources`), and no setting names a path.
- **The reader takes bytes and gives countries.**
  `read_countries(content)` takes the content of a file as it is on the
  disk and gives a tuple of `ReferenceCountry` (its code of two letters,
  its code of three, its name), in the order of the file.
  `countries_of_the_project()` reads the project's own file through it.
  A `ReferenceCountry` cannot be changed.
- **It reads what MotoSphere keeps and nothing else.** An entry's
  number, flag, official name and common name are left unread, whatever
  they hold, and so is anything a later release adds to an entry.
- **A damaged file is refused whole.** The reader gives every country of
  a file or none: one wrong entry anywhere refuses the file, with a
  sentence (`CountriesFileError`) that says what is wrong and in which
  entry, counted from 1. The acceptance criteria list what is refused.
- **The codes are held as the table holds them**: two, and three, of the
  26 capital letters, and nothing else (DAT-011). A code is not put into
  capitals and nothing is taken off it.
- **A name is given as it is written**, and held to what a name of a
  country can be: not empty by the rule of the store's own text
  (`motosphere.db.texts.WHITE_SPACE`, so that the reader and the table
  cannot disagree about what is empty), no white space around it, no
  white space inside other than a plain space, and no control character
  (Unicode's kind "Cc", which is the same 65 characters in every version
  of Python). Letters that are not of the 26, a comma, an apostrophe and
  a full stop are part of names the file has.
- **The file is data from outside.** It is parsed as JSON and nothing of
  it is run. What Python's parser takes and JSON does not have is
  refused: a name twice in one place (Python would keep the last and say
  nothing), and the words `NaN`, `Infinity` and `-Infinity`. Content
  nested so deeply that Python gives up, and a number too long for
  Python to read, are refused in the reader's own sentence and not with
  Python's error.

## What the task left open, and what the trial settled

- **One task or three?** The task was written as: find the source,
  bring the file, register the source, and a command that loads the
  file with history. Those are three objectives with three kinds of
  test, and the trial found a fourth thing in the way: none of the
  twelve kinds of source fits a project that keeps the lists of a
  standard (`PROGRESS.md` had left that to this trial). So this task is
  the file and its reader; DAT-058 is the kind of source; DAT-059 loads.
- **Which source?** iso-codes, because it is the list itself, under a
  licence that was read and allows passing it on. Unicode's list is
  under a freer licence but is not the list of the standard (eight
  regions more, and nothing that says which). `DATA_SOURCES.md` has
  what else was looked at, and says plainly what could not be read.
- **Which name?** The file's `name`, the short name of the standard as
  iso-codes writes it, which is what the column of DAT-011 is for.
  Fifteen names have a comma ("Korea, Republic of"), and iso-codes has a
  common name for eleven entries. The reader does not read it: the
  table has one name. Which name the site shows is decided where
  countries are first shown.
- **Strict or lenient about what an entry holds besides?** Lenient: it
  is left unread. The release's own schema allows seven values and no
  other; a reader that refused an eighth would refuse a newer release
  for something MotoSphere does not use.
- **Strict or lenient about the top of the file?** Strict: one list
  under the name `3166-1` and nothing else. That is what says the file
  is of the form the reader was written for.
- **Are two countries with one name refused?** No. The table of DAT-011
  allows it ("a name is not held to be anything but text"), and the
  reader does not hold more than the table. The file has none.
- **Does a checkout change the files?** No: `.gitattributes` keeps text
  files with the line endings of the repository on every machine, and
  neither file has another kind. A test holds that. The SHA-256 tests
  ran on GitHub's Windows machine in the planner's trial.

+"""The countries of ISO 3166-1, read from the reference file of the project.
+
+The file is ``iso_3166-1.json`` of the project iso-codes, unchanged, in
+the folder ``iso-codes`` beside this module. ``README.md`` in that folder
+says which release it is from and under which licence it is passed on.
+
+:func:`read_countries` reads the content of such a file and gives its
+countries, each with its two codes and its name. It reads what MotoSphere
+keeps of a country and nothing else: whatever more an entry holds is left
+unread. A file that is damaged is refused whole, with a sentence that
+says what is wrong: no country is given of a file that is not right
+throughout. The content is data from outside the project and is treated
+as such. Nothing of it is run.
+"""
+
+import json
+import re
+import unicodedata
+from dataclasses import dataclass
+from importlib import resources
+
+from motosphere.db.texts import WHITE_SPACE
+
+__all__ = [
+    "COUNTRIES_FILE",
+    "LIST_NAME",
+    "ORIGIN_FOLDER",
+    "CountriesFileError",
+    "ReferenceCountry",
+    "countries_of_the_project",
+    "read_countries",
+]
+
+# The folder beside this module that holds what was taken from iso-codes.
+ORIGIN_FOLDER = "iso-codes"
+# The file of the countries in it, under the name its source gives it.
+COUNTRIES_FILE = "iso_3166-1.json"
+# The name the file gives its one list.
+LIST_NAME = "3166-1"
+
+_TWO_CAPITALS = re.compile("[A-Z]{2}")
+_THREE_CAPITALS = re.compile("[A-Z]{3}")
+_WHITE_SPACE = "".join(chr(number) for number in WHITE_SPACE)
+
+
+class CountriesFileError(ValueError):
+    """The content is not a countries file the reader can go by."""
+
+
+@dataclass(frozen=True, slots=True)
+class ReferenceCountry:
+    """One country as the reference file has it."""
+
+    # Its code of two letters, as "NZ".
+    alpha_2: str
+    # Its code of three letters, as "NZL".
+    alpha_3: str
+    # What the file calls it in English, as the file writes it.
+    name: str
+
+
+def countries_of_the_project() -> tuple[ReferenceCountry, ...]:
+    """Give the countries of the reference file that comes with the project."""
+    file = resources.files(__package__).joinpath(ORIGIN_FOLDER, COUNTRIES_FILE)
+    return read_countries(file.read_bytes())
+
+
+def read_countries(content: bytes) -> tuple[ReferenceCountry, ...]:
+    """Give the countries of a countries file, in the order the file has them.
+
+    ``content`` is the file as it is on the disk. The file is JSON in
+    UTF-8: one list, under the name ``3166-1``, of entries that each have
+    text under ``alpha_2``, ``alpha_3`` and ``name``. A
+    :class:`CountriesFileError` says what is wrong when the content is
+    anything else, when a code is not in capitals of the right number,
+    when a name is empty or holds what no name holds, and when two
+    entries have one code.
+    """
+    entries = _entries(_parsed(content))
+    countries = tuple(_country(number, entry) for number, entry in enumerate(entries, start=1))
+    _refuse_a_code_twice(countries)
+    return countries
+
+
+def _parsed(content: bytes) -> object:
+    try:
+        text = content.decode("utf-8")
+    except UnicodeDecodeError:
+        raise CountriesFileError("The countries file is not text in UTF-8.") from None
+    try:
+        return json.loads(text, object_pairs_hook=_names_once, parse_constant=_no_such_value)
+    except CountriesFileError:
+        raise
+    except ValueError as error:
+        raise CountriesFileError(f"The countries file cannot be read as JSON: {error}.") from None
+    except RecursionError:
+        raise CountriesFileError("The countries file is nested too deeply to be read.") from None
+
+
+def _names_once(pairs: list[tuple[str, object]]) -> dict[str, object]:
+    """Give what JSON calls an object, and refuse one that has a name twice."""
+    found: dict[str, object] = {}
+    for name, value in pairs:
+        if name in found:
+            raise CountriesFileError(f'The countries file has "{name}" twice in one place.')
+        found[name] = value
+    return found
+
+
+def _no_such_value(word: str) -> object:
+    """Refuse the three words Python reads as numbers and JSON does not have."""
+    raise CountriesFileError(f"The countries file has {word}, which JSON does not have.")
+
+
+def _entries(parsed: object) -> list[object]:
+    if not isinstance(parsed, dict) or list(parsed) != [LIST_NAME]:
+        raise CountriesFileError(
+            f'The countries file is not one list under the name "{LIST_NAME}" and nothing else.'
+        )
+    entries = parsed[LIST_NAME]
+    if not isinstance(entries, list):
+        raise CountriesFileError(f'The countries file has no list under the name "{LIST_NAME}".')
+    if not entries:
+        raise CountriesFileError("The countries file has no countries.")
+    return entries
+
+
+def _country(number: int, entry: object) -> ReferenceCountry:
+    if not isinstance(entry, dict):
+        raise CountriesFileError(f"Entry {number} of the countries file is not a country.")
+    alpha_2 = _text(number, entry, "alpha_2")
+    alpha_3 = _text(number, entry, "alpha_3")
+    name = _text(number, entry, "name")
+    if _TWO_CAPITALS.fullmatch(alpha_2) is None:
+        raise CountriesFileError(
+            f"Entry {number} of the countries file has {alpha_2!r} "
+            "where a code of two capital letters belongs."
+        )
+    if _THREE_CAPITALS.fullmatch(alpha_3) is None:
+        raise CountriesFileError(
+            f"Entry {number} of the countries file ({alpha_2}) has {alpha_3!r} "
+            "where a code of three capital letters belongs."
+        )
+    wrong = _wrong_with(name)
+    if wrong is not None:
+        raise CountriesFileError(
+            f"Entry {number} of the countries file ({alpha_2}) has a name that {wrong}."
+        )
+    return ReferenceCountry(alpha_2=alpha_2, alpha_3=alpha_3, name=name)
+
+
+def _text(number: int, entry: dict[object, object], name: str) -> str:
+    value = entry.get(name)
+    if not isinstance(value, str):
+        raise CountriesFileError(
+            f'Entry {number} of the countries file has no text under "{name}".'
+        )
+    return value
+
+
+def _wrong_with(name: str) -> str | None:
+    """Say what a name has that no name of a country has, or give nothing."""
+    if name.strip(_WHITE_SPACE) == "":
+        return "is empty"
+    if name != name.strip(_WHITE_SPACE):
+        return "begins or ends with white space"
+    for character in name:
+        if character != " " and character in _WHITE_SPACE:
+            return "holds white space that is not a plain space"
+        if unicodedata.category(character) == "Cc":
+            return "holds a control character"
+    return None
+
+
+def _refuse_a_code_twice(countries: tuple[ReferenceCountry, ...]) -> None:
+    for what in ("alpha_2", "alpha_3"):
+        first: dict[str, int] = {}
+        for number, country in enumerate(countries, start=1):
+            code: str = getattr(country, what)
+            if code in first:
+                raise CountriesFileError(
+                    f"Entries {first[code]} and {number} of the countries file "
+                    f"have one code, {code}."
+                )
+            first[code] = number

+def _taken(file: str) -> bytes:
+    """Give a file of the folder that holds what was taken from iso-codes."""

+def _file(*entries: Any) -> bytes:
+    """Give a countries file with these entries, as it would be on the disk."""
+    return json.dumps({LIST_NAME: list(entries)}, ensure_ascii=False).encode("utf-8")

+
+def _with(**changes: Any) -> dict[str, Any]:
+    """Give the entry of New Zealand, with these values in place of its own."""
+    return {**NEW_ZEALAND, **changes}

+
+def _without(name: str) -> dict[str, Any]:
+    """Give the entry of New Zealand without one of its values."""
+    return {key: value for key, value in NEW_ZEALAND.items() if key != name}

+    """Give the sentence with which the reader refuses this content."""
