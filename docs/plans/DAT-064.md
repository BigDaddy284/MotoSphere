## Objective

A region can say the code the standard ISO 3166-2 gives it, such as
`NZ-CAN`, so that a region is known across sources that write its name
differently.

## Why

A name is what a source writes: "Bayern" in one, "Bavaria" in another.
The code is the same in both. A track that says "the region `DE-BY`"
is placed without anyone judging two spellings, and "Do not
automatically merge uncertain rider or track identities." (CLAUDE.md
§11) is kept without a person having to look at every pair. The code
is also what tells apart two regions of one country that share a name,
which the standard's own list has (see "What the trial measured").

## What this task is, and what it is not

- **It is** one column of `region`, `iso_3166_2`, the check of its
  form, the rule that no two regions have one code, the seventeenth
  migration, which builds the table anew with them, and their tests.
- **It is not** the codes themselves. No region and no code is loaded:
  which codes there are is what a source says. The tests use a handful
  of real codes as examples, each on the region it belongs to.
- **It is not** the rule that the code of a region begins with the
  code of its country. The country's code is a column of another
  table, and holding the two together is a task of its own, DAT-067
  (PLAN-056). Until then the table would take `AT-1` for a region of
  New Zealand; no test of this task stores such a row.
- **It is not** a change to the rule of the names. That two regions of
  a country can share a name when their codes tell them apart is
  DAT-066 (PLAN-056).
- **It is not** a region inside a region (DAT-065).
- **It is not** a change to a command or to the published data.

## Design in short

    __table_args__ = (
        UniqueConstraint("country_id", "name"),
        _code_of_the_standard("iso_3166_2"),
    )

    country_id: Mapped[int] = mapped_column(ForeignKey("country.id"))
    name: Mapped[NotEmpty]
    iso_3166_2: Mapped[str | None] = mapped_column(unique=True)

`_code_of_the_standard` gives the check `ck_region_iso_3166_2_form`:
the text is two capital letters, a hyphen and one, two or three
capital letters or digits, and holds no character with the number 0.
The table then has fourteen columns. The migration writes the whole
table out as plain SQL, as every migration does, and the test of the
models and the migrations holds the two together.

## What the trial measured

The planner read the list of ISO 3166-2 that comes with release 4.20.1
of iso-codes (the project the countries come from), as data and
nothing else, before the form was written:

- It has 5046 codes, of 200 countries. Every one is two capital
  letters, a hyphen, and one, two or three capital letters or digits:
  327 have one character after the hyphen, 3099 two and 1620 three.
  None has another form, and none is there twice.
- 36 pairs of its regions share a name within one country, and 13 of
  those pairs even under the same parent or both without one (Maputo,
  the city and the province of Mozambique, is one). So the rule of
  DAT-013, one name in a country, is stricter than the standard, and
  the code is what tells such a pair apart. That is DAT-066, and it
  needs this task first.

The list itself is not in the repository and no test reads it: the
table holds the form, not the list.

## What the task left open, and what the trial settled

- **The form is held by the table**, as the codes of a country are
  (DAT-011): `GLOB` with the 26 letters and the ten digits written
  out as ranges, which tells small letters from capitals on every
  machine and takes a letter with an accent, a letter of full width, a
  Greek capital or a digit of another script for none of them. The
  three lengths are three patterns joined by `OR`. `GLOB` reads text
  only up to a character with the number 0, so the check also says
  that there is none; four tests put one before, within and after a
  code.
- **Nothing is put right.** A code with a space after it or in small
  letters is refused, not trimmed or put in capitals: the model stores
  what it is given, and what reads a source is what must give it the
  standard's form.
- **A region may be without a code, and any number may be.** SQLite
  takes rows without a value for different under a rule that no two
  rows have one value, so the rule `uq_region_iso_3166_2` needs
  nothing more; a test stores four regions without a code.
- **One code, one region**, whatever the country. The rule holds when
  a region is stored and when it is given a code later, and a code is
  free again once the region that had it is deleted, has another or
  has none.
- **SQLite's own index finds the region of a code.** It keeps one for
  the rule (`sqlite_autoindex_region_2`); the trial asked SQLite which
  index it uses for `WHERE iso_3166_2 = ?`, and a test holds the
  answer. So the column has no index of its own; a planted defect that
  adds one is found.
- **The table is built anew.** SQLite can add a column in place, but
  it puts it after all the others, where the model does not have it,
  and it cannot give a column that is added in place the rule of one
  value. So the seventeenth migration does what the fourteenth did to
  the sources (DAT-057): it copies the rows aside, drops the table,
  makes it again with the column, the check and the rule, fills it
  from the copy with every row's key, puts the highest key the table
  gave back, drops the copies and makes the index over `source_id`
  again. Unlike the fourteenth it does not ask SQLite to wait with its
  check of what points where: no table of a store at version 16
  points to a region. The tables that will, come in later migrations.
- **What the migration keeps is tested on a store with a gap in its
  keys**: four regions, two of them deleted again, so that the highest
  key the table gave is above every key that is there, one region with
  only what it cannot be without and one with everything. After the
  migration every region has all it had, its key and no code; the key
  of a deleted region is still not given again, also in a table with
  no regions left and in one that never had one.
- **Where the migration fails, the store is as it was**: where a
  table of the name of either copy is there, and at its very last
  statement, where an index of its name over another table stands in
  the index's place. By then the table was dropped, made anew and
  filled. (The test of the fifteenth migration puts a table there.
  SQLite refuses that whether the migration passes over a name that
  is taken or not, so here it is an index.)
- **History.** `change` (DAT-047) gives a region a code, another and
  none, with one row of history each; a code that is said again is no
  change; a change the table refuses leaves no history.
- **The tests' fixture has four countries**, New Zealand, Australia,
  Austria and France, and every code of the tests is the code of the
  region it is given to (`NZ-CAN` Canterbury, `NZ-OTA` Otago, `AU-WA`
  Western Australia, `AT-1` Burgenland, `FR-01` Ain, `FR-2A`
  Corse-du-Sud, `FR-75C` Paris). So the tests stay true when DAT-067
  holds a code to its country.

### 1. `backend/tests/integration/test_region_code.py` – new, the whole file, 104 tests

```python
"""Tests of the code a region says, against a real SQLite file.

The store of every test is built the way a real store is built: by the
migrations. What is stored through the model is also read as SQLite holds
it, and what the table must refuse is also written past the model.

The code is the one ISO 3166-2 gives a region, as "NZ-CAN" for
Canterbury. The tests hold its form, that a region may be without one,
and that no two regions have one code. Every code of the tests is a code
of the standard, and the code of the region it is given to.
"""

from collections.abc import Iterator
from contextlib import contextmanager
from datetime import UTC, datetime
from typing import Any

import pytest
from sqlalchemy import Engine, delete, select
from sqlalchemy.exc import IntegrityError

from motosphere.db.changes import change
from motosphere.db.models import Country, Region, Source
from motosphere.db.models.provenance import Confidence, VerificationStatus
from motosphere.db.models.source import CollectionMethod, SourceCategory
from motosphere.db.work import unit_of_work

COLLECTED = datetime(2026, 11, 27, 9, 0, tzinfo=UTC)
ADDRESS = "https://standards.example/regions.csv"
# The four countries of the tests, by their keys.
NEW_ZEALAND = 1
AUSTRALIA = 2
AUSTRIA = 3
FRANCE = 4
NO_FORM = "CHECK constraint failed: ck_region_iso_3166_2_form"
ONE_CODE_TWICE = "UNIQUE constraint failed: region.iso_3166_2"


@contextmanager
def refused(why: str) -> Iterator[None]:
    """SQLite refuses what the block writes, and says exactly this."""
    with pytest.raises(IntegrityError) as refusal:
        yield
    assert str(refusal.value.orig) == why


@pytest.fixture
def mapped(newest: Engine) -> Engine:
    """The test's own store with the newest schema, one source and four countries in it.

    The key of the source is 1. The keys of the countries are 1 to 4: New
    Zealand, Australia, Austria and France.
    """
    with unit_of_work(newest) as work:
        work.add(
            Source(
                name="Example Standards Body",
                website="https://standards.example",
                category=SourceCategory.GOVERNING_BODY,
                collection_method=CollectionMethod.DATASET,
            )
        )
    for two, three, name in [
        ("NZ", "NZL", "New Zealand"),
        ("AU", "AUS", "Australia"),
        ("AT", "AUT", "Austria"),
        ("FR", "FRA", "France"),
    ]:
        with unit_of_work(newest) as work:
            work.add(
                Country(
                    alpha_2=two,
                    alpha_3=three,
                    name=name,
                    source_id=1,
                    source_address="https://standards.example/countries.csv",
                    collected_at=COLLECTED,
                    last_verified_at=COLLECTED,
                    extraction_method=CollectionMethod.DATASET,
                    confidence=Confidence.HIGH,
                    verification_status=VerificationStatus.OFFICIAL,
                )
            )
    return newest


def a_region(**said: Any) -> Region:
    """Canterbury in New Zealand as the one source of the tests says it, and what the test says."""
    described: dict[str, Any] = {
        "country_id": NEW_ZEALAND,
        "name": "Canterbury",
        "source_id": 1,
        "source_address": ADDRESS,
        "collected_at": COLLECTED,
        "last_verified_at": COLLECTED,
        "extraction_method": CollectionMethod.DATASET,
        "confidence": Confidence.HIGH,
        "verification_status": VerificationStatus.OFFICIAL,
    }
    return Region(**(described | said))


def keep(store: Engine, region: Region) -> int:
    """Store a region in a unit of work of its own, and give its key."""
    with unit_of_work(store) as work:
        work.add(region)
    return region.id


def the_region(store: Engine, key: int) -> Region:
    """Read a region anew from the store."""
    with unit_of_work(store) as work:
        return work.execute(select(Region).where(Region.id == key)).scalar_one()


def write(
    store: Engine, code: object, name: str = "Canterbury", country: int = NEW_ZEALAND
) -> None:
    """Write a region past the model, as plain SQL, with this in the column of its code."""
    with store.begin() as connection:
        connection.exec_driver_sql(
            "INSERT INTO region (country_id, name, iso_3166_2, source_id, source_address, "
            "collected_at, last_verified_at, extraction_method, confidence, "
            "verification_status, created_at, updated_at) VALUES (?, ?, ?, 1, "
            "'https://standards.example/regions.csv', '2026-11-27T09:00:00.000000+00:00', "
            "'2026-11-27T09:00:00.000000+00:00', 'public dataset', 'high', 'official', "
            "'2026-11-27T09:00:05.000000+00:00', '2026-11-27T09:00:05.000000+00:00')",
            (country, name, code),
        )


def codes(store: Engine) -> list[tuple[str, object]]:
    """The name of every region and the code SQLite holds for it, by the region's key."""
    with store.connect() as connection:
        found = connection.exec_driver_sql("SELECT name, iso_3166_2 FROM region ORDER BY id")
        return [(str(name), code) for name, code in found]


def history(store: Engine) -> list[tuple[object, ...]]:
    """What the history holds of the regions: the record, the field, and what it held and holds."""
    with store.connect() as connection:
        found = connection.exec_driver_sql(
            "SELECT record_table, record_id, field, old_value, new_value FROM record_change "
            "ORDER BY id"
        )
        return [tuple(row) for row in found]


def test_a_region_says_its_code_and_is_read_back_with_it(mapped: Engine) -> None:
    key = keep(mapped, a_region(iso_3166_2="NZ-CAN"))

    found = the_region(mapped, key)

    assert found.iso_3166_2 == "NZ-CAN"
    assert (found.country_id, found.name) == (NEW_ZEALAND, "Canterbury")
    assert codes(mapped) == [("Canterbury", "NZ-CAN")]


def test_a_region_of_which_no_code_is_said_has_none(mapped: Engine) -> None:
    key = keep(mapped, a_region())

    assert the_region(mapped, key).iso_3166_2 is None
    assert codes(mapped) == [("Canterbury", None)]


def test_a_row_written_past_the_model_is_read_with_its_code(mapped: Engine) -> None:
    write(mapped, "NZ-CAN")
    write(mapped, None, name="Otago")

    assert the_region(mapped, 1).iso_3166_2 == "NZ-CAN"
    assert the_region(mapped, 2).iso_3166_2 is None
```
