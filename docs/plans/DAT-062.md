## Objective

Where the store and the reference file say different things of a
country, the loading puts what the file says to the review queue, one
item for each field the two differ in, and still changes no country.

## Why

"Use review queues when information conflicts." (CLAUDE.md §11). The
loading of the countries (DAT-059) finds such conflicts: the store has a
country with another name or another code than the file. Until now it
only named the country to whoever called it, and the conflict was kept
nowhere. The review queue is the place the store has for exactly this:
"Where the collecting cannot tell by itself what is right, it does not
guess: it puts the doubt down as an item of the review queue, and a
person decides." (`motosphere.db.review`). Its function
`open_field_doubt` takes what a source says of a field of a stored
record, and gives back the item that is there when the queue holds the
same doubt already.

PLAN-050 left this out, with the reason that a person is at hand
whenever the store and the file come to differ. That a person is at
hand does not keep the conflict: the command's sentence scrolls away,
and the administration that will list what waits for a decision (Phase
10) reads the queue. PLAN-051 in `PROGRESS.md` corrects it, before the
command of DAT-061 is written, so that the command's sentences are
settled once.

## Design in short

`load_countries` gathers the countries of the file that the store says
otherwise of, as before, but as the countries themselves and not only
their codes. After the new rows are written, and only when there is
such a country, it hands them to `_put_to_the_review_queue(work,
source, countries)`.

That helper reads the stored countries that have one of the codes of
two or one of the codes of three of those countries, and goes through
the countries in the order of the file:

| What the store has | The item is about | Field | What the source says |
|---|---|---|---|
| The code of two letters with another code of three | That country | `alpha_3` | The file's code of three |
| The code of two letters with another name | That country | `name` | The file's name |
| The file's code of three letters under another code of two | The country that has the code of three | `alpha_2` | The file's code of two |

For one country the items are opened in this order. Each is opened with
`open_field_doubt`: kind `sources disagree`, the key of the source of
the countries, `ADDRESS` (the file of the release), what the file says
as the text it is, and a reason in one sentence:

- `Release 4.20.1 of iso-codes has another code of three letters for the country TR.`
- `Release 4.20.1 of iso-codes has another name for the country TR.`
- `Release 4.20.1 of iso-codes has the code of three letters TUR for the country TR, and the store has it for the country TK.`

`CountriesLoaded` is unchanged: `said_otherwise` names the same
countries as before.

## What the trial settled

- **The queue's own function is used, unchanged.** `open_field_doubt`
  gives back the item that is there when this source says this of this
  field of this record already, open or decided, and writes nothing. So
  a second loading opens nothing again, and "a question a person has
  answered is not put to them again" (`motosphere.db.review`). A test
  listens to the statements sent to SQLite and hears none that writes.
- **A file that says yet another thing opens another item.** An item is
  one thing a source says. When a newer release says a third name, that
  is a new doubt beside the old one, whatever was decided of the old.
- **A code of three under another code of two is a doubt about that
  other country.** The file's country is not stored, so there is no
  record of it to doubt. What the file says in effect is that the
  stored country with that code of three has another code of two
  letters, and that is what waits: the field `alpha_2` of that country.
  It is not a possible duplicate: a duplicate is two stored records.
- **A country that differs both ways waits twice or three times.** One
  item for each field. A country whose own code of three differs, and
  whose file code of three another country has, gives an item about
  each of the two countries.
- **A country of the store that the file does not have is no doubt.**
  The file says nothing of it, so no source says anything of a field.
  It is named in `not_in_the_file`, as before. Such a country can be
  right: a federation may list a country ISO 3166-1 does not have.
- **The comparison is the loading's own.** A name is compared letter
  for letter, as in DAT-059: a name that differs by a capital, by a
  space or by a letter written as two is another name, and waits.
- **The stored countries are read as records only when one differs.**
  The loading still reads the two codes and the name of all countries
  as plain columns. `open_field_doubt` wants a record this unit of work
  read, so the helper reads those of the differing countries, and is
  not called when there is none.
- **No ordering of what is read.** The helper finds each record by its
  code; both codes are held once by the store, so the order in which
  SQLite gives the rows changes nothing.
- **The item's source is the source of the countries.** That is the
  row DAT-060 stores, which is switched off: a doubt needs a source
  that is stored, not one that is switched on.
- **The moments.** Each item is stored at a moment of its own by the
  store's clock, as the queue's function does it. A test with the clock
  set holds every column of two items.

## The new tests

In `backend/tests/integration/test_countries_load.py`, 16 tests in 11
functions, against a real SQLite file that the migrations built. The
items are read back as SQLite holds them:

- for each of the six ways in which the store says otherwise (another
  name, a capital, a letter written as two, a space, another code of
  three, both), the items that are opened: the record, the field and
  what the file says; and that the six ways and what is expected of
  them are the same six;
- every column of two items with the clock set: the kind, the table,
  the record, the field, the source of the countries (which is not the
  first source of that store), the address of the release, what the
  file says, the state, the reason, and the two moments;
- a code of three under another code of two, which waits as what the
  file says of that country, with its reason word for word; a country
  that differs both ways, which waits about two countries;
- the order of the file;
- no item where the store is as the file has it, or has a country the
  file does not have;
- loaded again, no statement that writes is sent and the three items
  are as they were; an item a person has rejected stays as it was
  decided and no statement that writes is sent; a file that says yet
  another thing opens an item beside the first;
- the items are taken back with a unit of work that fails.
