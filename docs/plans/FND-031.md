# FND-031 – Lint and format checks for Python outside the pipeline

**Phase:** 1 – Foundation
**Depends on:** FND-030 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §5, `docs/WORKFLOW.md`, `TESTING.md`,
`docs/plans/FND-017.md` ("Read this before touching the tests")

## Objective

The Python files outside `backend/` pass the same lint, format and type
checks as the pipeline, and three new gates in the check runner keep it that
way. Today the check runner and the two test folders at the repository root
are held to those rules only by hand.

## Design in short

- The files are `scripts/check.py`, `tests/repo/test_repo_hygiene.py` and
  `tests/scripts/test_check.py`. The gates cover the two folders `scripts/`
  and `tests/`, not a list of files, so a new file is covered from the day
  it is added.
- No new dependency. The gates use the ruff and mypy that the pipeline has
  locked, started from the repository root with
  `uv run --project backend …`. They come straight after the pipeline's own
  gates, so the environment is already installed on a clean checkout.
- `ruff.toml` at the repository root extends `backend/pyproject.toml`, so
  the rules are the pipeline's and stay the pipeline's. The one difference:
  the rules about pytest style (`PT`) are off, because these tests are
  written with the standard library's `unittest`.
- `mypy.ini` at the repository root checks `scripts` and `tests` as strictly
  as the pipeline's own configuration.
- The pipeline's own gates, commands and configuration do not change. ruff
  uses the closest configuration file, so files under `backend/` still
  follow `backend/pyproject.toml` alone.
- Bringing the existing files into line is small: return types in the
  repository checks, two marked and explained exemptions for its Git call,
  and two lines rewrapped by the formatter. The check runner and its tests
  already pass.
- A new test fails when a Python file appears outside the pipeline in a
  folder the gates do not cover, so the cover cannot quietly fall behind.
- The rule about the runner's tests still holds: they never run the real
  script in the real repository, only a copy in a stand-in repository.

## Implementation detail

The planner trial-ran everything below on Linux with Python 3.13.18 (and the
runner's tests also with Python 3.12), Node 22.23.4 and uv 0.11.32: the 73
tests passed, the full run reported 19 of 19 gates passed with 476 tests, and
the 38 planted defects listed under "Verification" were all detected. Use
the code as given; if something must differ, say so in the report.

### 1. `ruff.toml` – new, at the repository root

```toml
# Lint and format rules for the Python files outside the pipeline:
# `scripts/`, `tests/repo/` and `tests/scripts/`. They are the pipeline's
# rules (`backend/pyproject.toml`), with the one difference set out below.
extend = "backend/pyproject.toml"

[lint]
# These tests are written with the standard library's `unittest`, so the
# rules about pytest style do not apply to them.
extend-ignore = ["PT"]
```

### 2. `mypy.ini` – new, at the repository root

```ini
# Type check for the Python files outside the pipeline, as strict as the
# pipeline's own (`backend/pyproject.toml`).
[mypy]
python_version = 3.12
files = scripts, tests
strict = True
warn_unreachable = True
warn_return_any = True
enable_error_code = ignore-without-code, redundant-expr, truthy-bool, possibly-undefined
show_error_codes = True
pretty = True
```
