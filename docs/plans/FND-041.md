## Objective

On a touch screen every control is big enough to be hit with a finger.

## Why

The two buttons in the top bar are 31 pixels tall and the sections 40. That
suits a mouse. Under a finger a control should measure at least 44 pixels
(the size both Apple's and the web's accessibility guidelines name), or
the neighbour gets hit instead. This is the fourth of five small tasks
(PLAN-009).

## Design in short

- Where the main way of pointing is a finger, the style sheets say so
  themselves: `@media (pointer: coarse)`. That is true on a phone and on a
  tablet, whatever its width, and normally false on a laptop with a mouse
  or a touchpad, even when it also has a touch screen.
- There, the two buttons in the top bar and the nine sections get a least
  height of 44 pixels: one new token, `--size-touch-target: 2.75rem`, and
  one small rule in each of the two style sheets.
- There, the two buttons also stand in the middle of the bar's first line
  (`align-self: center`) instead of on its line of text. The first line of
  the top bar is 48 pixels tall, so the taller buttons fit into it and the
  bar keeps its height, wide or narrow, but only when they are centred:
  see "Why the buttons are centred" below.
- Nothing else changes. The controls are already wider than 44 pixels (71
  pixels and more).
- With a mouse every size stays exactly as it is.
- Style sheets only. No change to any component, no script.

Measured by the planner with a touch screen: the buttons 44 pixels tall at
320, 390, 900 and 1366 pixels wide, in the middle of the first line of the
bar (from 2 to 46 pixels on a narrow screen; from 1.5 to 45.5 on a wide
one, where the bar's border of one pixel lies inside its 48 pixels); the
sections 44 pixels each, one right under the other; the bar 99 pixels tall
at 390 pixels and 48 at 1366, as with a mouse.

### Why the buttons are centred

The top bar sets everything in it on one line of text
(`align-items: baseline`). The planner's first trial left the tall buttons
there. On the planner's machine they then stood from 3.5 to 47.5 pixels,
inside the bar. On GitHub's machines, which draw the page with other
fonts, the same buttons reached half a pixel out of the bar (to 48.5) and
made the bar on a phone half a pixel taller (99.5), on Linux and on
Windows alike: 3 of 696 tests failed there and none locally. Where a
button stands on a line of text depends on the font, and a button of 44
pixels in a line of 48 has no room for that. Centred, its place is the
same with every font, and the tests check the exact place.

## Implementation detail

### 1. `frontend/e2e/touch.spec.ts` – new, the whole file, 8 tests

```ts
import type { Page } from '@playwright/test'
import { expect, test } from './fixtures'

// The least height and width of a control under a finger, in pixels.
const TOUCH_TARGET = 44
// The heights the controls have with a mouse.
const BUTTON_HEIGHT = 31
const SECTION_HEIGHT = 40
// The height of the top bar when it has one line.
const TOP_BAR_HEIGHT = 48

const PHONE = { width: 390, height: 844 }
const DESKTOP = { width: 1366, height: 768 }
// With each screen, the room the first line of the top bar has for its
// buttons: the whole line on a phone, and one pixel less on a wide screen,
// where the border under the bar lies inside the bar's height.
const SCREENS = [
  { viewport: PHONE, firstLine: TOP_BAR_HEIGHT },
  { viewport: DESKTOP, firstLine: TOP_BAR_HEIGHT - 1 },
]

interface Control {
  name: string
  top: number
  bottom: number
  width: number
  height: number
}

/** Every control of the layout, with its sections panel open. */
async function controls(page: Page): Promise<{ buttons: Control[]; sections: Control[] }> {
  const topBar = page.getByRole('banner')
  const sectionsButton = topBar.getByRole('button', { name: 'Sections', exact: true })
  if ((await sectionsButton.getAttribute('aria-expanded')) === 'false') {
    await sectionsButton.click()
  }
  const sections = page.getByRole('navigation', { name: 'Sections' })
  await expect(sections.getByRole('button')).toHaveCount(9)
  const measure = (selector: string) =>
    page.locator(selector).evaluateAll((elements) =>
      elements.map((element) => {
        const rect = element.getBoundingClientRect()
        return {
          name: element.textContent,
          top: rect.top,
          bottom: rect.bottom,
          width: rect.width,
          height: rect.height,
        }
      }),
    )
  return { buttons: await measure('header button'), sections: await measure('nav button') }
}

for (const { viewport, firstLine } of SCREENS) {
  test.describe(`touch screen, ${viewport.width}×${viewport.height}`, () => {
    test.use({ viewport, hasTouch: true })

    test('the buttons in the top bar are tall enough for a finger, in the middle of its first line', async ({
      page,
    }) => {
      await page.goto('./')
      const { buttons } = await controls(page)

      expect(buttons.map((button) => button.name)).toEqual(['Sections', 'Details'])
      for (const button of buttons) {
        expect(button.height, button.name).toBe(TOUCH_TARGET)
        expect(button.width, `${button.name}: width`).toBeGreaterThanOrEqual(TOUCH_TARGET)
        // In the middle of the first line, whatever the font.
        expect(button.top, `${button.name}: top edge`).toBe((firstLine - TOUCH_TARGET) / 2)
        expect(button.bottom, `${button.name}: bottom edge`).toBe((firstLine + TOUCH_TARGET) / 2)
      }
    })

    test('every section is tall enough for a finger, one right under the other', async ({
      page,
    }) => {
      await page.goto('./')
      const { sections } = await controls(page)

      expect(sections).toHaveLength(9)
      for (const [index, section] of sections.entries()) {
        expect(section.height, section.name).toBe(TOUCH_TARGET)
        expect(section.width, `${section.name}: width`).toBeGreaterThanOrEqual(TOUCH_TARGET)
        const next = sections[index + 1]
        if (next !== undefined) {
          expect(next.top, `${next.name} follows ${section.name}`).toBe(section.bottom)
        }
      }
    })
  })

  test.describe(`mouse, ${viewport.width}×${viewport.height}`, () => {
    test.use({ viewport, hasTouch: false })

    test('the controls keep their sizes', async ({ page }) => {
      await page.goto('./')
      const { buttons, sections } = await controls(page)

      expect(buttons.map((button) => button.height)).toEqual([BUTTON_HEIGHT, BUTTON_HEIGHT])
      expect(sections.map((section) => section.height)).toEqual(
        Array.from({ length: 9 }, () => SECTION_HEIGHT),
      )
    })
  })
}

test.describe('touch screen, the top bar', () => {
  test.use({ hasTouch: true })

  test('keeps its height of one line on a wide screen', async ({ page }) => {
    await page.setViewportSize(DESKTOP)
    await page.goto('./')

    const topBar = await page.getByRole('banner').boundingBox()
    expect(topBar?.height).toBe(TOP_BAR_HEIGHT)
  })

  test('is no taller on a phone than with a mouse', async ({ page, browser }) => {
    await page.setViewportSize(PHONE)
    await page.goto('./')
    await expect(page.getByRole('banner').getByText('Data updated')).toBeVisible()
    const withTouch = await page.getByRole('banner').boundingBox()

    const context = await browser.newContext({ viewport: PHONE, hasTouch: false })
    const mousePage = await context.newPage()
    await mousePage.goto(page.url())
    await expect(mousePage.getByRole('banner').getByText('Data updated')).toBeVisible()
    const withMouse = await mousePage.getByRole('banner').boundingBox()
    await context.close()

    expect(withTouch?.height).toBeGreaterThan(TOP_BAR_HEIGHT)
    expect(withTouch?.height).toBe(withMouse?.height)
  })
})
```

The test browser has a touch screen when it is started with
`hasTouch: true`; `(pointer: coarse)` is then true in it, on Linux and on
Windows.

## Acceptance criteria

1. With a touch screen, at 390 by 844 and at 1366 by 768 pixels, each of
   the two buttons in the top bar is 44 pixels tall, at least 44 wide, and
   exactly in the middle of the first line of the bar.
2. There, each of the nine sections is 44 pixels tall, at least 44 wide,
   and follows right under the one before.
3. With a touch screen the top bar is no taller than with a mouse: 48
   pixels on a wide screen, and on a phone the same height as with a mouse.
4. With a mouse, at both sizes, the buttons are 31 pixels tall and the
   sections 40, as before.
5. The height is one token, `--size-touch-target`, and the unit test of the
   agreed tokens knows it.
6. No existing test changed, and all pass.
7. The full run reports 19 of 19 gates and 696 tests (frontend unit
   tests 211, browser tests 166).
8. On the pull request, "All gates (Linux)" and "All gates (Windows)" are
   green with those numbers, and the three jobs after the gates are
   skipped.
9. Only the files under "Scope" changed.
