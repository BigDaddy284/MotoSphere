# FND-009 – Frontend project skeleton

**Phase:** 1 – Foundation
**Depends on:** FND-008 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §8, §12, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §2, §3, §9

## Objective

A React + TypeScript project under `frontend/` that installs reproducibly from
a lock file, type-checks in strict mode, builds, and renders the application
name. Nothing else: no styling, no tests, no linting, no API calls, no globe.
Those are FND-010 onwards.

## Scope

| File | Purpose |
|---|---|
| `frontend/package.json` | Project metadata, scripts, dependencies |
| `frontend/package-lock.json` | Committed lock file generated by npm |

  covers `node_modules/`, `dist/`, `*.tsbuildinfo` and `.vite/`).

## Implementation detail

The planner trial-ran this exact shape on Node 22 with the versions the
current Vite template selects: vite 8.3, react 19.3, @vitejs/plugin-react 6,
typescript 7.0. Type check and build passed, and `npm audit` reported no
vulnerabilities. You may start from `npm create vite@latest` with the
`react-ts` template, but the result must match the file list above exactly:
delete everything else the template creates (including its lint configuration
and lint dependency, its CSS, its assets, its icons and its README).

### `package.json`

- `"name": "motosphere-frontend"`, `"private": true`, `"version": "0.1.0"`,
  `"type": "module"`.
- `"engines": { "node": ">=22.12" }`.
- Scripts, exactly these four:

  | Script | Command |
  |---|---|
  | `dev` | `vite` |
  | `build` | `tsc -b && vite build` |
  | `typecheck` | `tsc -b` |
  | `preview` | `vite preview` |

- `dependencies`: `react`, `react-dom`.
- `devDependencies`: `@types/node`, `@types/react`, `@types/react-dom`,
  `@vitejs/plugin-react`, `typescript`, `vite`. Nothing else.
- Generate `package-lock.json` with `npm install` and commit it unedited.

### TypeScript configuration

`tsconfig.json` references `tsconfig.app.json` (includes `src`) and
`tsconfig.node.json` (includes `vite.config.ts`), as in the Vite template.
Keep the template's bundler-mode settings (`moduleResolution: bundler` for the
app, `verbatimModuleSyntax`, `noEmit`, `jsx: react-jsx`,
`types: ["vite/client"]`, build info under `node_modules/.tmp/`). In **both**
compiler configurations set explicitly:

```json
"strict": true,
"noUncheckedIndexedAccess": true,
"noImplicitOverride": true,
"exactOptionalPropertyTypes": true,
"noUnusedLocals": true,
"noUnusedParameters": true,
"noFallthroughCasesInSwitch": true
```

No `// @ts-ignore`, `// @ts-expect-error` or `any` in the source.

### `index.html`

`<!doctype html>`, `<html lang="en">`, UTF-8 charset, viewport meta, a
`<meta name="description">` with one plain sentence about MotoSphere,
`<title>MotoSphere</title>`, the favicon link, `<div id="root"></div>` and the
module script for `/src/main.tsx`.

### `public/favicon.svg`

A small (under 1 KB), original, simple SVG: for example a dark filled circle
with a lighter curved line suggesting a globe. Do not reuse the Vite or React
logo or any third-party artwork.

### `src/App.tsx`

Named exports only (no default export):

```tsx
export const APP_NAME = 'MotoSphere'
export const APP_TAGLINE = 'The World of Motocross, Connected.'

export function App() { ... }
```

`App` renders a `<main>` containing an `<h1>` with `APP_NAME` and a `<p>` with
`APP_TAGLINE`. Nothing else.

### `src/main.tsx`

Looks up `#root`; if it is missing, throws an `Error` with a clear message
(no non-null assertion); otherwise renders `<App />` inside `<StrictMode>`
with `createRoot`.

## Acceptance criteria

1. `npm ci` succeeds from a clean checkout.
2. `npm run typecheck` passes with the strict settings above.
3. `npm run build` produces `dist/index.html` and a script bundle under
   `dist/assets/`; the built page, served by `npm run preview`, shows the
   application name.
4. `node_modules`, `dist` and build caches are not tracked or visible in
   `git status`; no template demo content remains; exactly the listed files
   exist under `frontend/`.
5. README, TESTING.md and CHANGELOG.md describe the frontend commands.
6. Repository checks still pass 9/9 and the backend is untouched.

## Verification

From a clean state (delete `frontend/node_modules` and `frontend/dist` first
if they exist):

```
cd frontend
npm ci
npm run typecheck
npm run build
cd ..
python -m unittest discover -s tests/repo -v
git status --short
git ls-files frontend
```

Expected: `npm ci` reports no errors; type check exits 0; the build lists
`dist/index.html` and one `dist/assets/index-*.js`; `Ran 9 tests` / `OK`;
clean status once committed; `git ls-files frontend` prints exactly the ten
files in the scope table.

Then check the built page for real:

1. From `frontend/`, run `npm run preview` (serves the build on
   `http://localhost:4173`). In a second terminal:
   `curl -s http://localhost:4173/` contains `<title>MotoSphere</title>` and
   `<div id="root">`; the script URL it references returns 200; and
   `curl -s -o /dev/null -w "%{http_code}" http://localhost:4173/favicon.svg`
   prints `200`. Stop the preview server.
2. If a browser automation tool is already available in your environment,
   open the preview page and confirm the heading text `MotoSphere` is visible
   and the console has no errors. Do not add any such tool to the project;
   if none is available, say so in the report. The planner performs this
   browser check independently either way.

Then prove the gates can fail (do not commit these changes):

1. In `src/App.tsx`, temporarily add `const count: number = 'one'` inside
   `App` → `npm run typecheck` and `npm run build` must both exit non-zero.
   Restore it.
2. Temporarily add an unused import to `src/main.tsx` → `npm run typecheck`
   must exit non-zero. Restore it.

Finish with `git status` clean.
