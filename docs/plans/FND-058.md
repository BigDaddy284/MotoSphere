# FND-058 – The globe tests have a browser that draws 3D pictures, one test at a time

**Phase:** 1 – Foundation (added later, for Phase 3)
**Track:** B (see `TASKS.md`, "Two tracks")
**Depends on:** FND-054 (the browser of the browser tests), GLB-025
(merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3 and §6, `docs/WORKFLOW.md`, `TASKS.md`
("Two tracks" and the entry of this task), `PROGRESS.md` (PLAN-053),
`TESTING.md` ("The browser of the browser tests"),
`frontend/playwright.config.ts`, `frontend/e2e/browser.ts`,
`frontend/e2e/browser.spec.ts`, `frontend/e2e/fixtures.ts`

## Objective

The browser tests of the globe get a project of their own: its browser
is told how to draw 3D pictures, so that it says nothing of its own on
the console, and its tests run one at a time. A globe test that runs
beside another fails and says so.

## Why

The next tasks put the globe into the page and test it in a real
browser. Before the first of them, the planner measured how the
browser of the tests draws a 3D picture, on a developer's Linux machine
and on both of GitHub's machines (PLAN-053 in `PROGRESS.md`; the
numbers are in the new section of `TESTING.md`). Three things were
found:

- **Four warnings for every page with a 3D picture.** Started as the
  tests start it today, the browser logs four warnings of its own for
  every page that shows a 3D picture ("GPU stall due to ReadPixels").
  Every browser test fails on a warning on the console
  (`e2e/fixtures.ts`), so every test of the globe would fail, for no
  fault of the page. Told one word more, `--use-angle=swiftshader`, the
  browser says nothing, on all three machines, and on GitHub's Linux
  machine the Earth appears four to five times sooner.
- **Two globes at once starve each other on GitHub's Windows machine.**
  Of eight globes started two at a time there, seven were not complete
  within 40 seconds. One alone was complete in 2.1 to 4.8 seconds.
- **One globe at a time is drawn.** In a run of all browser tests with
  the globes held to one at a time, 16 of 16 were complete on the
  Windows machine, in 1.5 to 7.6 seconds, and 16 of 16 on the Linux
  machine, in 0.6 to 0.8 seconds. Playwright started them after the
  other tests, at the end of the run.

So the tests of the globe need a browser of their own and a rule of
their own, and both are set up and tested here, before there is a
globe: the task has no globe in it, only a plain 3D picture of four
lines, and what it sets up is what GLB-002 and the tasks after it
stand on.

## Design in short

`frontend/e2e/browser.ts`:

- `SOFTWARE_3D_SWITCH` is `'--use-angle=swiftshader'`.
- `GLOBE_BROWSER` is `TEST_BROWSER` with that word after the list of
  features to turn off: `{ ...TEST_BROWSER, args: [TEST_BROWSER_SWITCH,
  SOFTWARE_3D_SWITCH] }`.

`frontend/playwright.config.ts` has two projects:

| Project | Its tests | Its browser | Workers |
|---|---|---|---|
| `chromium` | Every file under `e2e` that is not in `e2e/globe` | `TEST_BROWSER`, as before | As the run has them |
| `globe` | The files in `e2e/globe` | `GLOBE_BROWSER` | 1 |

`frontend/e2e/globe/fixtures.ts` gives the `test` every globe test
uses. It is the `test` of all browser tests (`e2e/fixtures.ts`), so a
globe test fails on any problem of the page like every other, and it
adds one thing: for as long as a test runs it holds the turn, a file in
the folder of the run's results that only one can make
(`takeTheTurn`). A test that finds the file there fails with

> Two globe tests ran at once. They must run one at a time: see the
> project "globe" in playwright.config.ts.

## What the trial settled

- **A project, not a second command.** The globe tests could have been
  a gate of their own in `scripts/check.py`. A project keeps them in
  the one command and the one count of the browser tests, and builds
  the site once. `npx playwright test --project globe` runs them alone.
- **The limit is Playwright's own, for one project.** A project can be
  given a number of workers of its own (`workers: 1`), and the run keeps
  its number for the rest. So the other tests run two at a time on
  GitHub as before, and the globe tests one at a time.
- **No order is set between the projects.** Playwright can make one
  project wait for another (`dependencies`). Then a person who runs one
  globe test runs every other test first. It is not needed: Playwright
  starts the tests of the first project first, and in the measurement
  and in the trial on GitHub the globe tests were the last of the run
  on both machines. What was not measured is a globe drawn while other
  browser tests run beside it. If a later Playwright mixes the
  projects and the globe tests become slow on GitHub's Windows machine,
  that is where to look; `TESTING.md` says so.
- **The limit is held by the tests themselves.** That a project is
  given one worker is a line in the settings, which a later change or
  an upgrade of Playwright can take the meaning from, and the price is
  a run on GitHub's Windows machine that starves without saying why. So
  every globe test holds the turn while it runs, and the second of two
  at once fails with a sentence that says where to look. Four tests
  that do nothing but take a third of a second each are there so that
  two workers have something to collide on: with the limit taken out,
  the run fails.
- **The turn is a file that only one can make.** Tests of one run share
  no memory: each worker is a process of its own. They share the folder
  of the run's results, which Playwright empties before every run, so a
  turn that a broken run left behind is gone at the next.
- **The turn is handed back when the test is over, however it ended.**
  What a fixture does after it handed over is done after a failed test
  as after a passed one; a test checks that the turn is held while a
  test runs, and each test after it would fail if one before it had
  kept the turn.
- **The refusal carries what the system said.** That the file is there
  is one reason why it cannot be made; a folder that cannot be written
  to is another, and the sentence would then send a person the wrong
  way. So the error of the system goes with the sentence, as its cause
  (`EEXIST` when another has the turn), and a test holds that.
- **The fixture names the page.** Playwright tells a fixture about its
  test only after the fixtures it asks for, and wants one named. Every
  browser test has the page, through the rule of the problems, so
  naming it costs nothing.
- **The renderer is the same with the word and without it.** On all
  three machines the browser draws in software either way, with the
  renderer that comes with it (SwiftShader). The word changes how the
  picture is brought to the page. So the test of the renderer does not
  tell the two apart; the test that does is the one that shows thirty
  pictures and hears nothing on the console.
- **The other tests keep their browser.** They show no 3D picture, so
  nothing changes for them. `TEST_BROWSER` is as it was, and four of
  the five tests of `e2e/browser.spec.ts` are untouched.

`e2e/browser.spec.ts`, `is set for the one project there is`, held that
the settings have one project and that it is given `TEST_BROWSER`.
There are two projects now. The test becomes `is set for every project,
and for the project of the globe with one word more`: it holds that it
runs in the project `chromium` with `TEST_BROWSER`, and that the two
projects are given `TEST_BROWSER` and `GLOBE_BROWSER`, in that order.
It says more than before, and nothing it said is dropped.

## The new tests

`frontend/e2e/globe/browser.spec.ts`, 9 tests, all in the project
`globe`:

- the browser of the project is started with exactly one list of
  features to turn off, the list of every test's browser, and with
  exactly one word on how to draw, the word; and `GLOBE_BROWSER` is
  `TEST_BROWSER` with the two;
- a page of the site shows thirty 3D pictures one after another, of the
  size asked for, drawn in software, with the picture not lost, and the
  rule of every browser test hears nothing on the console;
- the test runs in the project `globe`, the second of two, with
  `GLOBE_BROWSER`;
- a globe test holds the turn while it runs, in the folder its own
  results lie in, and one who asks for the turn then is refused with

  yet, refused to a second, who is told what the system said of the
  file too (`EEXIST`), handed back, and taken again;
- four tests that take a third of a second each.

The browser tests go from 261 to 270.
