# FND-036 – Remove the audit exception that is no longer needed

**Phase:** 1 – Foundation

## Why this task exists, and why it is urgent

On 2026-11-17 an exception was recorded for one security advisory
(GHSA-fc5q-39xc-vjpf, picomatch), because no fixed version existed
(FND-033). On 2026-11-18 `npm audit` no longer reports that advisory: its
report holds 0 advisories, for the same lock file and the same picomatch
(4.0.7, still the latest). The npm registry's own list of advisories for
picomatch no longer holds it either. Why it is gone the planner could not
read (the advisory's page cannot be reached from the planning environment).

The audit was built for exactly this: an exception that nothing reports any
more fails the gate, so that the list cannot grow stale. **Until this task
is merged, the last gate fails on `main` and on every pull request**, with:

```
npm audit reports 0 advisories.
FAILED:
  - the exception for GHSA-fc5q-39xc-vjpf (picomatch) is no longer needed: remove it
```

`main` was green at `c04a5db` on 2026-11-17; nothing in the repository
changed since. Your own pull request is the first place it turns green
again.

## Objective

The dependency audit passes again because the exception it no longer needs
is gone, and no other exception takes its place.

## If the advisories have changed again

Advisories are published and withdrawn by other people, so what
`npm audit` reports when you run it may differ from what the planner saw.
You do not add, widen or reword an exception: that is a decision for the
owner and the planner.

- **The picomatch advisory is reported again.** With the empty list the
  gate fails and names it. Stop, do not open a pull request that removes
  the exception, and report the gate's output: the planner will change the
  plan.
- **Another advisory is reported.** The gate fails and names it. Finish
  the task as written, report the advisory, and say that your run is red
  because of it. Do not record an exception and do not update packages.
