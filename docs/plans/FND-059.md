# FND-059 – The other browser tests run in a browser without 3D pictures

**Phase:** 1 – Foundation (added later, for Phase 3)
**Track:** B (see `TASKS.md`, "Two tracks")
**Depends on:** FND-058 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3 and §6, `docs/WORKFLOW.md`, `TASKS.md`
("Two tracks" and the entry of this task), `PROGRESS.md` (PLAN-053),
`TESTING.md` ("The browser of the browser tests" and "The browser of
the globe tests"), `frontend/playwright.config.ts`,
`frontend/e2e/browser.ts`, `frontend/e2e/browser.spec.ts`,
`frontend/e2e/globe/browser.spec.ts`

## Objective

The browser of every test that is not a globe test is started so that a
page gets no 3D picture. The tests of the globe are then the only ones
that can draw one.

## Why

FND-058 holds the globe tests to one at a time, because two 3D pictures
drawn in software at once take each other's processor time, and on
GitHub's Windows machine neither globe is then loaded within forty
seconds. That holds only as long as no other test draws a 3D picture.
Today none does. Once the globe is in the page (GLB-002), every browser
test that opens the page would draw one, two at a time on GitHub.

So the other tests get a browser that gives a page no 3D picture, and
they get it now, while nothing in the page asks for one: the task
changes nothing for any test that is there. What the page shows a
person in such a browser is the task after next on this track, GLB-026.

## What this task is, and what it is not

- **It is** one constant in `frontend/e2e/browser.ts`, `NO_3D_SWITCH`,
  and that word in `TEST_BROWSER`.
- **It is** three new browser tests, two in `frontend/e2e/browser.spec.ts`
  and one in `frontend/e2e/globe/browser.spec.ts`, and two existing
  tests that are named for what is now so.
- **It is** two comments in `frontend/playwright.config.ts`.
- **It is** the documents: `TESTING.md`, `ARCHITECTURE.md` and
  `CHANGELOG.md`.
- **It is not** a change to the page. Nothing under `frontend/src`
  changes.
- **It is not** a change to the browser of the globe tests: it is
  started as before, and a test now holds that it is not told the new
  word.
- **It is not** a change to the projects, to `scripts/check.py`, to the
  workflow or to any package.

## Design in short

`frontend/e2e/browser.ts`:

- `NO_3D_SWITCH` is `'--disable-3d-apis'`.
- `TEST_BROWSER` is told it after its list of features to turn off:
  `args: [TEST_BROWSER_SWITCH, NO_3D_SWITCH]`.
- `GLOBE_BROWSER` is as it was: it takes `ignoreDefaultArgs` from
  `TEST_BROWSER` and names every word it is told itself,
  `args: [TEST_BROWSER_SWITCH, SOFTWARE_3D_SWITCH]`.

| Project | Its browser | A page that asks for a 3D picture |
|---|---|---|
| `chromium` | `TEST_BROWSER`: the list of features to turn off, and `--disable-3d-apis` | Is given none |
| `globe` | `GLOBE_BROWSER`: the list of features to turn off, and `--use-angle=swiftshader` | Is given one, drawn in software, as before |

## What the trial settled

- **The word is `--disable-3d-apis`.** A page that asks a browser
  started with it for a 3D picture of either kind
  (`getContext('webgl2')`, `getContext('webgl')`) is given nothing, as
  in a browser that cannot draw one. It still gets a flat picture, and
  the browser says nothing on the console about either. Two other
  words were tried as planted defects and do not do it:
  `--disable-gpu` leaves a page both kinds of 3D picture, and
  `--disable-webgl2` takes away only the newer kind.
- **The tests that are there pass in such a browser.** For PLAN-053
  the 261 browser tests of that day were run in a browser started with
  the word on both of GitHub's machines, and all passed but the one
  that says how the browser is started (trial pull request #202, run
  46063407570). In this trial the whole run passes, here and on both
  of GitHub's machines (below).
- **The browser of the globe tests names its words itself.**
  `GLOBE_BROWSER` was written in FND-058 with its own `args`, so the
  new word does not reach it, and nothing in it changes. A new test in
  the project `globe` holds that its browser is not started with the
  word, and the test that shows thirty 3D pictures fails if it is.
- **A test asks the page, not only the settings.** That the browser is
  started with a word is one thing; that a page then gets no 3D
  picture is what the task is for, and a later browser may no longer
  know the word. Chromium does not refuse a word it does not know: it
  starts and gives the page a 3D picture. So one test has a page of
  the site ask for both kinds and for a flat picture, and holds what
  it gets. With a word the browser does not know planted, that test
  fails.
- **Both kinds are asked for.** The engine can draw with either. With
  `--disable-webgl2` planted, the test fails for the older kind.
- **The flat picture is read back.** The test draws one colour and
  reads it from the picture, so "a flat picture as before" is seen and
  not taken on trust.
- **The word stands after the list of features.** The order means
  nothing to the browser; one test holds `TEST_BROWSER` whole, so that
  the constant says exactly what the documents say.

## The two existing tests that are named anew, and why

No line inside either test changes; only what they are called.

- `e2e/browser.spec.ts`: `is set for every project, and for the project
  of the globe with one word more` becomes `is set for the project of
  these tests, and the browser of the globe for its project`. The
  browser of the globe is no longer the browser of the tests with one
  word more: each has a word the other has not.
- `e2e/globe/browser.spec.ts`: `is started as the browser of every
  test, and told to draw 3D pictures in software` becomes `is started
  with the features of every test turned off, and told to draw 3D
  pictures in software`. It is no longer started as the browser of
  every test is.

## The new tests

`frontend/e2e/browser.spec.ts`, 2 tests, in the project `chromium`:

- `is told once to give its pages no 3D picture`: a browser started as
  the project starts one was told exactly one word that begins as the
  word does, the word itself; the word is `--disable-3d-apis`; and
  `TEST_BROWSER` is exactly the two settings with the two words.
- `gives a page no 3D picture, and a flat one as before, without a word
  of its own`: a page of the site asks for a `webgl2` picture, a
  `webgl` picture and a flat one, each on a drawing surface of its own;
  it gets neither of the first two, and reads the colour it drew from
  the third; the rule of every browser test hears nothing on the
  console.

`frontend/e2e/globe/browser.spec.ts`, 1 test, in the project `globe`:

- `is not told to give its pages no 3D picture`: a browser started as
  the project starts one was told no word that begins as the word
  does; `GLOBE_BROWSER.args` is exactly its two words; and
  `TEST_BROWSER.args` does have the word, so the test cannot pass
  because the word went missing everywhere.

The browser tests go from 270 to 273.
