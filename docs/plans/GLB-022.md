**Phase:** 3 – Interactive 3D Earth
**Track:** B (see `TASKS.md`, "Two tracks")
**Depends on:** GLB-001 (merged), FND-047 and FND-051 (merged), FND-052 (merged)

## Objective

The files the engine fetches while it runs are part of the built site,
under one folder of the site's path.

## Why

The engine of the globe (`@cesium/engine`, installed by GLB-001) does
part of its work in background scripts and reads programs, tables and
pictures from files of its own: the picture of the Earth it starts
with, the stars, the tables for the Earth's turning. It asks for each
by its name beneath one address, while it runs. These files come with
the package, in its folder `Build`, and are not code: the build does
not take them in by itself. Without them in the site the globe of
GLB-002 has nothing to fetch.

## What this task is, and what it is not

- **It is** a step of the build, `frontend/sitebuild/engineFiles.ts`
  (new), that puts every file beneath `node_modules/@cesium/engine/Build`
  into the site under the folder `cesium/`, as it is, and its place in
  `frontend/vite.config.ts`.
- **It is** a list, in that step, of the files that are left out, each
  with its reason. It has two entries.
- **It is** 16 unit tests of the step and 23 browser tests of the built
  site.
- **It is not** the development server: `npm run dev` does not answer
  the folder yet. That is GLB-024.
- **It is not** telling the engine where the files are. That is
  GLB-025. Nothing of the application asks for a file of the folder
  yet, so a visitor's browser fetches none.
- **It is not** a change to `scripts/live.py`. The check of the
  published site compares every published file with the built one byte
  for byte, whatever its kind, and so holds these files from this task
  on. What GitHub Pages says a `.wasm` and a `.jpg` file are is
  FND-053.
- **It is not** a choice of imagery. The pictures are passed on as the
  package brings them; what the globe shows, and with what credit, is
  GLB-002 and GLB-015.

## Design in short

- **Every file, none picked by hand.** The step walks the folder `Build`
  of the installed engine and takes every file at any depth: 277 files
  with `@cesium/engine` 26.5.0, in the folders `Assets`, `ThirdParty`,
  `Widgets` and `Workers`. Another version of the engine then brings
  what it needs without anyone editing a list.
- **Two files are left out, by name, each with why.** `LEFT_OUT` in the
  step names `Assets/Images/bing_maps_credit.png` and
  `Assets/Images/google_earth_credit.png`: logos of other companies,
  which the engine shows only with imagery of those companies. The
  globe uses neither (CLAUDE.md and ARCHITECTURE.md §8: no Google
  assets, and a provider only with its terms read). A file is put on
  that list by a person, and the build stops when a listed file is not
  there any more, so the list cannot go stale in silence. The site so
  gets 275 files, 8.3 MB.
- **One folder of the site.** The files go to `cesium/` under the
  site's path (`ENGINE_FOLDER`), with the folders the engine keeps them
  in, because the engine asks for `Workers/…`, `Assets/…` by those
  names beneath one address.
- **As they are.** Each file is read as bytes and handed to the build
  under its own name (`emitFile` with a `fileName`), so the build
  neither renames nor rewrites it.
- **In a set order.** The files of a folder come before those of the
  folders in it, each by name, on every computer, as in the step of the
  licences (FND-051).
- **What is not a file or a folder stops the build.** The engine brings
  no link; a link among its files would put something into the site
  that the package did not bring.
- **The licence.** The engine's licence is in the site's `licences.txt`
  already (FND-047), with the notices of the code of others the engine
  brings. No second copy is put beside the files; a browser test holds
  that the text is in `licences.txt`.
- **For the build only** (`apply: 'build'`). The development server is
  GLB-024.

## What the task left open, and what the trial settled

- **Which files does the engine need?** All of `Build`. The trial read
  how the engine asks (`buildModuleUrl`, by name beneath one base
  address) and did not try to tell which names it will ask for with
  the features MotoSphere uses: a file that is missing shows only when
  that feature first runs.
- **Are there files that must not go out?** The two logos. The trial
  looked at every picture in `Assets/Images`: besides the two there are
  the engine's own logo, which it shows by default, and the logo of
  Cesium ion. They stay; what the globe shows as credit is GLB-015.
- **Does the engine's licence say anything of the pictures and tables?**
  No: `LICENSE.md` is the Apache licence 2.0 and the notices of code of
  others. The files are passed on unchanged, as the package brings
  them, under that licence. This plan claims nothing more about them.
- **Does the build change a file?** No: all 275 are byte for byte the
  files of the package, in the built folder and through the server.
- **How large is the site then?** 283 files, 8.8 MB, where it had 8
  files and 0.44 MB. A visitor's browser fetches none of the new ones
  until the globe asks for them.
- **Does the check of the published site need a change?** No. It has
  no rule for `.jpg`, `.wasm` and `.xml`, and compares those byte for
  byte like every file. After the merge it compares 283 files.
- **Could the tests tell a file that is left out?** Not before FND-052,
  which this task stands on: the site under test answered every
  address with the page.

+/**
+ * The engine's own files, in the site.
+ *
+ * The engine of the globe does part of its work in background scripts, and
+ * reads pictures and tables from files of its own. It fetches them while it
+ * runs, each by its name beneath one address. They come with the package,
+ * in its folder `Build`, and are not code the build takes in. This step puts
+ * them into the site as they are, under one folder. The engine's licence is
+ * in the site's file of licences, with those of the other packages.
+ */
+
+/** The folder of the site that holds the engine's files. */
+export const ENGINE_FOLDER = 'cesium'
+
+/** The engine as it is installed, from the folder of the project. */
+export const ENGINE_PACKAGE = 'node_modules/@cesium/engine'
+
+/** The folder of the package that holds the files it fetches while it runs. */
+export const BROUGHT_IN = 'Build'
+
+/**
+ * The files of the engine the site leaves out, each with why. A file is put
+ * here by a person who has read what the engine does with it, never by the
+ * build. Each is a picture of another company, which the engine shows only
+ * with imagery of that company. The globe uses none, and a provider of
+ * imagery is taken on with its terms read, its pictures with it.
+ */
+export const LEFT_OUT: Readonly<Record<string, string>> = {
+  'Assets/Images/bing_maps_credit.png': 'The logo of Bing Maps, shown with imagery of Bing Maps.',
+  'Assets/Images/google_earth_credit.png':
+    'The logo of Google Earth, shown with imagery of a Google Earth server.',
+}
+
+/** The engine's files cannot be put into the site, and why. */
+export class EngineFilesError extends Error {
+  override name = 'EngineFilesError'
+}
+
+/**
+ * Every file beneath a folder, each by its path from it, with `/` between the
+ * parts on every computer. The files of a folder come before those of the
+ * folders in it, each by name. Anything that is neither a file nor a folder,
+ * a link among them, stops the build: the engine brings none, and the site
+ * is to hold what the engine brings and nothing a link leads to.
+ */
+function filesBeneath(folder: string, beneath = ''): string[] {
+  const entries = readdirSync(join(folder, beneath), { withFileTypes: true })
+  const strange = entries.find((entry) => !entry.isFile() && !entry.isDirectory())
+  if (strange !== undefined) {
+    throw new EngineFilesError(
+      `${join(folder, beneath, strange.name)} is neither a file nor a folder.`,
+    )
+  }
+  const here = entries
+    .filter((entry) => entry.isFile())
+    .map(({ name }) => name)
+    .toSorted()
+    .map((name) => `${beneath}${name}`)
+  const deeper = entries
+    .filter((entry) => entry.isDirectory())
+    .map(({ name }) => name)
+    .toSorted()
+    .flatMap((name) => filesBeneath(folder, `${beneath}${name}/`))
+  return [...here, ...deeper]
+}
+
+/**
+ * The files of the engine that go into the site, for the project given: each
+ * by its path beneath the folder the engine fetches from.
+ */
+export function engineFiles(
+  project: string,
+  leftOut: Readonly<Record<string, string>> = LEFT_OUT,
+): string[] {
+  const folder = join(project, ENGINE_PACKAGE, BROUGHT_IN)
+  let all: string[]
+  try {
+    all = filesBeneath(folder)
+  } catch (error) {
+    if (error instanceof EngineFilesError) {
+      throw error
+    }
+    throw new EngineFilesError(`${folder} cannot be read. Run "npm ci" first.`)
+  }
+  if (all.length === 0) {
+    throw new EngineFilesError(`${folder} holds no file.`)
+  }
+  for (const name of Object.keys(leftOut)) {
+    if (!all.includes(name)) {
+      throw new EngineFilesError(`${name} is listed as left out, and the engine does not bring it.`)
+    }
+  }
+  return all.filter((name) => !Object.hasOwn(leftOut, name))
+}
+

+export function engineFilesInTheSite(): Plugin {
+  let project = process.cwd()

+    apply: 'build',
+    configResolved(config) {

+        this.emitFile({
+          type: 'asset',
+          fileName: `${ENGINE_FOLDER}/${file}`,
+          source: readFileSync(join(brought, file)),
+        })
+      }
+    },
+  }
+}
