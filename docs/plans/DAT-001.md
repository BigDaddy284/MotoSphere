**Phase:** 2 – Data store and published data
**Depends on:** Phase 1 (complete)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §11, §12, `docs/WORKFLOW.md`, `TESTING.md`,
`ARCHITECTURE.md` §2 and §5, `DATABASE.md`,
`backend/src/motosphere/publish/files.py` and
`backend/tests/unit/test_publish_files.py` (the style of a module and of its

## Objective

Decide, with evidence, what the data store may rely on: which SQLite
features every machine that runs the pipeline has, where the store is kept
between scheduled runs, and which size limits bound it.

## Why

Phase 2 gives the pipeline a real store, an SQLite file. Before the first
table exists, three things must be known and written down, because
everything after them depends on them:

1. **SQLite is not one program.** Every Python carries its own, built with
   its own choice of features. The planner's probe found three different
   ones: 3.45.1 on GitHub's Linux machine, 3.49.1 on GitHub's Windows
   machine, 3.53.1 on the planner's. Two features differ between them. A
   store that used one of those two would pass every test on one machine
   and fail on another.
2. **A run on GitHub starts on an empty machine.** The store must be kept
   somewhere between runs, and that choice shapes the snapshot tasks
   (DAT-019, DAT-020).
3. **GitHub has size limits** for files, repositories and Pages sites, and
   the store and the published data must stay inside them.

`ARCHITECTURE.md` §5 has carried the second as an open question since the
hosting decision. This task closes it.

## Design in short

- One small module, `motosphere.db.sqlite`, names what the store relies
  on: a least version (3.45.0) and six features. Its function `missing()`
  returns one plain sentence for everything a given SQLite lacks, and an
  empty list when it lacks nothing. The package is `db`, as
  `ARCHITECTURE.md` §2 names it.
- **A feature is proven by statements, not by build options.** For each
  feature the module holds the statements a database must accept and, for
  two of them, a statement it must then refuse: a child row without its
  parent (foreign keys), text in a number column (strict tables). A build
  that accepts `PRAGMA foreign_keys = ON` and enforces nothing is found
  out.
- **Each feature is tried in an empty database of its own**, in memory,
  closed afterwards. No feature can lean on another, and the check touches
  no file.
- **The tests are of two kinds.** The integration tests ask the machine's
  own SQLite, unchanged: they are the proof on each machine the gates run
  on. The unit tests make the real SQLite behave like a lesser one (a
  subclass of the connection that reports another version, refuses what a
  lesser build refuses, or lets through what should have been refused), so
  every sentence `missing()` can say is checked without a mock.
- **The decision record is `DATABASE.md`**, and two tests compare it with
  the module (the least version and the six features), so the two cannot
  drift apart.
- Nothing opens a store yet: no setting, no connection module, no table.
  Those are DAT-002 onwards, and DAT-002 will call `missing()` before it
  opens anything.

### 2. `backend/src/motosphere/db/sqlite.py` – new, the whole file

```python
"""What the data store needs from SQLite, and whether a given SQLite has it.

SQLite is not one program: every Python carries its own, built with its own
choice of features, and the Python on a GitHub machine is not the one on a
developer's computer. So the store relies only on what is named here, and
:func:`missing` says in plain words what a given SQLite lacks. Its tests run
against the real SQLite of the Python that runs them, on Linux and on Windows
(``DATABASE.md`` records what each machine had when this was decided).

Nothing here opens the store itself. The check works in a database of its
own, in memory, which is gone when the check ends.
"""

import contextlib
import sqlite3
from collections.abc import Callable
from dataclasses import dataclass

__all__ = ["FEATURES", "LEAST_VERSION", "Feature", "Version", "missing", "text_of", "version_of"]

Version = tuple[int, ...]

# The least SQLite the store works with: 3.45 is the oldest series it has been
# run with. An older one may well have every feature below; nobody has tried.
LEAST_VERSION: Version = (3, 45, 0)


@dataclass(frozen=True)
class Feature:
    """One thing the store relies on, and the statements that prove it is there."""

    # What it is, in plain words, to complete "this SQLite has no ...".
    name: str
    # Every statement must be accepted, in this order.
    accepted: tuple[str, ...]
    # If given, this statement must be refused after the others were accepted.
    refused: str = ""


FEATURES: tuple[Feature, ...] = (
    Feature(
        "foreign keys that are enforced",
        (
            "PRAGMA foreign_keys = ON",
            "CREATE TABLE parent (id INTEGER PRIMARY KEY)",
            "CREATE TABLE child (parent_id INTEGER NOT NULL REFERENCES parent (id))",
        ),
        refused="INSERT INTO child (parent_id) VALUES (1)",
    ),
    Feature(
        "tables with strict column types",
        ("CREATE TABLE strict_types (number INTEGER) STRICT",),
        refused="INSERT INTO strict_types (number) VALUES ('not a number')",
    ),
    Feature(
        "statements that return the rows they wrote (RETURNING)",
        (
            "CREATE TABLE returned (id INTEGER PRIMARY KEY, name TEXT)",
            "INSERT INTO returned (name) VALUES ('a') RETURNING id",
        ),
    ),
    Feature(
        "JSON functions",
        ("""SELECT json_extract('{"a": 1}', '$.a')""",),
    ),
    Feature(
        "R*Tree indexes (for finding places inside a part of the map)",
        ("CREATE VIRTUAL TABLE boxes USING rtree (id, west, east, south, north)",),
    ),
    Feature(
        "full-text search (FTS5)",
        ("CREATE VIRTUAL TABLE words USING fts5 (body)",),
    ),
)

Connect = Callable[[], sqlite3.Connection]


def text_of(version: Version) -> str:
    """A version the way people write it: 3.45.0."""
    return ".".join(str(part) for part in version)


def _in_memory() -> sqlite3.Connection:
    """A new, empty database in memory, in which every statement takes effect at once."""
    return sqlite3.connect(":memory:", isolation_level=None)


def version_of(connection: sqlite3.Connection) -> Version:
    """The version of the SQLite behind a connection."""
    (text,) = connection.execute("SELECT sqlite_version()").fetchone()
    return tuple(int(part) for part in str(text).split("."))


def _has(feature: Feature, connect: Connect) -> bool:
    """Whether a new, empty database accepts and refuses what the feature says."""
    with contextlib.closing(connect()) as connection:
        try:
            for statement in feature.accepted:
                connection.execute(statement).fetchall()
        except sqlite3.Error:
            return False
        if not feature.refused:
            return True
        try:
            connection.execute(feature.refused).fetchall()
        except sqlite3.Error:
            return True
        return False


def missing(connect: Connect = _in_memory) -> list[str]:
    """What this SQLite lacks, one plain sentence each. Empty when it lacks nothing.

    ``connect`` gives a new, empty database every time it is called; each
    feature is tried in one of its own, so no feature can help or hinder
    another.
    """
    problems = []
    with contextlib.closing(connect()) as connection:
        version = version_of(connection)
    if version < LEAST_VERSION:
        problems.append(
            f"SQLite {text_of(version)} is older than {text_of(LEAST_VERSION)}, "
            "the least version the data store works with"
        )
    problems.extend(
        f"this SQLite has no {feature.name}" for feature in FEATURES if not _has(feature, connect)
    )
    return problems
```

### 3. `backend/tests/unit/test_db_sqlite.py` – new, the whole file, 33 tests

```python
"""Tests for what the data store needs from SQLite (`motosphere.db.sqlite`).

A lesser SQLite is stood in for by the real one, in memory, made to behave
like it: it reports another version, refuses statements a lesser build
refuses, or lets through what it should have refused. The tests against the
machine's own SQLite, unchanged, are in `tests/integration`.
"""

import sqlite3
from collections.abc import Callable
from pathlib import Path
from typing import Any

import pytest

from motosphere.db import sqlite
from motosphere.db.sqlite import FEATURES, LEAST_VERSION, Feature, missing, text_of, version_of

REPOSITORY = Path(__file__).resolve().parents[3]

Connect = Callable[[], sqlite3.Connection]


def lesser(
    *, version: str = "", refuses: tuple[str, ...] = (), drops: tuple[str, ...] = ()
) -> Connect:
    """An SQLite that says it is ``version``, refuses every statement that holds
    one of ``refuses``, and acts as if each of ``drops`` had not been written."""

    class Lesser(sqlite3.Connection):
        def execute(self, sql: str, parameters: Any = (), /) -> sqlite3.Cursor:
            if version and sql == "SELECT sqlite_version()":
                return super().execute("SELECT ?", (version,))
            if any(words in sql for words in refuses):
                raise sqlite3.OperationalError(f"not in this build: {sql}")
            for words in drops:
                sql = sql.replace(words, "")
            return super().execute(sql, parameters)

    return lambda: sqlite3.connect(":memory:", isolation_level=None, factory=Lesser)


def at(version: sqlite.Version) -> Connect:
    """A complete SQLite that says it is ``version``."""
    return lesser(version=text_of(version))


OLD = (
    "SQLite {found} is older than "
    + text_of(LEAST_VERSION)
    + ", the least version the data store works with"
)


def test_a_version_is_written_the_way_people_write_it() -> None:
    assert text_of((3, 45, 0)) == "3.45.0"


def test_reads_the_version_of_the_sqlite_behind_a_connection() -> None:
    connection = sqlite3.connect(":memory:")
    try:
        assert version_of(connection) == sqlite3.sqlite_version_info
    finally:
        connection.close()


def test_reads_the_version_as_numbers() -> None:
    connection = at((3, 9, 12))()
    try:
        assert version_of(connection) == (3, 9, 12)
    finally:
        connection.close()


def test_a_complete_sqlite_of_the_least_version_lacks_nothing() -> None:
    assert missing(at(LEAST_VERSION)) == []


def test_a_newer_sqlite_lacks_nothing() -> None:
    newer = (LEAST_VERSION[0], LEAST_VERSION[1] + 1, 0)

    assert missing(at(newer)) == []


def test_an_sqlite_just_below_the_least_version_is_too_old() -> None:
    below = (LEAST_VERSION[0], LEAST_VERSION[1] - 1, 99)

    assert missing(at(below)) == [OLD.format(found=text_of(below))]


def test_versions_are_compared_as_numbers_not_as_text() -> None:
    # As text, "3.9.0" comes after "3.45.0".
    assert missing(at((3, 9, 0))) == [OLD.format(found="3.9.0")]


@pytest.mark.parametrize("feature", FEATURES, ids=lambda feature: feature.name)
def test_a_feature_whose_last_statement_is_refused_is_missing(feature: Feature) -> None:
    connect = lesser(version=text_of(LEAST_VERSION), refuses=(feature.accepted[-1],))

    assert missing(connect) == [f"this SQLite has no {feature.name}"]


@pytest.mark.parametrize("feature", FEATURES, ids=lambda feature: feature.name)
def test_a_feature_whose_first_statement_is_refused_is_missing(feature: Feature) -> None:
    connect = lesser(version=text_of(LEAST_VERSION), refuses=(feature.accepted[0],))

    assert missing(connect) == [f"this SQLite has no {feature.name}"]


# What a build without each feature refuses, whatever the rest of the statement is.
BUILDS_WITHOUT = {
    "tables with strict column types": ") STRICT",
    "statements that return the rows they wrote (RETURNING)": " RETURNING ",
    "JSON functions": "json_extract(",
    "R*Tree indexes (for finding places inside a part of the map)": " USING rtree ",
    "full-text search (FTS5)": " USING fts5 ",
}


@pytest.mark.parametrize(("name", "words"), BUILDS_WITHOUT.items(), ids=BUILDS_WITHOUT)
def test_a_build_without_a_feature_is_found_out_by_what_it_refuses(name: str, words: str) -> None:
    connect = lesser(version=text_of(LEAST_VERSION), refuses=(words,))

    assert missing(connect) == [f"this SQLite has no {name}"]


def test_foreign_keys_that_are_not_enforced_are_missing() -> None:
    # A build without foreign keys accepts the setting and does nothing.
    connect = lesser(version=text_of(LEAST_VERSION), drops=("PRAGMA foreign_keys = ON",))

    assert missing(connect) == ["this SQLite has no foreign keys that are enforced"]


def test_strict_tables_that_take_any_value_are_missing() -> None:
    connect = lesser(version=text_of(LEAST_VERSION), drops=(" STRICT",))

    assert missing(connect) == ["this SQLite has no tables with strict column types"]


def test_everything_that_is_lacking_is_named_the_version_first() -> None:
    connect = lesser(version="3.31.1", refuses=("USING rtree", "USING fts5"))

    assert missing(connect) == [
        OLD.format(found="3.31.1"),
        "this SQLite has no R*Tree indexes (for finding places inside a part of the map)",
        "this SQLite has no full-text search (FTS5)",
    ]


def test_every_feature_is_tried_in_a_database_of_its_own_and_each_is_closed() -> None:
    opened: list[sqlite3.Connection] = []

    def connect() -> sqlite3.Connection:
        opened.append(at(LEAST_VERSION)())
        return opened[-1]

    assert missing(connect) == []

    # One for the version and one for each feature.
    assert len(opened) == 1 + len(FEATURES)
    for connection in opened:
        with pytest.raises(sqlite3.ProgrammingError, match="closed"):
            connection.execute("SELECT 1")


def test_a_feature_cannot_lean_on_a_table_another_one_made() -> None:
    # Each feature's statements work in an empty database: none uses a name twice.
    for feature in FEATURES:
        connection = sqlite3.connect(":memory:", isolation_level=None)
        try:
            for statement in feature.accepted:
                connection.execute(statement)
        finally:
            connection.close()


def test_the_store_relies_on_these_six_features() -> None:
    assert [feature.name for feature in FEATURES] == [
        "foreign keys that are enforced",
        "tables with strict column types",
        "statements that return the rows they wrote (RETURNING)",
        "JSON functions",
        "R*Tree indexes (for finding places inside a part of the map)",
        "full-text search (FTS5)",
    ]


def test_the_features_that_must_refuse_something_say_what() -> None:
    assert {feature.name: feature.refused for feature in FEATURES if feature.refused} == {
        "foreign keys that are enforced": "INSERT INTO child (parent_id) VALUES (1)",
        "tables with strict column types": (
            "INSERT INTO strict_types (number) VALUES ('not a number')"
        ),
    }


def test_the_least_version_is_the_one_the_decision_record_gives() -> None:
    record = (REPOSITORY / "DATABASE.md").read_text(encoding="utf-8")

    assert f"**SQLite {text_of(LEAST_VERSION)} or newer**" in record
    assert record.count(" or newer**") == 1


def test_the_decision_record_names_every_feature_the_store_relies_on() -> None:
    record = (REPOSITORY / "DATABASE.md").read_text(encoding="utf-8")

    for feature in FEATURES:
        assert f"| {feature.name} |" in record, feature.name
```

+## Where the store is kept between runs
+
+A run of the pipeline on GitHub starts on an empty machine, so the store
+must be kept somewhere that lasts.
+
+**Decision:** after a run the store is written out as text files that are
+the same, byte for byte, whenever the store is the same, and those files
+are committed to a branch of this repository named `data`. The next run
+rebuilds the SQLite file from them.
+
+| Way | For | Against | Verdict |
+|---|---|---|---|
+| Text files in a `data` branch | Every change to the data is a readable difference with a date, kept for good. Nothing outside the repository is needed. The rebuild is proven by a round-trip test (DAT-020). | The repository grows with every change, and files and repositories have size limits (below). | Chosen |
+| The database file as a release asset | One file of up to 2 GiB, and no limit on the total. | The file is binary: there is no readable history and no way to see what a run changed. Each run replaces it, so an earlier state is gone unless every one is kept. | In reserve, for size |
+| A workflow cache | Fast. | GitHub removes an entry that was not read for 7 days, and the oldest entries when the repository's 10 GB are used up. It is not a place to keep anything. | Rejected |
+| A workflow artifact | Simple. | It belongs to one run, and goes when that run is deleted or its artifacts expire. | Rejected |
+
+GitHub's limits, as its documentation gave them on 2026-11-19:
+
+| What | Limit | Read from |
+|---|---|---|
+| One file in a repository | A warning above 50 MiB; refused above 100 MiB | <https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github> |
+| A repository | "ideally less than 1 GB, and less than 5 GB is strongly recommended" | the same page |
+| A published Pages site | No larger than 1 GB; a soft limit of 100 GB of traffic a month; a deployment is stopped after 10 minutes | <https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits> |
+| A release asset | Under 2 GiB each, at most 1,000 in a release, no limit on the total | <https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases> |
+| Workflow caches | 10 GB for a repository; an entry not read for 7 days is removed | <https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching> |
+
+How the decision is kept within those limits:
+
+- No file of a snapshot is larger than 25 MiB, half of the size GitHub
+  warns about. Large tables are divided into several files by a rule that
+  depends only on the data (DAT-019).
+- The command that writes a snapshot reports its size (DAT-019). When one
+  snapshot passes 250 MB, or the repository with its history 1 GB, the
+  decision is looked at again before more is added. The tables that grow
+  fastest, the race results, would move to release assets first.
+- The published site has a budget of 500 MB, half of the limit, and the
+  export's own check holds it (PUB-007).

## Acceptance criteria

1. `missing()` returns an empty list for the SQLite of GitHub's Linux
   machine, of GitHub's Windows machine and of your own.
2. An SQLite older than 3.45.0 is reported with its version and the least
   version, compared as numbers; 3.45.0 itself is not.

   foreign keys and strict tables also when the build accepts the
   statements and enforces nothing.

   one is closed, and no file is written.

   names, and a test fails when the two differ.
