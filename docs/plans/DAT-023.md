## Objective

A file that is not a MotoSphere data store is never migrated: it is
refused in plain words and left as it is.

## Why

The store is the file `MOTOSPHERE_STORE_PATH` names, and `open_store` opens
any SQLite database. Until now `migrate` went by the file's version alone
(`user_version`), and nearly every SQLite database in the world has 0
there. So with a wrong path, `migrate` would take the database of another
program for a new store and build MotoSphere's tables into it. The next
task gives `migrate` its command (DAT-024), and from DAT-006 on there are
tables to build. The check comes first.

This is the second fifth of the old "DAT-004 – Schema migrations"
(PLAN-014, in `PROGRESS.md`).

## Design in short

- **A store's file carries a mark.** SQLite gives every database a field
  in which an application says whose the file is (`application_id`, four
  bytes of the file's header). MotoSphere's is `APPLICATION_ID`,
  `0x4D6F5370`: the letters "MoSp", the number 1299141488. It is none of
  the marks SQLite's own list knows (`magic.txt` in its source, read on
  2026-11-19: Fossil, GeoPackage, MBTiles and a few others).
- **`migrate` looks at the file before anything else**, in one new private
  function, `_why_not_ours`:
  - a file with MotoSphere's mark is a store of MotoSphere's;
  - a file with the mark of another application is not;
  - a file with no mark is a new store if it has nothing in it (no table,
    view or anything else in `sqlite_master`, and version 0), and
    otherwise it is not.
- **A file that is not MotoSphere's is refused before anything is
  written**, with `SchemaError` and one sentence that names the file and
  says why. It is left byte for byte as it was.
- **The mark is written in the transaction of the first migration.** A new
  file has the mark and its first version together, or neither: a first
  migration that fails leaves the file new. The line that writes the mark
  stands in every migration's transaction; for a store that carries the
  mark already it changes nothing, and so no migration is a special case.
- **A new store that lacks no migration is not written to**, as before.
  The list of migrations is still empty, so today `migrate(store)` leaves
  a new file unmarked and empty, and the file is still a new store the
  next time.
- **The mark is looked at before the version.** A file of another program
  whose version happens to be high is told that it is not MotoSphere's,
  not that it is newer than the code.
- `open_store` does not change: it opens any SQLite database, and reading
  one harms nothing. `schema_version` does not change either. The command
  that says which schema a store has (DAT-025) decides what it says about
  a file that is not MotoSphere's.
- No new package.
