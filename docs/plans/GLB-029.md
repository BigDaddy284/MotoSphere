## Objective

The `Globe` component tells whoever shows it, once, when its engine
has drawn the first complete picture, proven by unit tests with the
stand-in for the engine.

## Why

The engine needs a moment after it is started: it fetches the pictures
of the Earth and draws them piece by piece. Two things have to know
when the first complete picture is there. The browser tests of the
globe (GLB-002, GLB-003) must not look at the page or read a pixel
before it, and a person is to be told that the globe is loading until
then and not after (GLB-004). Only the engine knows the moment, so the
engine has to be able to say it, and the component has to pass it on
to whoever shows the globe: once, and never for a globe that has gone.
This task gives the component that, before the real engine is in the
page (GLB-002), where each of these cases would be slow and hard to
bring about in a browser test.

## What this task is, and what it is not

- **It is** a listener that an engine is handed when it is started, a
  property of the component for whom to tell (`onDrawn`), the same in
  the stand-in of the unit tests, and their tests.
- **It is not** in the page. Nothing shows the component yet, so
  nothing a user sees changes, and the task has no browser tests.
- **It is not** the real engine, and not what "complete" means for it:
  that is GLB-002, which says it to the listener of this task.
- **It is not** what a person sees while the globe loads (GLB-004).
- **It is not** an engine that says that it failed while drawing. The
  listener has one thing to be told so far; GLB-004 adds to it.

## Design in short

    /** What an engine that is started is handed, to say what it has to say. */
    export type Listener = {
      /** Said when the engine has drawn its first complete picture. */
      drawn: () => void
    }

    export type Start = (surface: HTMLElement, listener: Listener) => Stop

In the component, `onDrawn` is a property that may be left out, read
through `useEffectEvent` like the other two:

    const drawn = useEffectEvent(() => {
      onDrawn?.()
    })

    useEffect(() => {
      const element = surface.current
      let shown = true
      let toldItIsDrawn = false
      let stop: Stop | undefined
      const listener: Listener = {
        drawn: () => {
          if (shown && !toldItIsDrawn) {
            toldItIsDrawn = true
            drawn()
          }
        },
      }
      ...
            stop = start(element, listener)

The stand-in keeps whom each engine was handed, and a test has an
engine say it with `draws()`: the engine started first, or the one
named.

## What the trial settled

- **The listener is an object with one thing to say**, not a bare
  function: GLB-004 will have the engine say a second thing, that it
  failed while drawing, and can add it without changing how an engine
  is started.
- **An engine must be handed a listener; whoever shows the globe need
  not ask.** `Start` takes the listener as a second argument that
  cannot be left out, so the real engine (GLB-002) can say it without
  asking whether anyone listens. `onDrawn` can be left out, so the 27
  tests of the component that were there stay as they are, word for
  word.
- **Told once.** The component notes that it has told. An engine that
  says it again, as a real one might after every new complete picture,
  tells nobody a second time.
- **Never for a globe that has gone.** The effect notes that the globe
  has gone, as it does for a late engine and a late failure (GLB-027).
  A test stops the engine by taking the globe away and then has the
  engine say it: nobody is told.
- **The listener the globe has now is told**, through
  `useEffectEvent`: another listener handed in later loads and starts
  nothing anew, and is the one told, also when it was handed in only
  after the engine was started. The lint passes with the empty list of
  what the effect depends on.
- **Each showing has its own note.** The note is made in the effect,
  not kept in the component: a globe that is shown again after it has
  gone is told of its new engine, and of two globes each is told of
  its own. React can also put a component aside and show it again
  later with everything it kept (`Activity`): the globe has gone for
  that time, its engine is stopped, and when it is shown again a new
  engine is started in the same element and whoever shows the globe
  is told a second time. Planted defects that keep one note for all
  globes, or keep it in the component across showings, are found; the
  second was not found by the first tests of the trial, and the test
  with `Activity` was written for it.
- **A listener that fails is not a failure of the engine.** What
  `onDrawn` fails with goes back to the engine that said it, as a
  defect of whoever shows the globe, and is not handed to `onFailed`;
  the engine goes on running. The note was made before, so the
  listener is not told a second time.
- **The component still keeps no state** and asks React for nothing
  after it is shown, so the new tests need no waiting on React's work,
  and the set-up of the unit tests (FND-056) holds every one of them to
  ending with none waiting.
- **The stand-in says it at once**, before `draws()` comes back, so a
  test can look at once at what the component did with it; it says it
  as often as the test has it, and for an engine that was stopped too,
  because that is what a test of "never for a globe that has gone"
  needs. What it remembers of an engine (`engines()`) is as it was:
  whom an engine says it to is kept beside that, so the tests that
  compare what it remembers stay as they are.

Only in `frontend/src/test/engine.test.ts`, and none loses an
assertion: where its tests start an engine themselves they now hand it

started without one any more. That is ten calls in six tests. No test
of `Globe.test.tsx` changes; its line that brings in from `react` now
names `Activity` too, for one of the new tests.

## Acceptance criteria

1. An engine is started with a listener, and the component can be
   handed whom to tell that the picture is drawn; it can also be shown
   without.
2. When the engine says that its first complete picture is drawn,
   whoever shows the globe is told once, with nothing else, and the
   engine goes on running. Nobody is told before the engine says it.
3. An engine that says it again tells nobody a second time.
4. Nobody is told what an engine says after its globe has gone.
5. The listener the globe has then is the one told. Another listener
   handed in later neither loads nor starts nor stops anything.
6. Of two globes each is told of its own engine only, and a globe that
   is shown again after it has gone is told of its new engine only. A
   globe that React put aside and shows again is told a second time,
   of its new engine. Under `StrictMode` it is told once, of the one
   engine that runs.
7. Nobody is told that a picture is drawn when the engine cannot be
   loaded or started. A listener that fails is not told to `onFailed`;
   what it fails with goes back to the engine, which goes on running.
8. The stand-in has an engine say it when a test says so, at once, for
   the engine started first or the one named, and names an engine that
