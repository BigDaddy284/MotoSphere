# FND-025 – Section navigation

**Phase:** 1 – Foundation
**Depends on:** FND-014 (merged)
**Base branch:** `main`

## Objective

The user can see the application's nine sections in the sections panel and
choose one, by mouse or by keyboard. Exactly one section is current; it is
Explore when the application starts.

The chosen section is application state held in `App`. Later tasks use it to
decide what the panels and the globe show. In this task choosing a section
changes only which item is marked current: nothing else on the screen reacts
yet, on purpose.

### 3. `frontend/src/navigation/SectionList.tsx`

Exactly this content:

```tsx
import styles from './SectionList.module.css'
import { SECTIONS, type SectionId } from './sections.ts'

interface SectionListProps {
  /** The section the user is in. */
  current: SectionId
  /** Called with the section the user chose. */
  onSelect: (section: SectionId) => void
}

/** The list of sections. Exactly one is marked as the current one. */
export function SectionList({ current, onSelect }: SectionListProps) {
  return (
    <ul className={styles.list}>
      {SECTIONS.map(({ id, label }) => (
        <li key={id}>
          <button
            type="button"
            className={styles.item}
            aria-current={id === current ? 'page' : undefined}
            onClick={() => onSelect(id)}
          >
            {label}
          </button>
        </li>
      ))}
    </ul>
  )
}
```

Each section is a real `button`, so the browser gives Tab, Enter and Space
for free. `aria-current="page"` marks the current one and is also what the
style sheet selects on, so the mark and the look cannot drift apart.

```css
.item {

    color var(--duration-fast) var(--easing-standard);
}

.item:hover {
  background-color: var(--color-control);
  color: var(--color-text);
}

.item:active {
  background-color: var(--color-pressed);
}

.item:focus-visible {
  outline-offset: -2px;
}

.item[aria-current='page'] {
  border-left-color: var(--color-accent-sky);
  background-color: var(--color-selection);
  color: var(--color-text);

```

Notes: the focus ring is drawn inside the item (`outline-offset: -2px`)
because the panel scrolls its own overflow and would clip a ring drawn
outside. The rule for the current item comes last so that it wins over the
hover rule.

### 5. `frontend/src/layout/AppShell.tsx`

Add a `sections` prop and render it inside the navigation landmark. The
result is exactly:

```tsx
import type { ReactNode } from 'react'
import styles from './AppShell.module.css'

interface AppShellProps {
  /** The application name, shown as the page's main heading. */
  name: string
  /** One line under the name. */
  tagline: string
  /** What the sections panel shows. */
  sections: ReactNode
}

/**
 * The fixed regions of the screen: a top bar, the sections panel on the left,
 * the globe stage in the centre and the details panel on the right. The stage
 * always gets the largest share of the screen.
 */
export function AppShell({ name, tagline, sections }: AppShellProps) {
  return (
    <div className={styles.shell}>
      <header className={styles.topBar}>
        <h1 className={styles.name}>{name}</h1>
        <p className={styles.tagline}>{tagline}</p>
      </header>
      <nav className={styles.sections} aria-label="Sections">
        {sections}
      </nav>
      <main className={styles.stage} aria-label="Globe" />
      <aside className={styles.details} aria-label="Details">
        <p className={styles.hint}>Select something on the globe to see its details here.</p>
      </aside>
    </div>
  )
}
```

### 6. `frontend/src/App.tsx`

Exactly this content:

```tsx
import { useState } from 'react'
import { AppShell } from './layout/AppShell.tsx'
import { SectionList } from './navigation/SectionList.tsx'
import { DEFAULT_SECTION, type SectionId } from './navigation/sections.ts'

export const APP_NAME = 'MotoSphere'
export const APP_TAGLINE = 'The World of Motocross, Connected.'

export function App() {
  const [section, setSection] = useState<SectionId>(DEFAULT_SECTION)

  return (
    <AppShell
      name={APP_NAME}
      tagline={APP_TAGLINE}
      sections={<SectionList current={section} onSelect={setSection} />}
    />
  )
}
```

Import `test` and `expect` from `./fixtures`. Find a section with

"Only X is current" means: the elements with `aria-current` inside the panel

In a group named `section navigation`:

1. `lists the nine sections and starts in Explore` – the buttons in the

2. `moves to the section that is clicked and shows it in the selection style`

3. `can be used with the keyboard alone, with a visible focus ring` –
   **first wait for the Explore button to be visible**, then press Tab:
   Explore is focused with outline style `solid`, width `2px` and colour
   `rgb(94, 168, 255)`. Tab: Events is focused; Enter: only Events is
   current. Tab: Tracks is focused; Space: only Tracks is current.
4. `shows a hover style on a section that is not current` – hover Riders:
   background `rgb(53, 55, 60)`, colour `rgb(236, 236, 238)`; only Explore
   is still current.
5. In a nested group `at 1366×768` (`test.use({ viewport })`):
   `fits every section in the panel without scrolling` – for the panel,
   `scrollWidth - clientWidth` and `scrollHeight - clientHeight` are both 0,
   and each of the nine buttons is fully in the viewport
   (`toBeInViewport({ ratio: 1 })`).

About the wait in test 3: `page.goto` can return before React has drawn the
list, and a key pressed then is lost. Without the wait the planner saw this
test fail now and then in full runs, and every time when rendering was
delayed by 400 ms. With the wait it passed in every run, including with the
delay. Use web-first assertions (`await expect(locator)…`) throughout; no
fixed sleeps.
