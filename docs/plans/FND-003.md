# FND-003 – Backend linting and formatting

**Phase:** 1 – Foundation
**Depends on:** FND-002 (merged)
**Base branch:** `main`

## Objective

Make code style, common bug patterns and basic security rules an automatic,
mandatory gate for backend Python, using ruff for both linting and formatting.

## Scope

| `backend/uv.lock` | Regenerated by uv |

| `TESTING.md` | Gates table: add "Backend lint" and "Backend format" rows |
| `CHANGELOG.md` | One bullet under Unreleased → Added |

Existing Python files under `backend/` may be changed **only** if ruff
requires it, and then only by the minimum needed. The planner's trial run

## Implementation detail

### 1. Dependency

Add to the `dev` group in `backend/pyproject.toml`, keeping the list sorted:

```toml
[dependency-groups]
dev = [
    "pytest>=8.3",
    "ruff>=0.9",
]
```

Then run `uv lock` in `backend/`. The lock file pins the exact ruff version,
which keeps formatting output identical for everyone.

### 2. Configuration

Append to `backend/pyproject.toml`:

```toml
[tool.ruff]
line-length = 100
target-version = "py312"
src = ["src", "tests"]

[tool.ruff.lint]
select = [
    "E",    # pycodestyle errors
    "W",    # pycodestyle warnings
    "F",    # pyflakes
    "I",    # import sorting
    "N",    # naming
    "UP",   # modern Python syntax
    "B",    # likely bugs
    "C4",   # comprehensions
    "SIM",  # simplifications
    "PTH",  # pathlib over os.path
    "DTZ",  # timezone-aware datetimes
    "T20",  # no print statements
    "PT",   # pytest style
    "RET",  # return statements
    "S",    # security (bandit)
    "RUF",  # ruff-specific rules
]

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101"]  # assert is how pytest tests are written
```

Rules:

- Keep exactly this rule selection. Do not add a global `ignore` list and do
  not add `# noqa` comments. If a selected rule fires on existing code, fix
  the code. If you believe a rule is wrong for this project, stop and report
  it rather than disabling it.
- Formatter settings stay at ruff defaults (double quotes, spaces), so there
  is no `[tool.ruff.format]` section.

### 3. Documentation

- `README.md`, "Running the checks": after the backend unit test commands,
  add the lint and format commands, run from `backend/`:

  ```
  uv run ruff check .
  uv run ruff format --check .
  ```

  and one sentence that `uv run ruff format .` applies the formatting.
- `TESTING.md`, Gates table: add
  `Backend lint` → `cd backend && uv run ruff check .` and
  `Backend format` → `cd backend && uv run ruff format --check .`.
- `CHANGELOG.md`: one bullet, for example "Backend linting and formatting
  with ruff, including security rules (FND-003)."

## Acceptance criteria

1. `uv run ruff check .` passes in `backend/` with exactly the rule set above.
2. `uv run ruff format --check .` passes in `backend/`.
3. Both gates fail on a deliberate violation (see "Verification").
4. `uv lock --check` passes; backend tests (4) and repository checks (9) still
   pass.
5. README, TESTING.md and CHANGELOG.md describe the new gates.
6. No `# noqa`, no global ignores, no files outside "Scope" touched.

## Verification

From a clean state (delete `backend/.venv` first if it exists):

```
cd backend
uv lock --check
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run pytest -v
cd ..
python -m unittest discover -s tests/repo -v
git status --short
```

Expected: lock check passes; `All checks passed!`; `N files already
formatted` with nothing to reformat; `4 passed`; `Ran 9 tests` / `OK`; clean
status once committed.

Then prove each gate can fail (do not commit these changes). Create a
temporary file `backend/src/motosphere/_lint_probe.py` containing:

```python
import os
import subprocess
x = {  "a":1 }
subprocess.run("echo hi", shell=True)
```

1. `uv run ruff check .` must exit non-zero and report at least an unused
   import (`F401`) and the shell call (`S602`). Record the rule codes shown.
2. `uv run ruff format --check .` must exit non-zero and name the file.

Delete the probe file and confirm both gates pass again and `git status` is
clean.
