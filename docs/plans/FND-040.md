## Objective

On a narrow screen the page opens with the globe in view, and a panel covers
it only when the user asks for it.

## Why

Since FND-038 an open side panel lies over the globe stage on a narrow
screen, and since FND-039 both buttons are in reach there. But both panels
still start open, as on a desktop: on a phone the page opens with the stage
covered completely, and the visitor has to close two panels to see what the
application is about. This is the third of five small tasks (PLAN-009), and
the one after which the published site is usable on a phone.

## Design in short

- **Wide screen (900 pixels and more): nothing changes.** Each panel starts
  open, its button closes and opens it, and the choice is remembered for the
  session (`usePanelOpen`, unchanged).
- **Narrow screen (under 900 pixels):** both panels start closed, whatever
  the session remembers. A button opens its panel and closes it again.
  Opening one panel closes the other, so at most one is open. Nothing is
  remembered and nothing is written to the session's memory: loading the
  page again shows the globe.
- **Across the line** (a tablet is turned, a window is resized): the page
  follows at once, without loading again. What was chosen on the wide
  screen is untouched by anything done on the narrow one, and is there
  again when the screen is wide again.
- The script learns whether the screen is narrow from the browser
  (`window.matchMedia`), with the same question the style sheet asks. That
  question is written in one new module, `narrowScreen.ts`, and a unit test
  reads the style sheet and fails when the two differ.
- A new hook, `useSidePanels`, holds the two behaviours; `AppShell.tsx`
  asks it instead of calling `usePanelOpen` twice. Nothing else in the
  component changes: the same elements, in the same order, with the same
  attributes.
- The unit tests' environment has no screen. A small stand-in
  (`src/test/screen.ts`) answers `window.matchMedia` from a width the test
  sets; every unit test starts with a wide screen, so every existing unit
  test runs as before.

## Implementation detail

### 1. `frontend/src/layout/narrowScreen.ts` – new, the whole file

```ts
import { useSyncExternalStore } from 'react'

/**
 * A screen too narrow for the side panels to stand beside the globe stage: a
 * phone, or a tablet held upright. The layout's style sheet draws the same
 * line, in the same words.
 */
export const NARROW_SCREEN = '(max-width: 899px)'

function subscribe(onChange: () => void): () => void {
  const query = window.matchMedia(NARROW_SCREEN)
  query.addEventListener('change', onChange)
  return () => {
    query.removeEventListener('change', onChange)
  }
}

function isNarrow(): boolean {
  return window.matchMedia(NARROW_SCREEN).matches
}

/** Whether the screen is a narrow one, now and whenever its width changes. */
export function useNarrowScreen(): boolean {
  return useSyncExternalStore(subscribe, isNarrow)
}
```

`useSyncExternalStore` is React's own way to follow something outside
React: the page is drawn again when the answer changes, and the watcher is
removed when nothing on the page asks any more.

### 2. `frontend/src/layout/useSidePanels.ts` – new, the whole file

```ts
import { useState } from 'react'
import { useNarrowScreen } from './narrowScreen.ts'
import { type PanelName, usePanelOpen } from './usePanelOpen.ts'

interface SidePanel {
  open: boolean
  /** Closes the panel when it is open, and opens it when it is closed. */
  toggle: () => void
}

/**
 * The two side panels: whether each is open, and how to close or open it.
 *
 * On a wide screen the panels stand beside the globe stage. Each starts open
 * and has its own choice, remembered for the session.
 *
 * On a narrow screen an open panel covers the stage. Both start closed, so
 * that the page opens with the globe in view; at most one is open; and
 * nothing is remembered, so loading the page again shows the globe.
 */
export function useSidePanels(): Record<PanelName, SidePanel> {
  const narrow = useNarrowScreen()
  const [sectionsOpen, toggleSections] = usePanelOpen('sections')
  const [detailsOpen, toggleDetails] = usePanelOpen('details')
  const [openOnNarrow, setOpenOnNarrow] = useState<PanelName | null>(null)

  if (!narrow) {
    return {
      sections: { open: sectionsOpen, toggle: toggleSections },
      details: { open: detailsOpen, toggle: toggleDetails },
    }
  }

  function onNarrow(name: PanelName): SidePanel {
    const open = openOnNarrow === name
    return {
      open,
      toggle: () => {
        setOpenOnNarrow(open ? null : name)
      },
    }
  }
  return { sections: onNarrow('sections'), details: onNarrow('details') }
}
```

Both kinds of state are always kept (hooks may not be called
conditionally); the screen decides which one is shown. That is also what
keeps the wide screen's choice untouched while the screen is narrow.

### 3. `frontend/src/layout/AppShell.tsx` – the whole file

```tsx
import type { ReactNode } from 'react'
import styles from './AppShell.module.css'
import { useSidePanels } from './useSidePanels.ts'

const SECTIONS_PANEL_ID = 'sections-panel'
const DETAILS_PANEL_ID = 'details-panel'

interface AppShellProps {
  /** The application name, shown as the page's main heading. */
  name: string
  /** One line under the name. */
  tagline: string
  /** Short information shown at the end of the top bar, such as the date. */
  info: ReactNode
  /** What the sections panel shows. */
  sections: ReactNode
}

/**
 * The fixed regions of the screen: a top bar, the sections panel on the left,
 * the globe stage in the centre and the details panel on the right. The stage
 * always gets the largest share of the screen, and takes the room of a side
 * panel that the user closes with its button in the top bar. On a narrow
 * screen the stage has the whole width, and an open panel lies over it.
 */
export function AppShell({ name, tagline, info, sections }: AppShellProps) {
  const { sections: sectionsPanel, details: detailsPanel } = useSidePanels()

  return (
    <div className={styles.shell}>
      <header className={styles.topBar}>
        <button
          type="button"
          className={styles.toggle}
          aria-expanded={sectionsPanel.open}
          aria-controls={SECTIONS_PANEL_ID}
          onClick={sectionsPanel.toggle}
        >
          Sections
        </button>
        <h1 className={styles.name}>{name}</h1>
        <p className={styles.tagline}>{tagline}</p>
        <div className={styles.info}>{info}</div>
        <button
          type="button"
          className={styles.toggle}
          aria-expanded={detailsPanel.open}
          aria-controls={DETAILS_PANEL_ID}
          onClick={detailsPanel.toggle}
        >
          Details
        </button>
      </header>
      <nav
        id={SECTIONS_PANEL_ID}
        className={styles.sections}
        aria-label="Sections"
        hidden={!sectionsPanel.open}
      >
        {sections}
      </nav>
      <main className={styles.stage} aria-label="Globe" />
      <aside
        id={DETAILS_PANEL_ID}
        className={styles.details}
        aria-label="Details"
        hidden={!detailsPanel.open}
      >
        <p className={styles.hint}>Select something on the globe to see its details here.</p>
      </aside>
    </div>
  )
}
```

### 4. `frontend/src/test/screen.ts` – new, the whole file

```ts
import { act } from '@testing-library/react'

/** The width of the screen the tests start with: a wide one. */
export const WIDE_SCREEN = 1366

// The only kind of question about the screen the application asks.
const MAX_WIDTH = /^\(max-width: (\d+)px\)$/

type Listener = () => void

let width = WIDE_SCREEN
const listeners = new Set<Listener>()

/**
 * A stand-in for the part of the browser that knows how wide the screen is,
 * which the test environment does not have. It answers from the width the
 * test has set, and refuses a question it does not understand.
 */
function matchMedia(query: string): MediaQueryList {
  const limit = MAX_WIDTH.exec(query)?.[1]
  if (limit === undefined) {
    throw new Error(`The stand-in screen does not understand the question ${query}`)
  }
  const answer = {
    media: query,
    get matches() {
      return width <= Number(limit)
    },
    addEventListener(_type: string, listener: Listener) {
      listeners.add(listener)
    },
    removeEventListener(_type: string, listener: Listener) {
      listeners.delete(listener)
    },
  }
  return answer as MediaQueryList
}

/** Puts the stand-in in place, with a wide screen that nothing is watching. */
export function installScreen(): void {
  width = WIDE_SCREEN
  listeners.clear()
  window.matchMedia = matchMedia
}

/** Changes the width of the screen, in pixels, and tells whoever is watching. */
export function showScreen(pixels: number): void {
  act(() => {
    width = pixels
    for (const listener of listeners) {
      listener()
    }
  })
}

/** How many parts of the page are watching the width of the screen. */
export function screenWatchers(): number {
  return listeners.size
}
```
