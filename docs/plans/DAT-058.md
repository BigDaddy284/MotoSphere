## Objective

A source can be described as a keeper of reference lists, so that the
source of the countries is registered as what it is.

## Why

Every record in the store names the source it came from, and the
countries of the world come from the project iso-codes (DAT-012). A
source is described by one of twelve kinds (`SourceCategory`,
DESIGN.md §7.1), and each of the twelve is a kind of website of the
sport: a governing body, a championship, a track, a club and so on. A
project that keeps the lists of a standard is none of them.
"Distinguish official information from independently published
information." (CLAUDE.md §11): a source that is put under a kind that
does not fit says something of itself that is not so. `DATA_SOURCES.md`
has left the category of iso-codes open for that reason, and the source
cannot be registered in the store before it has one (DAT-059).

## What this task is, and what it is not

- **It is** one more text in the list `SourceCategory`,
  `reference list`, the fifteenth migration that lets the table
  `source` take it, and their tests.
- **It is** the category of iso-codes in `DATA_SOURCES.md`, where it
  was left open.
- **It is not** a source in the store. Registering iso-codes and
  loading the countries is DAT-059.
- **It is not** a change to DESIGN.md. The design's twelve stay the
  design's; the thirteenth is this project's own, and `DATABASE.md`
  and `DATA_SOURCES.md` say so.
- **It is not** a change to any source that is in a store: every
  source keeps all it had.

## What the task left open, and what the trial settled

- **The text.** `reference list`. Like the twelve it says who
  publishes: whoever keeps a list that other records are described by.
  It is not `reference data`, which is a text of another list, that of
  the kinds of information (`InformationType.REFERENCE`): a source of
  the kind `reference list` offers `reference data`. Two lists with
  one text for two things would be read as one.
- **Its name in the code.** `SourceCategory.REFERENCE`.
- **Its place.** Last. The twelve keep the order of the design, and
  the one that is this project's own follows them. A test holds the
  place, and that the twelfth is still `historical archive`.
- **A change in place, or the table built anew?** Built anew. The
  check of the column `category` names the texts it takes
  (`ck_source_category_one_of`), and SQLite cannot change a check of a
  table that is there. The fifteenth migration does what the
  fourteenth did (DAT-057), statement for statement: it asks SQLite to
  check the foreign keys only when the transaction ends, copies the
  rows aside, reads the highest key the table has given, drops the
  table, makes it again, fills it from the copy, puts the highest key
  back and drops the two copies.
- **What differs from the fourteenth.** Three things. The check names
  thirteen texts. The statement that fills the table copies
  `country_id` too, so a source keeps its country. And the index
  `ix_source_country_id` is there before the migration: it goes with
  the table when that is dropped, and the migration makes it again as
  its last statement.
- **The migration writes the table out once more**, whole, with its
  own copy of what the checks need (`white_space`, `not_empty`,
  `web_address`). That is the rule of the history
  (`history.py`, at its top): a migration names nothing of the
  store's code and nothing of another migration, so that it builds
  tomorrow what it builds today.
- **Nothing else of the table changes.** The trial reads how SQLite
  holds every table and index (`sqlite_master`) before and after: only
  `source` is written otherwise, and only in the one text more. The
  test does that on every run.
- **The four tables that point to a source** (`source_offer`,
  `collection_run`, `review_item`, `country`) are not touched. Their
  rows point to the same sources afterwards, and
  `PRAGMA foreign_key_check` finds nothing.
- **A text that is nearly the new one is refused**, as every text that
  is not of the list is: with a capital, with white space after it,
  with two spaces in it, in the plural, the first word alone, and
  `reference data`.
- **It is all or nothing.** A table of the name of either copy fails
  the migration at its second or third statement. To make it fail at
  its last statement, after the table was dropped, made anew and
  filled, the test puts a table of the index's name where the index
  was (it drops the index first): SQLite then refuses to make the
  index (`there is already a table named ix_source_country_id`). In
  both cases the store is at version 14 afterwards, written as it was,
  with every row and the highest key as before, and a source of the
  new kind is still refused.
