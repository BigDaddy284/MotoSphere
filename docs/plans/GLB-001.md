# GLB-001 – The Cesium engine installed

**Phase:** 3 – Interactive 3D Earth
**Track:** B (see `TASKS.md`, "Two tracks")
**Depends on:** FND-046 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §9, §12, §14, `docs/WORKFLOW.md`, `TASKS.md`
("Two tracks" and Phase 3), `PROGRESS.md` (PLAN-033, PLAN-034, PLAN-035),
`ARCHITECTURE.md` §3 and §8, `TESTING.md` ("The tools a computer needs"),
`tests/repo/test_node_version.py`, `frontend/package.json`

## Objective

The front end has the Cesium engine as a locked dependency: the packages
`@cesium/engine` and `@cesium/core` are named, locked and installed, unit
tests use the engine as it is installed, and a repository check holds
which packages the site ships.

## Why

The 3D Earth is the defining feature (CLAUDE.md §9), and CesiumJS is the
engine decided for it (ARCHITECTURE.md §3). Every later task of the globe
needs the engine installed. Installing it is a task of its own because a
package the site ships is code of someone else that every visitor runs:
which package, which version, what comes with it and what it asks of the
computer are settled here, with nothing of the application changed, so
that the next task can be about the Earth on the screen and nothing else.

## What this task is, and what it is not

- **It is** two packages named under `dependencies` in
  `frontend/package.json`, `"@cesium/core": "^0.1.1"` and
  `"@cesium/engine": "^26.5.0"`, and the lock file with the 28 packages
  they bring.
- **It is** one new file of unit tests, `frontend/src/globe/engine.test.ts`
  (11 tests), which uses the engine as installed, and one new file of
  repository checks, `tests/repo/test_frontend_packages.py` (9 tests).
- **It is not** a globe. Nothing of the application imports the engine,
  and the build makes the same files as before, byte for byte.
- **It is not** the engine's own files in the site (its background
  scripts, pictures and tables): that is GLB-022.
- **It is not** a change of the least Node.js. The engine and two of its
  packages need Node.js 22.17 or newer; the project asks for 22.22.2
  since FND-046, and the check of FND-046 passes as it is.

## Design in short

- **The engine by itself.** `@cesium/engine` is CesiumJS without the
  ready-made viewer. The full package `cesium` (1.147.0) is the engine
  plus `@cesium/widgets`, a viewer with its own buttons, timeline and
  search box, which MotoSphere does not use: its controls are its own.
  No wrapper for React (`resium`) either (ARCHITECTURE.md §3).
- **The engine's arithmetic is a package of its own.** Since CesiumJS
  1.146 positions, angles and the shape of the Earth (`Cartesian3`,
  `Cartographic`, `Ellipsoid`, `Math` and about 150 names in all) live in
  `@cesium/core`. The engine still hands them out, but each one writes a
  warning on its first use ("… has been moved from cesium/engine to
  cesium/core in CesiumJS 1.146, and will be removed from cesium/engine
  in 1.150. Import from cesium/core instead."). So the application
  imports those names from `@cesium/core`, and a package the application
  imports is one the project names. The engine brings `@cesium/core`
  anyway, at the same range, so naming it adds one line to the lock file
  and no package.
- **One copy.** The engine and the application must use the same
  `@cesium/core`: with two copies, a position the application makes
  would not be one the engine knows as its own. A repository check holds
  that the lock file installs each shipped package once, at the top, and
  a unit test holds that the ellipsoid of the engine's globe is the very
  object the application gets.
- **The list of what the site ships is held.** The check names the four
  packages under `dependencies` and fails when the file names another,
  one fewer, or one in both groups. A later task that ships a package
  changes the list in the same pull request, where a reviewer sees it.

The unit tests (11):

- the reference ellipsoid WGS84 is the default, with its radii to the
  last digit (1);
- six places whose positions WGS84 gives exactly: four on the equator
  and the two poles (6);
- longitude first, latitude second (1); a height is in metres (1); the
  degrees and the height come back from a position (1);
- the engine's globe and its tiling scheme stand on the very ellipsoid
  the application gets from `@cesium/core` (1).

In every one of them a warning from the engine is an error, so a name
imported from the wrong package fails the test that uses it first.

The repository checks (9), in two classes:

- **Reading a lock file** (3), on made-up lock files: a package is known
  by its name wherever it is put, with every place it has; when a
  package counts as only for the work; a file without the group asked
  for is not gone by.
- **Shipped packages** (6), on the real files: the site ships these four
  and no other; no package is in both groups; the lock file names the
  same packages for the project; it installs one copy of each shipped
  package; it does not mark a shipped one as only for the work; the
  full package, the ready-made viewer and the wrapper are neither named
  nor installed, at any depth.

## What the task left open, and what the trial settled

- **Which version?** `@cesium/engine` 26.5.0, the newest release (it is
  the engine of CesiumJS 1.147), and `@cesium/core` 0.1.1, the newest
  and the one the engine asks for (`^0.1.1`). Both Apache 2.0.
- **What comes with it?** 28 packages, 201 in the lock file where there
  were 173. Their licences as the lock file gives them: MIT (12),
  Apache-2.0 (8), ISC (4), BSD-3-Clause (2), `(MPL-2.0 OR Apache-2.0)`
  (`dompurify`) and `(MIT AND Zlib)` (`pako`). All come from the npm
  registry. One package that was there before, `tslib`, is no longer
  marked as only for the work, because the engine's packages use it.
- **Does any package run a script at install?** No: none of the 28 has
  an install script. One, `topojson-client`, brings command-line
  programs, which nothing here runs.
- **Which Node.js?** `@cesium/engine`, `@cesium/core` and `@cesium/gltf`
  say `>=22.17.0`; the others less or nothing. The least Node.js stays
  22.22.2, and all 133 ranges of the lock file allow it.
- **Does the audit pass?** Yes: `python scripts/audit.py` reports no
  advisory for the new lock file.
- **Does the built site change?** No. Nothing imports the engine, so the
  build leaves it out: the six files the build makes are the same as on
  `main`, byte for byte.
- **Does the engine load in the unit tests' environment?** Yes. The
  whole engine imports under Vitest with jsdom in under two seconds, and
  `new Globe()` needs no screen. Drawing does need one and is for the
  browser tests of GLB-002.
- **How big is it?** 32 MB installed for the engine and 3 MB for its
  core. What reaches a visitor is decided by GLB-002 and GLB-022; the
  planner's prototype loaded the engine as a part of its own of 1.3 MB
  compressed, fetched only when the globe starts.

### 1. `tests/repo/test_frontend_packages.py` – new, the whole file, 9 tests

```python
"""Checks on which packages the frontend installs (GLB-001).

What the site ships to a visitor's browser is named under `dependencies`
in `frontend/package.json`; what only builds and tests it is named under
`devDependencies`. A package under `dependencies` is code of someone else
that every visitor runs, so adding one is a decision, and it is made here
and not in passing. The engine of the globe is the Cesium engine by
itself, `@cesium/engine`: not the full `cesium` package with its ready-made
viewer, and no wrapper around it (ARCHITECTURE.md, section 3). The engine
keeps its arithmetic in a package of its own, `@cesium/core`, and asks
that it be taken from there; so the project names that package too, and
there must be one copy of it for the engine and the application alike.

Standard library only, as all repository checks. Run from the repository
root:

    python -m unittest discover -s tests/repo -v
"""

import json
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
PACKAGE = ROOT / "frontend" / "package.json"
LOCK = ROOT / "frontend" / "package-lock.json"

ENGINE = "@cesium/engine"
# The packages the site ships. Adding one is a decision about whose code
# every visitor runs.
SHIPPED = ("@cesium/core", "@cesium/engine", "react", "react-dom")
# Decided against: the full package and the ready-made viewer, whose
# controls MotoSphere does not use, and wrappers that must follow every
# release of the engine.
NOT_INSTALLED = ("cesium", "@cesium/widgets", "resium")


class UnusableError(Exception):
    """A file of the project is not what these checks can go by."""


def group(document: dict[str, object], name: str) -> dict[str, object]:
    """One group of a package file or a lock file, such as `dependencies`."""
    found = document.get(name)
    if not isinstance(found, dict):
        raise UnusableError(f"there is no {name}")
    return found


def load(path: Path) -> dict[str, object]:
    loaded = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(loaded, dict):
        raise UnusableError(f"{path.name} is not a list of names and values")
    return loaded


def places(lock: dict[str, object]) -> dict[str, list[str]]:
    """Where a lock file installs each package, by the package's name.

    `node_modules/a/node_modules/@b/c` is a place of the package `@b/c`. A
    package with two places is installed twice, as two copies of its code.
    """
    found: dict[str, list[str]] = {}
    for where in group(lock, "packages"):
        if where != "":
            found.setdefault(where.rpartition("node_modules/")[2], []).append(where)
    return found


def only_for_the_work(package: object) -> bool:
    """Whether a lock file marks a package as one the site does not ship."""
    return isinstance(package, dict) and package.get("dev") is True


class ReadingALockFileTest(unittest.TestCase):
    def test_a_package_is_known_by_its_name_wherever_it_is_put(self) -> None:
        lock: dict[str, object] = {
            "packages": {
                "": {"name": "the project"},
                "node_modules/one": {"version": "1.0.0"},
                "node_modules/@two/three": {"version": "2.0.0"},
                "node_modules/one/node_modules/four": {"version": "4.0.0"},
                "node_modules/one/node_modules/@two/three": {"version": "2.1.0"},
            }
        }

        self.assertEqual(
            places(lock),
            {
                "one": ["node_modules/one"],
                "@two/three": [
                    "node_modules/@two/three",
                    "node_modules/one/node_modules/@two/three",
                ],
                "four": ["node_modules/one/node_modules/four"],
            },
        )

    def test_a_package_is_only_for_the_work_when_the_lock_file_says_so(self) -> None:
        self.assertTrue(only_for_the_work({"version": "1.0.0", "dev": True}))
        for package in ({"version": "1.0.0"}, {"dev": False}, {"dev": "true"}, None):
            with self.subTest(package=package):
                self.assertFalse(only_for_the_work(package))

    def test_a_file_without_the_group_asked_for_is_not_gone_by(self) -> None:
        unusable: tuple[dict[str, object], ...] = ({}, {"packages": []}, {"packages": "none"})
        for lock in unusable:
            with self.subTest(lock=lock), self.assertRaises(UnusableError):
                places(lock)


class ShippedPackagesTest(unittest.TestCase):
    def test_the_site_ships_these_packages_and_no_other(self) -> None:
        self.assertEqual(sorted(group(load(PACKAGE), "dependencies")), sorted(SHIPPED))

    def test_no_package_is_named_both_as_shipped_and_as_only_for_the_work(self) -> None:
        package = load(PACKAGE)
        both = set(group(package, "dependencies")) & set(group(package, "devDependencies"))

        self.assertEqual(both, set())

    def test_the_lock_file_names_the_same_packages_for_the_project(self) -> None:
        package = load(PACKAGE)
        project = group(group(load(LOCK), "packages"), "")

        for name in ("dependencies", "devDependencies"):
            with self.subTest(group=name):
                self.assertEqual(group(project, name), group(package, name))

    def test_the_lock_file_installs_one_copy_of_each_package_the_site_ships(self) -> None:
        # Two copies of the engine's arithmetic would be two kinds of every
        # position: one made by the application is then not one the engine
        # knows as its own.
        found = places(load(LOCK))

        for name in SHIPPED:
            with self.subTest(package=name):
                self.assertEqual(found.get(name), [f"node_modules/{name}"])

    def test_the_lock_file_installs_what_the_site_ships_as_shipped(self) -> None:
        packages = group(load(LOCK), "packages")

        for name in SHIPPED:
            with self.subTest(package=name):
                self.assertFalse(only_for_the_work(packages.get(f"node_modules/{name}")))

    def test_the_engine_of_the_globe_is_the_engine_by_itself(self) -> None:
        self.assertIn(ENGINE, SHIPPED)
        found = places(load(LOCK))
        package = load(PACKAGE)
        named = {*group(package, "dependencies"), *group(package, "devDependencies")}

        for name in NOT_INSTALLED:
            with self.subTest(package=name):
                self.assertNotIn(name, found)
                self.assertNotIn(name, named)


if __name__ == "__main__":
    unittest.main()
```

+import { Cartesian3, Cartographic, Ellipsoid, Math as EngineMath } from '@cesium/core'
+import { GeographicTilingScheme, Globe } from '@cesium/engine'
+import { beforeEach, describe, expect, it, vi } from 'vitest'

+// The engine of the globe is used here as it is installed, with nothing in
+// its place. It keeps its arithmetic (positions, angles, the shape of the
+// Earth) in a package of its own, `@cesium/core`, and asks that those names
+// be taken from there and no longer from the engine.
+//
+// The numbers are those of the reference ellipsoid WGS84, by which positions
+// on the Earth are given: 6378137 m from the centre to the equator and
+// 6356752.314245179 m to a pole.
+const TO_THE_EQUATOR = 6378137
+const TO_A_POLE = 6356752.314245179
+
+describe('the engine of the globe, as installed', () => {
+  // The engine writes a warning the first time a name is used that it wants
+  // taken from elsewhere. A test that brings one about fails.
+  beforeEach(() => {
+    vi.spyOn(console, 'warn').mockImplementation((...said: unknown[]) => {
+      throw new Error(`The engine warned: ${said.join(' ')}`)
+    })
+  })
+
+  it('goes by the reference ellipsoid WGS84', () => {
+    expect(Ellipsoid.default).toBe(Ellipsoid.WGS84)
+    expect(Ellipsoid.WGS84.radii.x).toBe(TO_THE_EQUATOR)
+    expect(Ellipsoid.WGS84.radii.y).toBe(TO_THE_EQUATOR)
+    expect(Ellipsoid.WGS84.radii.z).toBe(TO_A_POLE)
+  })
+
+  it.each([
+    {
+      where: 'where the equator meets the prime meridian',
+      at: [0, 0],
+      x: TO_THE_EQUATOR,
+      y: 0,
+      z: 0,
+    },
+    {
+      where: 'on the equator, a quarter of the way round to the east',
+      at: [90, 0],
+      x: 0,
+      y: TO_THE_EQUATOR,
+      z: 0,
+    },
+    {
+      where: 'on the equator, a quarter of the way round to the west',
+      at: [-90, 0],
+      x: 0,
+      y: -TO_THE_EQUATOR,
+      z: 0,
+    },
+    { where: 'on the equator, half the way round', at: [180, 0], x: -TO_THE_EQUATOR, y: 0, z: 0 },
+    { where: 'at the north pole', at: [0, 90], x: 0, y: 0, z: TO_A_POLE },
+    { where: 'at the south pole', at: [0, -90], x: 0, y: 0, z: -TO_A_POLE },
+  ] as const)('puts a place $where', ({ at: [longitude, latitude], x, y, z }) => {
+    const place = Cartesian3.fromDegrees(longitude, latitude)
+
+    // To a thousandth of a millimetre.
+    expect(place.x).toBeCloseTo(x, 6)
+    expect(place.y).toBeCloseTo(y, 6)
+    expect(place.z).toBeCloseTo(z, 6)
+  })
+
+  it('takes longitude first and latitude second', () => {
+    const north = Cartesian3.fromDegrees(0, 45)
+    const east = Cartesian3.fromDegrees(45, 0)
+
+    expect(north.z).toBeGreaterThan(4_000_000)
+    expect(north.y).toBeCloseTo(0, 6)
+    expect(east.y).toBeGreaterThan(4_000_000)
+    expect(east.z).toBeCloseTo(0, 6)
+  })
+
+  it('counts a height in metres above the ellipsoid', () => {
+    expect(Cartesian3.fromDegrees(0, 0, 1000).x).toBeCloseTo(TO_THE_EQUATOR + 1000, 6)
+    expect(Cartesian3.fromDegrees(0, 90, 1000).z).toBeCloseTo(TO_A_POLE + 1000, 6)
+  })
+
+  it('gives back the degrees and the height a place was made from', () => {
+    const place = Cartesian3.fromDegrees(-122.5, 37.75, 250)
+
+    const read = Cartographic.fromCartesian(place)
+
+    expect(EngineMath.toDegrees(read.longitude)).toBeCloseTo(-122.5, 9)
+    expect(EngineMath.toDegrees(read.latitude)).toBeCloseTo(37.75, 9)
+    expect(read.height).toBeCloseTo(250, 6)
+  })
+
+  it('makes its globe on the same ellipsoid, the very one the application gets', () => {
+    // Were there two copies of the arithmetic, the engine's ellipsoid would
+    // be another object than the one the application is given.
+    expect(new Globe().ellipsoid).toBe(Ellipsoid.WGS84)
+    expect(new GeographicTilingScheme().ellipsoid).toBe(Ellipsoid.WGS84)
+  })
