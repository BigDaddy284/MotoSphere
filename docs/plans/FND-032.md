# FND-032 – Continuous integration on Windows

**Phase:** 1 – Foundation
**Depends on:** FND-018 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §6, §14, `docs/WORKFLOW.md`, `TESTING.md`
("Continuous integration"), `docs/plans/FND-018.md`

## Objective

GitHub also runs every gate on a Windows machine, for each pull request and
each change to `main`. MotoSphere is meant to be used on Windows 11, and
until now it had never run on Windows at all.

## Design in short

- The one job of the checks workflow becomes two, from a small table of
  machines: Linux (`ubuntu-24.04`) and Windows (`windows-2025`). The steps
  are written once and run on both.
- Each machine gives its own result, "All gates (Linux)" and "All gates
  (Windows)", and one failing does not stop the other (`fail-fast: false`),
  so a pull request always shows both.
- The browser install becomes two steps of one command each. On Windows a
  step with several commands only fails on its last one, so `npm ci`
  failing would have gone unnoticed. A repository check now forbids steps
  with several commands.
- Nothing else changes: the same four pinned actions, the same token that
  can only read, the same single command `python scripts/check.py`.

## What the planner tried

On GitHub, in a trial pull request (#30, closed without merging), with
exactly the files below:

- **The first run on Windows passed, with nothing to fix**: 19 of 19 gates
  and `Tests: 492 passed, 0 failed, 0 skipped.` on `windows-2025` with
  Python 3.12.10, the same counts as on Linux (25 repository checks, 73
  script tests, 115 backend tests, 199 frontend unit tests, 80 browser
  tests). The Windows job takes about five minutes, most of it installing
  the browser.
- A temporary test that fails on Windows only turned the Windows job red
  while the Linux job stayed green (step 12 below).

Locally on Linux (Python 3.13.18 and 3.12.3, Node 22.23.4, uv 0.11.32): the
25 repository checks pass, the full run reports 19 of 19 gates and 492
tests, and 41 planted defects in the workflow were all detected.

So no fix for Windows is expected. If your run on Windows fails all the
same, see "On GitHub".

## Implementation detail

### 1. `.github/workflows/checks.yml` – the whole file

```yaml
# Runs every gate of the project for each pull request and each change to
# `main`. The gates themselves are in `scripts/check.py`; this file only
# prepares a machine and starts them (TESTING.md, "Continuous integration").
name: Checks

on:
  pull_request:
  push:
    branches: [main]

# The job only reads the repository. It is given no secret and cannot write.
permissions:
  contents: read

# A newer commit on a pull request replaces a run that is still going. Runs
# for `main` are never cut short, so every commit there gets its result.
concurrency:
  group: checks-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  gates:
    name: All gates (${{ matrix.name }})
    runs-on: ${{ matrix.os }}
    timeout-minutes: 20
    strategy:
      # Each system gives its own result: one failing does not stop the other.
      fail-fast: false
      matrix:
        include:
          - name: Linux
            os: ubuntu-24.04
          - name: Windows
            os: windows-2025
    steps:
      # Every action is pinned to a commit, with its release beside it.
      - name: Check out the repository
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Install Python
        uses: actions/setup-python@6d4fd22b20465ccc0f7354476588e8df7c9ca0e0 # v7.1.0
        with:
          python-version: "3.12"

      - name: Install uv
        uses: astral-sh/setup-uv@68559e99cc807c1eb7e9238fd43a15bba460eec2 # v10.3.3
        with:
          version: "0.11.32"

      - name: Install Node.js
        uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: "22"

      # The browser tests need a browser, and the locked Playwright decides
      # which one, so the frontend's dependencies are installed first. One
      # command to a step: on Windows a step only fails on its last command.
      - name: Install the frontend's dependencies
        working-directory: frontend
        run: npm ci

      - name: Install the browser for the browser tests
        working-directory: frontend
        run: npx playwright install --with-deps chromium

      - name: Run every gate
        run: python scripts/check.py
```

### 2. `tests/repo/test_ci_workflow.py` – the whole file, 16 tests

What changes: two expressions join the allowed list (`matrix.name`,
`matrix.os`); a `MACHINES` table; "runs on a named linux image with a time
limit" becomes four tests (the two machines, one failing does not stop the
other, the time limit, one command to a step).

```python
"""Checks on the continuous integration workflows (tasks FND-018 and FND-032).

The workflows are read as text: the repository checks use the standard
library only, and it has no YAML reader. The files are kept plain enough for
that, and the checks are strict about their layout for the same reason.

Run from the repository root:

    python -m unittest discover -s tests/repo -v
"""

import json
import re
import tomllib
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parents[2]
WORKFLOWS = ROOT / ".github" / "workflows"
CHECKS = WORKFLOWS / "checks.yml"

# The actions a workflow may use. Adding one is a decision about whose code
# runs with access to the repository, so it is made here and not in passing.
KNOWN_ACTIONS = (
    "actions/checkout",
    "actions/setup-node",
    "actions/setup-python",
    "astral-sh/setup-uv",
)

# The only expressions a workflow may contain. Text that comes from outside,
# such as the title of a pull request, must never reach a command.
KNOWN_EXPRESSIONS = (
    "github.event_name == 'pull_request'",
    "github.ref",
    "matrix.name",
    "matrix.os",
)

# The machines the gates run on, each a named image and not "the latest".
MACHINES = (
    ("Linux", "ubuntu-24.04"),
    ("Windows", "windows-2025"),
)

# An action pinned to a full commit, with the release it belongs to beside it.
PINNED = re.compile(r"^ +uses: ([\w.-]+/[\w.-]+)@[0-9a-f]{40} # v\d+\.\d+\.\d+$")


def workflows() -> dict[str, str]:
    """Return the text of every workflow, by file name."""
    files = sorted(WORKFLOWS.glob("*.y*ml")) if WORKFLOWS.is_dir() else []
    return {file.name: file.read_text(encoding="utf-8") for file in files}


def commands(text: str) -> list[str]:
    """Return every command the steps of a workflow run, in order."""
    found: list[str] = []
    lines = text.splitlines()
    for number, line in enumerate(lines):
        step = re.match(r"^( +)run: (.+)$", line)
        if step is None:
            continue
        if step.group(2) != "|":
            found.append(step.group(2))
            continue
        inside = step.group(1) + "  "
        for following in lines[number + 1 :]:
            if not following.startswith(inside):
                break
            found.append(following.strip())
    return found


class WorkflowSafetyTest(unittest.TestCase):
    """Rules that hold for every workflow in the repository."""

    def test_there_is_a_workflow_to_check(self) -> None:
        self.assertIn("checks.yml", workflows())

    def test_every_action_is_pinned_to_a_commit_with_its_release(self) -> None:
        for name, text in workflows().items():
            used = [line for line in text.splitlines() if re.search(r"\buses:", line)]
            self.assertTrue(used, f"{name} uses no action")
            for line in used:
                with self.subTest(workflow=name, line=line.strip()):
                    self.assertRegex(line, PINNED)

    def test_only_known_actions_are_used(self) -> None:
        for name, text in workflows().items():
            for action in re.findall(r"\buses: *([^@\s]+)", text):
                with self.subTest(workflow=name, action=action):
                    self.assertIn(action, KNOWN_ACTIONS)

    def test_no_workflow_runs_code_from_outside_with_the_rights_of_the_repository(self) -> None:
        for name, text in workflows().items():
            with self.subTest(workflow=name):
                self.assertNotIn("pull_request_target", text)
                self.assertNotIn("workflow_run", text)
                self.assertNotIn("secrets.", text)

    def test_every_workflow_limits_what_its_token_may_do(self) -> None:
        for name, text in workflows().items():
            with self.subTest(workflow=name):
                self.assertRegex(text, re.compile(r"^permissions:$", re.MULTILINE))
                self.assertNotIn("write-all", text)

    def test_no_text_from_outside_reaches_a_command(self) -> None:
        for name, text in workflows().items():
            for expression in re.findall(r"\$\{\{(.*?)\}\}", text):
                with self.subTest(workflow=name, expression=expression.strip()):
                    self.assertIn(expression.strip(), KNOWN_EXPRESSIONS)


class ChecksWorkflowTest(unittest.TestCase):
    """The workflow that runs every gate."""

    text: str

    @classmethod
    def setUpClass(cls) -> None:
        cls.text = CHECKS.read_text(encoding="utf-8")

    def test_runs_for_pull_requests_and_for_changes_to_main(self) -> None:
        self.assertIn("\non:\n  pull_request:\n  push:\n    branches: [main]\n\n", self.text)

    def test_its_token_can_only_read(self) -> None:
        self.assertEqual(self.text.count("permissions:"), 1)
        self.assertIn("\npermissions:\n  contents: read\n\n", self.text)

    def test_checkout_keeps_no_credentials(self) -> None:
        self.assertEqual(self.text.count("actions/checkout@"), 1)
        self.assertRegex(
            self.text,
            r"uses: actions/checkout@\S+ # \S+\n +with:\n +persist-credentials: false\n",
        )

    def test_runs_the_check_runner_and_nothing_in_its_place(self) -> None:
        self.assertEqual(
            commands(self.text),
            [
                "npm ci",
                "npx playwright install --with-deps chromium",
                "python scripts/check.py",
            ],
        )

    def test_nothing_lets_a_failing_step_pass(self) -> None:
        self.assertNotIn("continue-on-error", self.text)
        self.assertNotRegex(self.text, re.compile(r"^ +(- )?if:", re.MULTILINE))
        self.assertNotRegex(self.text, re.compile(r"^ +(- )?shell:", re.MULTILINE))

    def test_runs_on_linux_and_on_windows(self) -> None:
        machines = re.findall(r"^ +- name: (\w+)\n +os: (\S+)$", self.text, re.MULTILINE)

        self.assertEqual(machines, list(MACHINES))
        self.assertEqual(
            re.findall(r"^ +runs-on: (.+)$", self.text, re.MULTILINE), ["${{ matrix.os }}"]
        )
        self.assertIn("All gates (${{ matrix.name }})", self.text)

    def test_one_machine_failing_does_not_stop_the_other(self) -> None:
        self.assertEqual(re.findall(r"^ +fail-fast: (.+)$", self.text, re.MULTILINE), ["false"])

    def test_the_job_has_a_time_limit(self) -> None:
        self.assertRegex(self.text, re.compile(r"^ +timeout-minutes: \d+$", re.MULTILINE))

    def test_every_step_runs_one_command(self) -> None:
        # On Windows a step with several commands only fails on its last one.
        self.assertNotRegex(self.text, re.compile(r"^ +run: *[|>]", re.MULTILINE))

    def test_tools_are_the_versions_the_project_supports(self) -> None:
        with (ROOT / "backend" / "pyproject.toml").open("rb") as file:
            oldest_python = tomllib.load(file)["project"]["requires-python"]
        package = json.loads((ROOT / "frontend" / "package.json").read_text(encoding="utf-8"))
        oldest_node = package["engines"]["node"]

        python = re.findall(r'^ +python-version: "(.+)"$', self.text, re.MULTILINE)
        node = re.findall(r'^ +node-version: "(.+)"$', self.text, re.MULTILINE)
        uv = re.findall(r'^ +version: "(.+)"$', self.text, re.MULTILINE)

        # The oldest Python the pipeline supports, so that nothing newer
        # slips into the code unnoticed.
        self.assertEqual([f">={version}" for version in python], [oldest_python])
        self.assertEqual(len(node), 1)
        self.assertTrue(oldest_node.startswith(f">={node[0]}."), (node, oldest_node))
        self.assertEqual(len(uv), 1)
        self.assertRegex(uv[0], r"^\d+\.\d+\.\d+$")


if __name__ == "__main__":
    unittest.main()
```

### 3. `TESTING.md`

In "Continuous integration", the first paragraph, the sentence about Python
and the last bullet change, and the closing sentence about Windows goes. The

```markdown
## Continuous integration

GitHub runs every gate for each pull request and for each change to `main`,
on a Linux machine and on a Windows machine. The workflow is
`.github/workflows/checks.yml`. It does nothing of its own: on each machine
it installs Python, uv, Node.js and the browser for the browser tests, and
then runs `python scripts/check.py`, the same command as on a developer's
machine. A job fails when the command does, and its log ends with the same
summary. Each machine gives its own result, "All gates (Linux)" and "All
gates (Windows)": one failing does not stop the other.

The jobs use Python 3.12, the oldest version the pipeline supports, so that
nothing newer slips into the code unnoticed.

The workflow is given as little as possible, and the repository checks hold
it to that:

- Its token can only read the repository, and it uses no secret.
- Every action is pinned to a full commit, with its release beside it, and
  only actions on a short list may be used. To update one, change the commit
  and the release together.
- It never runs with the repository's rights on code from outside
  (`pull_request_target`), and no text from outside, such as the title of a
  pull request, reaches a command.
- No step may be skipped or allowed to fail, and every step runs one
  command: on Windows, a step with several commands only fails on its last
  one.
```

## Acceptance criteria

1. On this task's own pull request, both jobs finish green, "All gates
   (Linux)" and "All gates (Windows)", and each log ends with
   `19 of 19 gates passed.` and `Tests: 492 passed, 0 failed, 0 skipped.`
2. A failure on one machine only turns that machine's job red and leaves
   the other green; both run to the end.
3. The machines are named images, not "latest"; the repository checks pin
   the two machines, the job names, `fail-fast: false` and one command to a
   step.
4. Every rule from FND-018 still holds (read-only token, no secret, pinned
   and known actions, nothing from outside in a command, no step skipped or
   allowed to fail).
5. Locally, `python -m unittest discover -s tests/repo -v` reports 25 tests,
   OK, and the full run reports 19 of 19 gates and 492 tests.
6. Only the files under "Scope" changed.

## Verification

### Locally

From a clean state (delete `frontend/node_modules`, `frontend/dist`,
`frontend/test-results`, `frontend/public/data` and `backend/.venv` first if
they exist). Stage your changes first (`git add -A`).

```
python -m unittest discover -s tests/repo -v
python scripts/check.py
git status --short
```

Expected: `Ran 25 tests` / `OK`; the full run ends with
`19 of 19 gates passed.` and `Tests: 492 passed, 0 failed, 0 skipped.`, exit
code 0. Paste the whole summary into the report. Port 4173 must be free. In
this development environment the browser is already installed: do **not**
run `npx playwright install` here.

Then prove the tests can fail (do not commit these changes; restore each one
before the next). After each of steps 1 to 11 run
`python -m unittest discover -s tests/repo` and report which tests fail.

1. **No Windows machine.** Remove the two lines `- name: Windows` /
   `os: windows-2025` → "runs on linux and on windows" fails.
2. **The Windows image is whatever is newest.** `os: windows-latest` → the
   same test fails.
3. **Every job runs on Linux whatever its name says.**
   `runs-on: ubuntu-24.04` → the same test fails.
4. **The jobs cannot be told apart.** `name: All gates` → the same test
   fails.
5. **A third machine nobody decided on.** Add `- name: Mac` /
   `os: macos-15` to the table → the same test fails.
6. **One machine failing stops the other.** `fail-fast: true` → "one machine
   failing does not stop the other" fails. Removing the line fails it too.
7. **A step with two commands.** Put `npm ci` and
   `npx playwright install --with-deps chromium` back into one step with
   `run: |` → 2 tests fail.
8. **The browser is installed without the locked version.** Remove the step
   "Install the frontend's dependencies" → "runs the check runner and
   nothing in its place" fails.
9. **An action named by a tag that can be moved.**
   `uses: actions/checkout@v7` → 2 tests fail (as in FND-018).
10. **The token may write.** `contents: write` → "its token can only read"
    fails (as in FND-018).
11. **A failing run is forgiven.** `run: python scripts/check.py || true` →
    "runs the check runner and nothing in its place" fails (as in FND-018).

### On GitHub

Commit, push your branch and open the pull request. The workflow starts by
itself, with two jobs. Read their results with the GitHub tools you have
(the pull request's check runs and each job's log); do not poll in a tight
loop. The Windows job takes about five minutes.

- **If the Windows job fails where the planner's trial passed**: that is a
  real finding. Read the whole summary first (every gate runs even when an
  earlier one failed), find the cause and fix the cause. Never skip a test,
  loosen an assertion, mark a step as allowed to fail or make a test behave
  differently on Windows to get it through. A fix outside the files under
  "Scope" is a deviation to report, with the cause. If the fix needs a
  decision about how the application should behave, stop and report the
  failures instead.
- **If a preparation step fails**: make the smallest change to the workflow
  that fixes it, keep every rule the repository checks pin, and report it.

When both jobs are green, paste the end of each job's log (the summary and
the two closing lines) into the report.

Then prove that each machine gives its own result:

12. **A failure on Windows only.** Push one extra commit, titled
    `TEMPORARY: a test that fails on Windows only`, that adds the file
    `tests/repo/test_planted.py` with one `unittest` test:
    `self.assertNotEqual(sys.platform, "win32")` (typed, with `-> None`, so
    that the lint and type gates pass). Expected: "All gates (Linux)" is
    green with `Tests: 493 passed, 0 failed, 0 skipped.`; "All gates
    (Windows)" is red with `FAILED  Repository checks` showing
    `25 passed, 1 failed`, `18 of 19 gates passed.` and
    `Tests: 492 passed, 1 failed, 0 skipped.` Paste those lines into the
    report. Then push a commit that undoes it (`git revert`), and wait for
    both jobs to be green on the final commit. Do not force-push; the pull
    request is merged as one commit, so neither commit reaches `main`.

## Deliver

- A pull request to `main` with the same title and a **Test report** in the

  summary of the full local run, the prove-it results, links to the run on
  the final commit (both jobs green) and to the run of step 12 with the

- The pull request's final diff must hold only the files under "Scope".
