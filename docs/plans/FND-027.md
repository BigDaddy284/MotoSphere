# FND-027 – Real published data in local development and browser tests

**Phase:** 1 – Foundation
**Depends on:** FND-021 (merged), FND-016 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §9, §11, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §4 and §6

## Objective

The development server, the preview of the production build and the browser
tests serve published data that the real export command wrote, never a
hand-written copy. This task joins the pipeline and the frontend for the
first time: the frontend's manifest reader reads what the pipeline really
writes, from the site as it is really served.

## Design in short

- One command, `npm run data` (in `frontend/`), runs the pipeline's export
  through uv and writes into `frontend/public/data/`. Vite serves everything
  in `public/` during development and copies it into the build, so the data
  is then at `data/manifest.json` in both.
- The command runs from the `backend/` folder (`uv run --directory`), so the
  pipeline finds its own settings there, exactly as when it is run by hand.
- The exported files are generated, so Git ignores the folder, and Prettier
  does too.
- The browser tests' web server runs the export before the build. If the
  export fails, the server does not start and no test runs, so stale data is
  never tested by mistake.
- The tests prove the data is from this run: the Playwright configuration
  records when the run started, and a test checks that the manifest's
  generation time is not earlier than that. A manifest left over from an
  earlier run, or a copy written by hand, fails this test.
- The frontend's reader (`loadManifest`, `parseManifest`) is used by the
  tests directly, against the served site. The page itself does not show the
  data yet; that is FND-028.

### 6. `frontend/e2e/data.spec.ts` – 6 browser tests

```ts
import { readdir, readFile } from 'node:fs/promises'
import path from 'node:path'
import { loadManifest, manifestUrl, parseManifest } from '../src/data/manifest.ts'
import { expect, test } from './fixtures'

/**
 * The built site under test carries published data that the real export
 * command wrote when the test server started (see `playwright.config.ts`).
 * No test here uses a hand-written copy of a published file.
 */

const REPOSITORY = path.resolve(import.meta.dirname, '..', '..')

/** When this run started, to the second, because the manifest's time has no fractions. */
function runStarted(): number {
  const started = Number(process.env['MOTOSPHERE_E2E_STARTED'])
  expect(Number.isSafeInteger(started), 'the start of the run is known').toBe(true)
  return Math.floor(started / 1000) * 1000
}

test.describe('published data', () => {
  test('the built site serves the manifest as JSON', async ({ request }) => {
    const response = await request.get(manifestUrl('/'))

    expect(response.status()).toBe(200)
    expect(response.headers()['content-type']).toMatch(/^application\/json/)
    expect((await response.text()).endsWith('}\n')).toBe(true)
  })

  test('the manifest reader accepts the served manifest', async ({ request, baseURL }) => {
    const response = await request.get(manifestUrl('/'))
    expect(parseManifest(await response.json()).ok).toBe(true)

    const result = await loadManifest(`${baseURL}/`)
    expect(result.ok).toBe(true)
  })

  test('the manifest was exported for this run', async ({ baseURL }) => {
    const result = await loadManifest(`${baseURL}/`)
    if (!result.ok) {
      throw new Error(`no manifest: ${result.problem}`)
    }

    const generated = Date.parse(result.manifest.generatedAt)
    expect(generated).toBeGreaterThanOrEqual(runStarted())
    expect(generated).toBeLessThanOrEqual(Date.now())
  })

  test('the manifest comes from this version of the pipeline', async ({ baseURL }) => {
    const project = await readFile(path.join(REPOSITORY, 'backend', 'pyproject.toml'), 'utf8')
    const version = /^version = "([^"]+)"$/m.exec(project)?.[1]
    expect(version, 'the version in backend/pyproject.toml').toBeDefined()

    const result = await loadManifest(`${baseURL}/`)

    expect(result.ok && result.manifest.applicationVersion).toBe(version)
    expect(result.ok && result.manifest.formatVersion).toBe(1)
  })

  test('the page a browser loads can fetch and read the manifest', async ({ page }) => {
    await page.goto('/')

    const content: unknown = await page.evaluate(async (url) => {
      const response = await fetch(url, { cache: 'no-cache' })
      return response.json()
    }, manifestUrl('/'))

    expect(parseManifest(content).ok).toBe(true)
  })

  test('the export leaves nothing but the manifest in the data folder', async () => {
    const exported = await readdir(path.join(REPOSITORY, 'frontend', 'public', 'data'))

    expect(exported).toEqual(['manifest.json'])
  })
})
```

1. **No export before the build, old data left behind.** With

   exported for this run" fails, and only that test.

   `frontend/public/data` → all six data tests fail.

   Delete the stray `frontend/public/manifest.json` afterwards.
4. **Failing export.** `--out ../frontend/package.json` in the script → the
   web server does not start (`Export failed: cannot write to …`), no test
   runs and the exit code is not 0.
5. **Start of the run not recorded.** Remove the `MOTOSPHERE_E2E_STARTED`
   line from the configuration → "the manifest was exported for this run"
   fails.
6. **Exported data not ignored.** Remove `/frontend/public/data/` from
   `.gitignore` → the repository checks fail.

Finish with every gate passing again and `git status` clean.
