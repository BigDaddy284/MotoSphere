# DAT-003 – A real, separate store for every test

**Phase:** 2 – Data store and published data
**Depends on:** DAT-021 and DAT-022 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §12, `docs/WORKFLOW.md`, `TESTING.md`
("Opening the data store", "Units of work"), `ARCHITECTURE.md` §5,
`backend/tests/conftest.py`, `backend/src/motosphere/db/store.py`,
`backend/tests/integration/test_work.py`

## Objective

Every database test gets its own real SQLite file and can never see another
test's data, and a test that leaves a connection to its store open fails
for that reason itself.

## Why

Every later task of Phase 2 tests tables, migrations and collected records
against the store. Three things must not be left to each test file:

1. **Where the store is.** The two test files that use a store today each
   build one with a helper of their own. The next twenty would each do it
   again, and nothing would hold them to a file of their own.
2. **A connection left open fails the wrong test.** With warnings counted
   as errors, Python reports a connection that was never closed whenever it
   tidies up, which is in the middle of some later test. The planner saw
   exactly that in its trial of DAT-021: a planted defect that kept
   connections open failed a second test, a different one from run to run.
   A leak in the pipeline's code would show up the same way.
3. **On Windows an open file cannot be removed**, so one test that leaves a
   connection open can break the clean-up of the whole run.

## Design in short

- One fixture, `store`, in `backend/tests/conftest.py`. It opens
  `store.sqlite3` in the test's own temporary folder through `open_store`,
  the function the pipeline uses, and gives the test the engine. The store
  is empty, real, and nobody else's.
- **It remembers every connection that is taken** from the engine (the
  engine's `checkout` event hands over SQLAlchemy's own handle for it).
  When the test has ended, the handles that are still valid are the
  connections the test left open.
- **They are closed for the test**, through SQLAlchemy, so that work that
  was not committed is taken back and the file is closed.
- **And the test is reported**: the fixture fails with "Connections to its
  store that the test left open: N. They were closed for it." pytest shows
  that as an error at the end of that test, beside the test's own result.
  A connection that was dropped without being closed counts too, because
  the fixture still holds its handle.
- **How the fixture is tested.** What it gives a test is tested by ordinary
  tests that use it. What it does after a test has ended cannot be seen
  from inside that test, so one test lets pytest itself run a small file of
  tests in a process of its own, with this project's `conftest.py`, and
  reads the outcome. pytest brings the tool for that, `pytester`; it is
  switched on in `conftest.py` and is no new package.
- The existing tests of the store and of units of work keep their own
  helpers. They test the opening itself and count connections themselves,
  and this task changes no existing test.

def tables(store: Engine) -> list[str]:
    with store.connect() as connection:
        found = connection.exec_driver_sql("SELECT name FROM sqlite_master ORDER BY name")
        return [str(name) for (name,) in found]


@pytest.mark.parametrize("turn", ["first", "second", "third"])
def test_every_test_has_an_empty_store_and_can_write_the_same_key(store: Engine, turn: str) -> None:
    assert tables(store) == []

    with store.begin() as connection:
        connection.exec_driver_sql("CREATE TABLE parent (id INTEGER PRIMARY KEY, turn TEXT)")
        connection.exec_driver_sql("INSERT INTO parent (id, turn) VALUES (1, ?)", (turn,))

    assert tables(store) == ["parent"]


def test_the_store_is_a_real_sqlite_file_in_the_tests_own_folder(
    store: Engine, tmp_path: Path
) -> None:
    with store.begin() as connection:
        connection.exec_driver_sql("CREATE TABLE parent (id INTEGER PRIMARY KEY)")

    assert store.url.database == str(tmp_path / "store.sqlite3")
    assert (tmp_path / "store.sqlite3").read_bytes().startswith(b"SQLite format 3\x00")


def test_the_store_is_opened_the_way_the_pipeline_opens_it(store: Engine) -> None:
    with store.begin() as connection:
        connection.exec_driver_sql("CREATE TABLE parent (id INTEGER PRIMARY KEY)")
        connection.exec_driver_sql(
            "CREATE TABLE child (parent_id INTEGER NOT NULL REFERENCES parent (id))"
        )

    with store.connect() as connection, pytest.raises(IntegrityError, match="FOREIGN KEY"):
        connection.exec_driver_sql("INSERT INTO child (parent_id) VALUES (7)")


def test_a_test_that_leaves_connections_open_is_an_error_and_they_are_closed_for_it(
    pytester: pytest.Pytester,
) -> None:
    pytester.makeconftest(CONFTEST.read_text(encoding="utf-8"))
    pytester.makepyfile(LEAVING_CONNECTIONS_OPEN)

    result = pytester.runpytest_subprocess("-p", "no:cacheprovider", "-W", "error", timeout=120)

    result.assert_outcomes(passed=16, errors=4)
    result.stdout.fnmatch_lines(
        [
            "*ERROR at teardown of test_one_that_closes_a_connection_and_leaves_another_open*",
            "*Connections to its store that the test left open: 1. They were closed for it.",
            "*ERROR at teardown of test_one_that_leaves_two_connections_open*",
            "*Connections to its store that the test left open: 2. They were closed for it.",
            "*ERROR at teardown of test_one_that_leaves_a_session_open*",
            "*Connections to its store that the test left open: 1. They were closed for it.",
            "*ERROR at teardown of test_one_that_drops_a_connection_without_closing_it*",
            "*Connections to its store that the test left open: 1. They were closed for it.",
        ]
    )

## Acceptance criteria

1. A test that asks for `store` gets the engine of a real SQLite file,
   `store.sqlite3` in its own temporary folder, opened through
   `open_store` (a row without its parent is refused), and empty.
2. Three tests that each expect an empty store and write the same key all
   pass. Nothing is shared between them, so their order cannot matter.
3. A test that leaves connections open, one or two, through a session, or
   by dropping a connection without closing it, is reported by pytest as an
   error at the end of that test, with "Connections to its store that the
   test left open: N. They were closed for it." and the right N; a
   connection the test closed itself is not counted.
4. Every connection that was left open is closed by the time the next test
   runs, and the store's file can be removed, on Windows too. The next test
   has a store of its own.
5. A test that closes what it opened is not reported.
6. The type check passes with no `ignore`.
7. No existing test changed, and all pass. The full run reports 19 of 19
   gates and 834 tests (backend tests 204).
8. On the pull request, "All gates (Linux)" and "All gates (Windows)" are
   green with those numbers, and the three jobs after the gates are
   skipped.
9. Only the files under "Scope" changed.
