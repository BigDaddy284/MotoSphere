## Objective

One function puts two stored records that may be the same thing into
the review queue, and a doubt that is there already stays one item.

## Why

"Do not automatically merge uncertain rider or track identities." and
"Use review queues when information conflicts." (CLAUDE.md §11). The
table of the review queue is there (DAT-010) and refuses the same
doubt a second time (DAT-050), but nothing writes an item. The code
that collects needs one call for "these two may be one": a call that
takes the two records as they are, cannot name a record that is not
stored, cannot put a pair in the wrong order, and can be made again by
the next run without asking a person twice.

## What this task is, and what it is not

- **It is** one function, `open_possible_duplicate`, in a new module
  `motosphere.db.review`, and its tests.
- **It is not** the function that opens a doubt about a field. That is
  DAT-053 now (PLAN-030): it has questions of its own, which are
  answered by trying, and none of them is needed here.
- **It is not** anything that decides an item or keeps a decision
  (DAT-052), nor anything that merges two records or finds that two
  records are alike.
- No table, column, check, index or migration changes. The schema
  stays at version 9.

## Design in short

    def open_possible_duplicate(work: Session, record: Base, other: Base, *, reason: str) -> ReviewItem:

- **Given the two records themselves.** The name of the table and the
  two keys are taken from them, as `change` takes them (DAT-047).
- **Either order.** The item names the record with the smaller key as
  its record and the one with the greater as the other, which is the
  one way the table says a pair (DAT-010).
- **The doubt that is there is given back as it is.** One statement
  looks for an item of this table and these two keys. If there is
  one, it is returned and nothing is written, whatever its state. If
  not, one open item is added, written to the unit of work, and
  returned.
- **Four refusals before anything is written**, each a `ValueError`
  with one sentence: a record that is not stored or not of this unit
  of work; two records of two tables; rows of a table that holds no
  collected records; one record twice.
- **Part of the unit of work.** It is written (`work.flush()`) before
  the function returns, and kept or taken back with the unit.

## What the task left open, and what the trial settled

- **One function, or one for each kind of doubt?** One for each shape.
  A possible duplicate is given two records and a reason. A doubt
  about a field is given one record, a field, a source, an address,
  what the source says and which of two kinds it is. A function for
  both would take eight arguments of which each call uses half, and
  would have to refuse every mixture. The second function is DAT-053.
- **What does it give back when the doubt is there?** The item that is
  there, unchanged. The code that called can read its state: an open
  item means a person has not looked yet, a rejected one means "these
  are two", an accepted one means "these are one". The function does
  not say apart from that whether the item is new; nothing asks for
  it yet.
- **Is the reason of the second call kept?** No. The item keeps the
  reason it was opened with, its note and its times. A run that finds
  the same pair again has nothing to add that a person needs, and an
  item that changed every night would look new every morning. The
  second reason is not read at all, so an empty one is not refused
  there; a test holds that, so that it is on record.
- **Does a decided item count?** Yes, as in DAT-050: it is given back
  as it was decided. Four tests hold that, for both decisions and both
  orders.
- **Which records are taken?** Those that are stored and that this
  unit of work read or stored, by the same rule and for the same
  reason as `change`: only they have a key that is a key of the
  table. A record that was added and is not written yet has no key,
  so the caller writes it first (`work.flush()`); the function does
  not write what is pending by itself. A planted defect that makes it
  do so is detected.
- **Which tables?** Every table but those on `NOT_COLLECTED` (DAT-046):
  the sources, what they offer, the runs, the history and the queue
  itself. The queue is where the collecting puts what it cannot
  settle about what it collected; two rows of the history or two
  items are not a possible duplicate in that sense, and what would
  follow from accepting one is nothing any task builds. The list is
  the one the store already keeps of exactly these tables, each with
  its reason, so the function names no table itself. The test has two
  stored rows of each table on the list and fails for a table that is
  put on it later until that table has its two rows there.
- **In which order are the refusals said?** Stored first, because a
  record that is not stored has no key to compare. Then the tables:
  the test gives a venue and a person that have the same key, so a
  function that compared the keys first would call them one record.
  Then the list, then the record given twice: a source given twice is
  refused for its table, like any two sources. The order between "two
  tables" and "a table of the list" is not held by a test: both
  sentences are true of a source and a track, and either may be said.
- **Does it write at once, or with the unit of work?** With the unit
  of work, and it is written to it before the function returns, as
  `change` does. So the item has its key when it is given back, a
  reason the store refuses is refused at the call, and a unit of work
  that fails leaves no item.
- **What refuses an empty reason?** The store, by the check the table
  has (`ck_review_item_reason_not_empty`), at the call. The function
  does not say the rule a second time in its own words.
- **Can another connection store the same doubt between the look and
  the write?** No. A unit of work is one transaction of SQLite, which
  holds its reading lock from the look onwards, and SQLite keeps
  nothing another connection writes while that lock is held: the
  other connection is told "database is locked". The trial tried it,
  and a test does it on every run, on both machines: between the
  function's look and its write another connection writes the same
  pair and tries to keep it. If that ever went through, the index of
  DAT-050 would refuse the function's write and the unit of work would
  fail as a whole; no doubt would be there twice either way.
- **Is the look answered by the index of DAT-050?** Yes. The test
  takes the statement the function really sends, with what it is
  given, and reads SQLite's plan for it: one search of
  `ix_review_item_record_table_record_id_other_record_id`. It also
  holds that the function sends one statement where the doubt is
  there, and two where it is new.
- **Where does it live?** In a module of its own, `motosphere.db.review`,
  beside `motosphere.db.changes` and `motosphere.db.runs`: what the
  store does with its review queue. DAT-053 and DAT-052 add to it.

### 1. `backend/src/motosphere/db/review.py` – new, the whole file

```python
"""Putting a doubt into the review queue.

Where the collecting cannot tell by itself what is right, it does not
guess (DESIGN.md 8, CLAUDE.md 11): it puts the doubt down as an item of
the review queue, and a person decides. The functions here are how an
item is opened. Each is given the records themselves and takes the name
of their table and their keys from them, so that an item is about
records that are stored.

A doubt is one item. Whoever opens a doubt that the queue holds already
is given the item that is there, as it is, whether it is still open or
was decided: a question a person has answered is not put to them again.
"""

from sqlalchemy import inspect, select
from sqlalchemy.orm import Session

from motosphere.db.base import Base
from motosphere.db.models.provenance_rule import NOT_COLLECTED
from motosphere.db.models.review_item import ReviewItem, ReviewKind

__all__ = ["open_possible_duplicate"]


def open_possible_duplicate(work: Session, record: Base, other: Base, *, reason: str) -> ReviewItem:
    """Put down that two stored records of one table may be the same thing, and give the item.

    The two records can be given in either order: the item names the one
    with the smaller key as its record and the one with the greater as
    the other, which is the one way the table says a pair. ``reason``
    says why they may be the same, in plain words, for the person who
    decides.

    When the queue holds an item for these two records already, that
    item is given back as it is and nothing is written: its state, its
    reason and its note stay what they were, and the reason given here
    is not read. Otherwise one open item is stored and given back.

    Neither record is touched. Nothing is merged, and nothing is written
    to the history of the changes: an item is a question, and what
    follows from its answer belongs to the code that decides and merges.

    The item is part of the unit of work ``work`` and is written to it
    before the function returns, so what the store refuses is refused
    here, which is a reason that is empty. Whatever is refused, the unit
    of work fails as a whole, and no item is kept.

    The function looks for the doubt and then writes it. No other
    connection can store the same doubt between the two: SQLite keeps
    nothing another connection writes while a unit of work that has read
    is open. Past this function, the store's own index refuses the same
    doubt a second time (DAT-050).

    Refused before anything is written, each in one sentence: a record
    that this unit of work did not read or store, or that is not stored
    yet; two records of two tables; records of a table that holds no
    collected records; and a record given as its own duplicate.
    """
    for one in (record, other):
        state = inspect(one)
        if not state.persistent or state.session is not work:
            raise ValueError(
                "Only records that are stored, and that this unit of work read or stored, "
                "are put to the review queue."
            )
    table = str(type(record).__tablename__)
    table_of_the_other = str(type(other).__tablename__)
    if table_of_the_other != table:
        raise ValueError(
            "A possible duplicate is two records of one table: these are of "
            f"{table} and of {table_of_the_other}."
        )
    if table in NOT_COLLECTED:
        raise ValueError(
            "The review queue is for doubts about collected records, and the table "
            f"{table} holds none."
        )
    if record.id == other.id:
        raise ValueError("A record is not its own duplicate.")

    first, second = sorted((record.id, other.id))
    there = work.scalars(
        select(ReviewItem).where(
            ReviewItem.record_table == table,
            ReviewItem.record_id == first,
            ReviewItem.other_record_id == second,
        )
    ).one_or_none()
    if there is not None:
        return there

    item = ReviewItem(
        kind=ReviewKind.POSSIBLE_DUPLICATE,
        record_table=table,
        record_id=first,
        other_record_id=second,
        reason=reason,
    )
    work.add(item)
    work.flush()
    return item
```

def held(store: Engine) -> list[tuple[object, ...]]:
    """What the queue holds, as SQLite holds it, by the key, without the key and the times."""
    with store.connect() as connection:
        return [tuple(row) for row in connection.exec_driver_sql(WHAT_IT_HOLDS)]


def everything(store: Engine) -> list[tuple[object, ...]]:
    """Every column of every item, as SQLite holds it, by the key."""
    with store.connect() as connection:
        return [tuple(row) for row in connection.exec_driver_sql(EVERYTHING_IT_HOLDS)]


def rows_of(store: Engine, statement: str) -> list[tuple[object, ...]]:
    """What a plain statement finds in the file."""
    with store.connect() as connection:
        return [tuple(row) for row in connection.exec_driver_sql(statement)]


def opened(store: Engine, record: int, other: int, reason: str = REASON) -> ReviewItem:
    """Open the possible duplicate of two venues in a unit of work of its own."""
    with unit_of_work(store) as work:
        return open_possible_duplicate(
            work, work.get_one(ProofVenue, record), work.get_one(ProofVenue, other), reason=reason

def test_a_possible_duplicate_is_one_open_item_that_names_its_two_records(
    made: Engine, clock: list[datetime]
) -> None:
    asked = len(clock)

    item = opened(made, 1, 2)

    # The name of the table and the two keys are those of the records. It
    # is open, and nothing else is said of it.
    assert held(made) == [a_pair("proof_venue", 1, 2)]
    # One reading of the clock: the item was stored at that moment.
    assert len(clock) == asked + 1
    moment = times.to_text(clock[-1])
    assert rows_of(made, "SELECT id, created_at, updated_at FROM review_item") == [
        (1, moment, moment)
    ]
    assert (item.id, item.kind, item.record_table, item.record_id, item.other_record_id) == (
        1,
        ReviewKind.POSSIBLE_DUPLICATE,
        "proof_venue",
        1,
        2,
    )
    assert (item.reason, item.state, item.decided_by, item.decided_at, item.note) == (
        REASON,
        ReviewState.OPEN,
        None,
        None,
        None,
    )
    assert (item.field, item.source_id, item.source_address, item.source_value) == (
        None,
        None,
        None,
        None,
    )
    assert item.created_at == item.updated_at == clock[-1]

def sent_by(store: Engine, call: Callable[[], object]) -> list[tuple[str, Sequence[object]]]:
    """Every statement a call sends to the store, with what it is given."""
    sent: list[tuple[str, Sequence[object]]] = []

    def remember(
        _connection: Connection,
        _cursor: object,
        statement: str,
        given: Sequence[object],
        _context: object,
        _many: bool,
    ) -> None:
        sent.append((statement, given))

    event.listen(store, "before_cursor_execute", remember)
    try:
        call()
    finally:
        event.remove(store, "before_cursor_execute", remember)
    return sent


def plan_of(store: Engine, statement: str, given: Sequence[object]) -> list[str]:
    """SQLite's own account of how it will answer a statement, step by step."""
    with store.connect() as connection:
        steps = connection.exec_driver_sql("EXPLAIN QUERY PLAN " + statement, tuple(given))
        return [str(step[3]) for step in steps]

def test_no_other_connection_stores_the_doubt_between_the_look_and_the_write(
    made: Engine,
) -> None:
    # The function looks and then writes. Were another connection able to
    # store the same doubt in between, the write would be refused. SQLite
    # lets none: it keeps nothing another connection writes while this
    # unit of work, which has read, is open.
    said: list[str] = []

    def write_from_elsewhere(
        _connection: Connection,
        _cursor: object,
        statement: str,
        _given: Sequence[object],
        _context: object,
        _many: bool,
    ) -> None:
        if not statement.startswith("INSERT INTO review_item "):
            return
        with closing(sqlite3.connect(str(made.url.database), timeout=0)) as elsewhere:
            elsewhere.execute(THE_PAIR_PAST_THE_MODEL)
            try:
                elsewhere.commit()
            except sqlite3.OperationalError as refusal:
                said.append(str(refusal))
            else:
                said.append("kept")
            elsewhere.rollback()

    event.listen(made, "before_cursor_execute", write_from_elsewhere)
    try:
        opened(made, 1, 2)
    finally:
        event.remove(made, "before_cursor_execute", write_from_elsewhere)

    assert said == ["database is locked"]
    assert held(made) == [a_pair("proof_venue", 1, 2)]

## Acceptance criteria

1. `open_possible_duplicate(work, record, other, reason=...)` stores
   one open item of the kind "possible duplicate" that names the
   table and the two keys of the records and the reason, and nothing
   else, at one reading of the clock, and gives it back.
2. The two records can be given in either order: the smaller key is
   the record and the greater the other.
3. The same doubt again gives back the item that is there and stores
   none, as before and turned round, in a later unit of work and in
   the same one, and also where the item was accepted or rejected:
   not one column of it is another afterwards, and the reason given
   the second time is not read.
4. A pair that shares one record with another pair, and the same two
   keys in another table, are other doubts and are stored.
5. The item is written to the unit of work before the function
   returns and is kept only when the unit ends; a unit of work that
   fails leaves no item. The records are not touched and the history
   gets no row.
6. Refused before anything is written, each with its one sentence: a
   record that is not stored or not of this unit of work, as the
   record and as the other; two records of two tables; two rows, and
   one row twice, of each table that holds no collected records; and
   one record twice.

   of work fails as a whole.

   one search, and a write only where the doubt is new. Another
   connection that tries to store the same doubt between the look and
