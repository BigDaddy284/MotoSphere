# FND-026 – Current date in the top bar

**Phase:** 1 – Foundation
**Depends on:** FND-015 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §8, `DESIGN.md` §12.1, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §3

## Objective

The top bar shows today's date, written out in the language of the user's
browser and for the day where the user is, for example
"Tuesday, 17 November 2026". It changes at midnight without a reload.

## Design in short

- A calendar day is handled as a **day key**: the text `YYYY-MM-DD` for the
  day in the time zone of the user's device. It is also the value of the
  `datetime` attribute of the HTML `time` element.
- Three small pure functions work on moments and day keys; a hook keeps
  today's key current; a component renders it.
- The hook sets one timer for the next local midnight, worked out from the
  calendar (days are not always 24 hours long). A timer does not run while a
  device sleeps, so the hook also checks the day whenever the page comes
  back into view.
- The shell gets an `info` slot at the right-hand end of the top bar, before
  the Details button. The data status (FND-016) will use the same slot.

### 1. `frontend/src/clock/today.ts`

Exactly this content:

```ts
// A calendar day is handled as a "day key": the text YYYY-MM-DD, for the day
// in the user's own time zone. It is also the machine-readable form that the
// HTML `time` element expects.

function pad(value: number, length: number): string {
  return String(value).padStart(length, '0')
}

/** The day key of a moment, in the time zone of the user's device. */
export function localDayKey(moment: Date): string {
  return [
    pad(moment.getFullYear(), 4),
    pad(moment.getMonth() + 1, 2),
    pad(moment.getDate(), 2),
  ].join('-')
}

/**
 * The milliseconds from a moment to the start of the next day in the time
 * zone of the user's device. Days are not always 24 hours long (clock
 * changes), so this is worked out from the calendar.
 */
export function msUntilNextDay(moment: Date): number {
  const nextDay = new Date(moment.getFullYear(), moment.getMonth(), moment.getDate() + 1)
  return nextDay.getTime() - moment.getTime()
}

/**
 * A day key written out for reading, such as "Tuesday 17 November 2026", in
 * the given language, or in the language of the user's browser.
 */
export function formatDay(dayKey: string, locale?: string): string {
  // The key already is the user's local day. Reading and formatting it as a
  // UTC date keeps the device's time zone from shifting it a second time.
  return new Intl.DateTimeFormat(locale, {
    weekday: 'long',
    day: 'numeric',
    month: 'long',
    year: 'numeric',
    timeZone: 'UTC',
  }).format(new Date(`${dayKey}T00:00:00Z`))
}
```

### 2. `frontend/src/clock/useToday.ts`

Exactly this content:

```ts
import { useEffect, useState } from 'react'
import { localDayKey, msUntilNextDay } from './today.ts'

/**
 * Today's day key (YYYY-MM-DD) in the time zone of the user's device. It
 * changes when the day changes, without a reload.
 */
export function useToday(): string {
  const [today, setToday] = useState(() => localDayKey(new Date()))

  useEffect(() => {
    let timer: number | undefined

    function refresh() {
      const now = new Date()
      setToday(localDayKey(now))
      window.clearTimeout(timer)
      timer = window.setTimeout(refresh, msUntilNextDay(now))
    }

    // A timer does not run while the device sleeps, so the day is also
    // checked whenever the page comes back into view.
    document.addEventListener('visibilitychange', refresh)
    refresh()

    return () => {
      document.removeEventListener('visibilitychange', refresh)
      window.clearTimeout(timer)
    }
  }, [])

  return today
}
```

`refresh` always works from the clock, never from a count of elapsed time,
so a timer that fires early or late corrects itself.

### 3. `frontend/src/clock/CurrentDate.tsx`

Exactly this content:

```tsx
import { formatDay } from './today.ts'
import { useToday } from './useToday.ts'

/** Today's date, written out in the language of the user's browser. */
export function CurrentDate() {
  const today = useToday()

  return <time dateTime={today}>{formatDay(today)}</time>
}
```

### 7. `frontend/src/clock/today.test.ts` – 12 tests

Build every `Date` from local calendar values (`new Date(2026, 10, 17, …)`),
never from a UTC text, so that the tests give the same result in every time
zone.

Group `localDayKey` (4):

1. `writes the day as YYYY-MM-DD` – 17 November 2026, noon → `2026-11-17`.
2. `pads single-digit months and days` – 5 January 2027 → `2027-01-05`.
3. `uses the local day up to the last millisecond before midnight` –
   23:59:59.999 on the 17th → `2026-11-17`.
4. `uses the new local day from midnight` – 00:00:00.000 on the 18th →
   `2026-11-18`.

Group `msUntilNextDay` (3):

5. `counts the time left in the day` – 23:59:50 → `10_000`.
6. `is a whole day at midnight` – from 00:00 on the 18th, adding the result
   lands exactly on 00:00:00.000 of the 19th (check the day key and the
   hours, minutes, seconds and milliseconds; do not assert 86 400 000).
7. `crosses the end of a month and of a year` – 23:00 on 31 December 2026 →
   `3_600_000`, landing on `2027-01-01`.

Group `formatDay` (5):

8. `writes the day out in British English` – `formatDay('2026-11-17', 'en-GB')`
   matches `/^Tuesday,? 17 November 2026$/` (the comma depends on the
   version of the language data: Node and Chromium differ).
9. `writes the day out in American English` – `en-US` →
   `Tuesday, November 17, 2026`.
10. `writes the day out in German` – `de-DE` → `Dienstag, 17. November 2026`.
11. `keeps the day of the key at both ends of a month` – `2026-03-01` is a
    Sunday the 1st of March and `2026-12-31` a Thursday the 31st of December
    (British English, with the same optional comma).
12. `refuses text that is not a day` – `formatDay('today', 'en-GB')` throws a
    `RangeError`.

### 8. `frontend/src/clock/CurrentDate.test.tsx` – 5 tests

Use `vi.useFakeTimers()` before each test and `vi.useRealTimers()` after
each. Set the clock with `vi.setSystemTime(new Date(2026, 10, 17, …))`
(local values again). Advance timers inside `act`. Find the `time` element
with `container.querySelector('time')` and fail clearly if it is missing.

1. `shows today's date, written out, with the day in machine-readable form`
   – at 14:30 on the 17th: `datetime` is `2026-11-17`; the text equals
   `formatDay('2026-11-17')` and contains `17` and `2026`.
2. `changes at midnight without being loaded again` – start at 23:59:50;
   after 9 999 ms the `datetime` is still `2026-11-17`; one millisecond
   later it is `2026-11-18` and the text equals `formatDay('2026-11-18')`.
3. `keeps changing at every following midnight` – start at 23:59:50, advance
   10 s, then 24 hours → `2026-11-19`; another 24 hours → `2026-11-20`.
4. `catches up when the page comes back into view after the device slept` –
   render at 22:00 on the 17th; move the clock to 08:00 on the 19th with
   `vi.setSystemTime` (this runs no timers): the element still says the
   17th. Dispatch a `visibilitychange` event on `document`: it says the
   19th. Advance 16 hours: it says the 20th (the timer was set again from
   the new time).
5. `leaves no timer and no listener behind when it is removed` – spy on
   `document.addEventListener` and `document.removeEventListener`; after
   rendering, `vi.getTimerCount()` is 1 and exactly one `visibilitychange`
   listener was added; after unmounting, the timer count is 0 and the
   `visibilitychange` calls to `removeEventListener` equal those to
   `addEventListener`.

### 11. `frontend/e2e/date.spec.ts` – 5 browser tests

Exactly this content. The language and time zone are emulated with
`test.use`, and the clock with Playwright's `page.clock`, set before the
page is loaded:

```ts
import type { Page } from '@playwright/test'
import { expect, test } from './fixtures'

function currentDate(page: Page) {
  return page.getByRole('banner').locator('time')
}

test.describe('current date', () => {
  test.describe('for a British user in London', () => {
    test.use({ locale: 'en-GB', timezoneId: 'Europe/London' })

    test("shows today's date in the top bar", async ({ page }) => {
      await page.clock.setFixedTime(new Date('2026-11-17T12:00:00Z'))
      await page.goto('/')

      await expect(currentDate(page)).toHaveText(/^Tuesday,? 17 November 2026$/)
      await expect(currentDate(page)).toHaveAttribute('datetime', '2026-11-17')
    })

    test('changes at midnight without a reload', async ({ page }) => {
      await page.clock.install({ time: new Date('2026-11-17T23:59:50Z') })
      await page.goto('/')
      await expect(currentDate(page)).toHaveAttribute('datetime', '2026-11-17')

      await page.clock.fastForward(15_000)

      await expect(currentDate(page)).toHaveAttribute('datetime', '2026-11-18')
      await expect(currentDate(page)).toHaveText(/^Wednesday,? 18 November 2026$/)
    })

    test('sits between the tagline and the Details button, in the quiet text colour', async ({
      page,
    }) => {
      await page.setViewportSize({ width: 1366, height: 768 })
      await page.clock.setFixedTime(new Date('2026-11-17T12:00:00Z'))
      await page.goto('/')

      const date = currentDate(page)
      await expect(date).toBeInViewport({ ratio: 1 })
      await expect(date).toHaveCSS('color', 'rgb(169, 172, 179)')
      await expect(date).toHaveCSS('font-size', '14px')
      const tagline = await page.getByText('The World of Motocross, Connected.').boundingBox()
      const dateBox = await date.boundingBox()
      const details = await page
        .getByRole('banner')
        .getByRole('button', { name: 'Details', exact: true })
        .boundingBox()
      if (tagline === null || dateBox === null || details === null) {
        throw new Error('The tagline, the date or the Details button is not visible.')
      }
      expect(dateBox.x).toBeGreaterThan(tagline.x + tagline.width)
      expect(dateBox.x + dateBox.width).toBeLessThan(details.x)
      // The date and the button are pushed to the right-hand end of the bar.
      expect(details.x - (dateBox.x + dateBox.width)).toBeLessThanOrEqual(16)
      expect(1366 - (details.x + details.width)).toBeLessThanOrEqual(16)
    })
  })

  test.describe('for an American user in Los Angeles', () => {
    test.use({ locale: 'en-US', timezoneId: 'America/Los_Angeles' })

    test('shows the day where the user is, in the American form', async ({ page }) => {
      // 02:00 in London on the 17th is still the evening of the 16th in Los Angeles.
      await page.clock.setFixedTime(new Date('2026-11-17T02:00:00Z'))
      await page.goto('/')

      await expect(currentDate(page)).toHaveText('Monday, November 16, 2026')
      await expect(currentDate(page)).toHaveAttribute('datetime', '2026-11-16')
    })
  })

  test.describe('for a German user in Tokyo', () => {
    test.use({ locale: 'de-DE', timezoneId: 'Asia/Tokyo' })

    test('shows the day where the user is, in German', async ({ page }) => {
      // 20:00 in London on the 17th is already the morning of the 18th in Tokyo.
      await page.clock.setFixedTime(new Date('2026-11-17T20:00:00Z'))
      await page.goto('/')

      await expect(currentDate(page)).toHaveText('Mittwoch, 18. November 2026')
      await expect(currentDate(page)).toHaveAttribute('datetime', '2026-11-18')
    })
  })
})
```
