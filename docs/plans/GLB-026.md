# GLB-026 – The stage says when the browser cannot show the globe

**Phase:** 3 – Interactive 3D Earth
**Track:** B (see `TASKS.md`, "Two tracks")
**Depends on:** FND-058, FND-059 and FND-060 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §6 and §8, `docs/WORKFLOW.md`, `TASKS.md`
("Two tracks" and the entry of this task), `PROGRESS.md` (PLAN-053),
`TESTING.md` ("The browser of the browser tests" and "The browser of
the globe tests"), `frontend/src/layout/AppShell.tsx`,
`frontend/src/test/setup.ts`, `frontend/src/test/screen.ts`,
`frontend/e2e/fixtures.ts`, `frontend/e2e/globe/fixtures.ts`

## Objective

In a browser that gives a page no 3D picture, the globe stage says in
two plain sentences that the globe cannot be shown and what a person
can do, and the rest of the application works as before.

## Why

The engine of the globe draws the Earth as a 3D picture. Started in a
browser that gives none, it puts up a panel of its own and logs an
error (planner's trial for PLAN-053). Since FND-059 that is the browser
of every test outside the project of the globe, and it is the browser
of some people: an old one, one with its 3D graphics switched off, a
computer with nothing to draw them with. So the page has to know what
to do there before the globe is put into it. This task has no globe in
it. Where the browser can draw, the stage is as empty as it was; the
globe itself comes with GLB-027 and GLB-002.

## What this task is, and what it is not

- **It is** the question, `browserDraws3D()` in the new module
  `frontend/src/globe/drawing.ts`: it asks the browser for a 3D picture
  on a drawing surface of its own and gives the picture back at once.
- **It is** the component `GlobeStage`
  (`frontend/src/globe/GlobeStage.tsx`, with its style sheet): it asks
  once, when it is first shown, and where the answer is no it shows the
  two sentences.
- **It is** a new property of the shell, `stage`: what the globe stage
  shows. The application gives it `<GlobeStage />`.
- **It is** a stand-in for the drawing surface in the unit tests
  (`frontend/src/test/drawing.ts`), put in place before every test:
  the test environment gives a page no picture to draw on.
- **It is** 28 new unit tests and 13 new browser tests, and the
  documents: `TESTING.md`, `ARCHITECTURE.md`, `README.md` and
  `CHANGELOG.md`.
- **It is not** a globe, and nothing of the engine is loaded or
  started: `@cesium/engine` is imported by nothing of this task.
- **It is not** what the stage says when the engine fails to load or
  to start in a browser that does draw: that is GLB-004.
- **It is not** a new package, and no setting of the tests changes.
- **It is not** a change to any browser test that is there. Every one
  of the project `chromium` now runs with the two sentences in the
  stage, and passes as it is.

## Design in short

`frontend/src/globe/drawing.ts`:

- `browserDraws3D(): boolean` makes a `canvas` that is not put into the
  page, asks it for a picture of the kind `webgl2`, and says no where
  the browser gives `null`. Otherwise it gives the picture back
  (`getExtension('WEBGL_lose_context')?.loseContext()`) and says yes.
  The function names nothing outside itself, so that a browser test can
  hand it to a page as it stands.

`frontend/src/globe/GlobeStage.tsx`:

- `NO_GLOBE` is `The 3D globe cannot be shown in this browser.` and
  `NO_GLOBE_HELP` is `It needs 3D graphics, which this browser does not
  offer or has switched off. Try an up-to-date browser, or switch on
  graphics acceleration (also called hardware acceleration) in the
  settings of this one.`
- `GlobeStage()` keeps the browser's answer in a state that is filled
  when the component is first shown (`useState(browserDraws3D)`). Where
  the answer is yes it shows nothing. Where it is no it shows a `div`
  with two paragraphs, the first sentence and then the second.
- The style sheet puts the `div` over the whole stage and the words in
  its middle: the first sentence in the larger size, the second in the
  colour of secondary text, both in lines no longer than 32 times the
  size of the text of the page, 24 pixels from the edge of the stage.
  The words are held in the middle by a margin above the first and
  below the second (`margin-top: auto`, `margin-bottom: auto`), not by
  `justify-content: center`: in a stage too low for the words such
  margins are nothing, the words start at the top, and the stage
  scrolls to their end.

`frontend/src/layout/AppShell.tsx` gets the property `stage` and shows
it inside the `main` region, which keeps its name, "Globe".
`frontend/src/App.tsx` gives it `<GlobeStage />`.

`frontend/src/test/drawing.ts`, the stand-in, in the manner of
`screen.ts`:

- `installDrawing()` puts a `getContext` of its own on every `canvas`
  of the test environment and makes it a current browser that was
  asked for nothing: it gives the kinds `webgl` and `webgl2` and takes
  pictures back. `setup.ts` calls it before every test.
- `browserGives(kinds, takesBack = true)` makes it a browser that gives
  these kinds and no other.
- `picturesAskedFor()` gives the kinds the page asked for, in order,
  and `picturesHeld()` how many pictures the page was given and has not
  given back.
- What it gives is an object with `getExtension`, which hands out
  `loseContext` under the name `WEBGL_lose_context` and nothing else.
  No unit test draws.

## What the trial settled

- **Only the newer kind of 3D picture counts.** The engine as it is
  installed (`@cesium/engine` 26.5.0, `Source/Renderer/Context.js`)
  asks a browser that knows the kind `webgl2` for that kind and for no
  other; it takes the older kind, `webgl`, only in a browser that does
  not know the newer at all, or when it is told to
  (`requestWebgl1`), which nothing of MotoSphere does. No browser of
  the tests is a browser with the older kind alone, so the globe has
  not been seen drawn with it. The question asks for `webgl2`, and a
  browser with only the older kind is told that the globe cannot be
  shown. That is recorded in `TESTING.md`.
- **What the two browsers of the tests say.** Handed to a page of the
  built site, the question says no in the project `chromium` and yes
  in the project `globe`, and the browser says nothing on the console
  in either.
- **The picture has to be given back.** In the project `globe`, the
  question without its line of giving back, asked forty times in a row
  in one go, made the browser log `WARNING: Too many active WebGL
  contexts. Oldest context will be lost.` 25 times (the browser keeps
  sixteen, and the page had asked once itself). Asked forty times with
  a pause after each, the same question logged nothing: the browser
  had cleared the pictures away by itself in between. So the browser
  test asks forty times in a row, in one `page.evaluate`. The question
  as it is logs nothing that way.
- **The test environment gives no picture at all, and says so
  loudly.** Without the stand-in, jsdom answers `getContext` with
  `null` and prints `Not implemented: HTMLCanvasElement's getContext()
  method: without installing the @napi-rs/canvas npm package` each time
  a test shows the application: 12 times in the 406 unit tests that
  were there, and every such test would show the two sentences. With
  the stand-in a unit test starts in a browser that draws, the stage is
  empty as before, and nothing is printed. No unit test that was there
  had to change but the helper of `AppShell.test.tsx`, which gives the
  shell its new property.
- **No role for the sentences.** They are two paragraphs in the `main`
  region, which a screen reader reads as it reads any text there. A
  `role="status"` would be a second status beside the data status of
  the top bar, and the sentences do not change while the page is open,
  so there is nothing for it to announce.
- **Asked once.** What a browser can draw does not change while the
  page is open. The component asks when it is first shown and keeps the
  answer; shown again, it does not ask again. In development React
  shows a component twice (`StrictMode`) and may ask twice; nothing is
  held afterwards, and the sentences are there once.
- **The words on small screens.** On screens of 320 by 568, 390 by 844,
  568 by 320 and 768 by 1024 pixels both sentences are whole inside the
  stage and the page does not scroll. On a screen of 320 by 240 the
  stage is too low for the words: they start 24 pixels under its top,
  and a turn of the mouse wheel over the stage brings the end of the
  second sentence 24 pixels above its bottom. With
  `justify-content: center` in the place of the two margins that test
  fails.
- **No file of the engine is asked for.** Nothing of this task loads
  the engine, so a test of that cannot fail today for a defect of the
  task itself; it is there for the tasks that put the globe in. That it
  can fail is shown by a prove-it step that makes the stage fetch one
  file of the engine's folder.

+/** What a browser does when a page asks it for a picture to draw on. */
+interface Browser {
+  /** The kinds of picture it gives. */
+  kinds: readonly string[]
+  /** Whether it hands out the way to give a 3D picture back. */
+  takesBack: boolean
+}
+
+/** A current browser: it gives both kinds of 3D picture and takes them back. */
+const CURRENT: Browser = { kinds: ['webgl', 'webgl2'], takesBack: true }
+
+let browser = CURRENT
+let asked: string[] = []
+let held = 0
+
+/**
+ * A stand-in for the part of the browser that gives a page a picture to
+ * draw on, which the test environment does not have. It gives the kinds the
+ * test has set, as something that can be given back and nothing more: no
+ * test draws.
+ */
+function getContext(kind: string): object | null {
+  asked.push(kind)
+  if (!browser.kinds.includes(kind)) {
+    return null
+  }
+  const { takesBack } = browser
+  let mine = true
+  held += 1
+  return {
+    getExtension(name: string) {
+      if (name !== 'WEBGL_lose_context' || !takesBack) {
+        return null
+      }
+      return {
+        // A picture is given back once, however often that is said.
+        loseContext() {
+          if (mine) {
+            mine = false
+            held -= 1
+          }
+        },
+      }
+    },
+  }
+}
+
+/** Puts the stand-in in place, as a current browser that was asked for nothing. */
+export function installDrawing(): void {
+  browser = CURRENT
+  asked = []
+  held = 0
+  Object.defineProperty(HTMLCanvasElement.prototype, 'getContext', {
+    configurable: true,
+    writable: true,
+    value: getContext,
+  })
+}
+
+/** Makes the browser one that gives these kinds of picture and no other. */
+export function browserGives(kinds: readonly string[], takesBack = true): void {
+  browser = { kinds, takesBack }
+}
+
+/** The kinds of picture the page asked for, in the order it asked. */
+export function picturesAskedFor(): readonly string[] {
+  return [...asked]
+}
+
+/** How many pictures the page was given and has not given back. */
+export function picturesHeld(): number {
+  return held
+}
