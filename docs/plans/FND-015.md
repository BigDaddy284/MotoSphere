# FND-015 – Collapsible side panels

**Phase:** 1 – Foundation
**Depends on:** FND-025 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §8, `DESIGN.md` §12.1, `docs/WORKFLOW.md`, `ARCHITECTURE.md` §3

## Objective

The user can give the globe the whole screen. Each side panel has a button
in the top bar that closes it and opens it again, by mouse or by keyboard.
The globe stage takes the room of a closed panel. The choice is remembered
for the browser session: it survives a reload and ends with the tab.

## Design in short

- Two buttons in the top bar: **Sections** at the left end, **Details** at
  the right end. Their names never change; `aria-expanded` says whether the
  panel is open, and `aria-controls` points at the panel.
- A closed panel stays in the page with the `hidden` attribute, so its
  content keeps its state and leaves the keyboard order and the
  accessibility tree.
- The grid's side columns become `auto` and the panels carry their own
  width, so a hidden panel's column shrinks to nothing without any extra
  state in the style sheet.
- The choice is kept in session storage under `motosphere.panel.sections`
  and `motosphere.panel.details` with the values `open` and `closed`. Any
  other value, or storage that cannot be used, means open.
- No animation in this task: the panel appears and disappears at once.

### 1. `frontend/src/layout/usePanelOpen.ts`

Exactly this content:

```ts
import { useState } from 'react'

/** The side panels the user can close and open. */
export type PanelName = 'sections' | 'details'

const KEY_PREFIX = 'motosphere.panel.'

// The choice is kept in session storage: it survives a reload and ends with
// the browser tab. Storage can be unavailable (some privacy settings block
// it); the panels then simply start open.
function readOpen(name: PanelName): boolean {
  try {
    return window.sessionStorage.getItem(KEY_PREFIX + name) !== 'closed'
  } catch {
    return true
  }
}

function writeOpen(name: PanelName, open: boolean): void {
  try {
    window.sessionStorage.setItem(KEY_PREFIX + name, open ? 'open' : 'closed')
  } catch {
    // Not remembered: the choice still holds until the page is reloaded.
  }
}

/**
 * Whether a side panel is open, and a function that closes or opens it.
 * Panels start open; the user's choice is remembered for the session.
 */
export function usePanelOpen(name: PanelName): [open: boolean, toggle: () => void] {
  const [open, setOpen] = useState(() => readOpen(name))

  function toggle() {
    const next = !open
    writeOpen(name, next)
    setOpen(next)
  }

  return [open, toggle]
}
```

### 2. `frontend/src/layout/AppShell.tsx`

Exactly this content:

```tsx
import type { ReactNode } from 'react'
import styles from './AppShell.module.css'
import { usePanelOpen } from './usePanelOpen.ts'

const SECTIONS_PANEL_ID = 'sections-panel'
const DETAILS_PANEL_ID = 'details-panel'

interface AppShellProps {
  /** The application name, shown as the page's main heading. */
  name: string
  /** One line under the name. */
  tagline: string
  /** What the sections panel shows. */
  sections: ReactNode
}

/**
 * The fixed regions of the screen: a top bar, the sections panel on the left,
 * the globe stage in the centre and the details panel on the right. The stage
 * always gets the largest share of the screen, and takes the room of a side
 * panel that the user closes with its button in the top bar.
 */
export function AppShell({ name, tagline, sections }: AppShellProps) {
  const [sectionsOpen, toggleSections] = usePanelOpen('sections')
  const [detailsOpen, toggleDetails] = usePanelOpen('details')

  return (
    <div className={styles.shell}>
      <header className={styles.topBar}>
        <button
          type="button"
          className={styles.toggle}
          aria-expanded={sectionsOpen}
          aria-controls={SECTIONS_PANEL_ID}
          onClick={toggleSections}
        >
          Sections
        </button>
        <h1 className={styles.name}>{name}</h1>
        <p className={styles.tagline}>{tagline}</p>
        <button
          type="button"
          className={`${styles.toggle} ${styles.toggleEnd}`}
          aria-expanded={detailsOpen}
          aria-controls={DETAILS_PANEL_ID}
          onClick={toggleDetails}
        >
          Details
        </button>
      </header>
      <nav
        id={SECTIONS_PANEL_ID}
        className={styles.sections}
        aria-label="Sections"
        hidden={!sectionsOpen}
      >
        {sections}
      </nav>
      <main className={styles.stage} aria-label="Globe" />
      <aside
        id={DETAILS_PANEL_ID}
        className={styles.details}
        aria-label="Details"
        hidden={!detailsOpen}
      >
        <p className={styles.hint}>Select something on the globe to see its details here.</p>
      </aside>
    </div>
  )
}
```

The buttons come first and last inside the top bar, so the keyboard order
of the page is now: Sections button, Details button, then the section list.

### 7. `frontend/e2e/keyboard.ts`

Exactly this content:

```ts
import type { Locator, Page } from '@playwright/test'

const MAX_PRESSES = 20

/**
 * Presses Tab, as a keyboard user would, until the element has focus. Fails
 * if the element cannot be reached that way.
 */
export async function tabTo(page: Page, target: Locator): Promise<void> {
  for (let presses = 0; presses < MAX_PRESSES; presses += 1) {
    await page.keyboard.press('Tab')
    if (await target.evaluate((element) => element === document.activeElement)) {
      return
    }
  }
  throw new Error(`${target.toString()} was not reached with ${MAX_PRESSES} presses of Tab`)
}
```

## Acceptance criteria

1. Each side panel closes and opens with its own button in the top bar, by
   click, Enter and Space, without affecting the other panel.
2. `aria-expanded` on each button always matches its panel, and
   `aria-controls` names the panel.
3. The globe stage takes the room of a closed panel: at 1366×768 it runs
   from 0 to 1006 without the sections panel, from 220 to 1366 without the
   details panel, and from 0 to 1366 with both closed; the page never
   scrolls.
4. A closed panel's content cannot be reached with Tab.
5. The choice survives a reload and does not carry over to a new tab.
   Unknown stored values and unusable storage both mean open, and the
   buttons keep working.
6. With both panels open the layout is unchanged: `e2e/layout.spec.ts`
   passes unmodified.
7. `npm test` reports 96 passed in 6 files; `npm run e2e` reports 30
   passed; every other gate passes.
8. Only the files under "Scope" changed; no dependency changed.
