# DAT-026 – The models and the migrated schema agree

**Phase:** 2 – Data store and published data
**Depends on:** DAT-033 (merged)
**Base branch:** `main`
**Read first:** `CLAUDE.md` §3, §11, §12, `docs/WORKFLOW.md`, `DATABASE.md`
("How the schema changes", "The rules every table keeps", "What the store
relies on in SQLite"), `TESTING.md` ("A data store of its own for every
test"), `backend/src/motosphere/db/migrations.py`,
`backend/src/motosphere/db/base.py`, `backend/tests/conftest.py`

## Objective

A test fails whenever the models describe a schema other than the one the
migrations build, and its message says in plain words where the two
differ.

## Why

The models say what the store's tables are, to the code that reads and
writes rows. The migrations build the tables, in every store there is.
Nothing holds the two together yet: a model could get a column that no
migration adds, and every test that makes its tables from the models would
still pass, while the real store, which only the migrations build, is
without the column. The first table comes with the next task (DAT-006), so
the test that holds the two together has to be there before it.

## Design in short

- **One new module, `motosphere.db.compare`, with one function.**
  `differences(*, models, migrated)` is given two stores and returns a
  list of plain sentences, one for each table, index, view or trigger
  that is not the same in both. Stores with the same schema give an empty
  list. It writes to neither.
- **What is compared are the statements SQLite keeps.** SQLite keeps, in
  the file (`sqlite_master`), the statement by which each table, index,
  view and trigger was made. `differences` reads them from both stores
  and compares them, by kind and name. What SQLite keeps for itself (every
  name that begins with `sqlite_`) is left out.
- **Two statements are the same when they are the same words in the same
  order.** White space, comments of both kinds, large and small letters,
  and quotes around a name (of the three kinds SQLite takes) make no
  difference. Text in single quotes is compared letter for letter.
- **Three sentences.** For what one store has and the other has not:
  `Only the models have the table rider.` and
  `Only the migrations have the index ix_rider_name.` For what both have
  and is not the same:
  `The table rider is not the same in both. Where they first differ, the
  models say ... and the migrations say ....` (one line), with the words
  of both from where the column or constraint begins that differs: after
  the last comma or opening bracket before the first word that differs,
  to five words after it, and ` ...` where more follow.
- **The sentences come kind by kind and name by name** (`index`, `table`,
  `trigger`, `view`, as SQLite calls them).
- **One test holds the real models to the real migrations**:
  `test_the_models_and_the_migrations_agree` brings the store of the
  fixture to the newest schema with `migrate`, makes the tables of
  `Base.metadata` in a second real file, and `differences` must find
  nothing. When it fails, its message is the sentences, one to a line.
  Both are empty today, so the other 47 tests prove that the comparison
  can fail, with two models and migrations of their own.
- No new package, no model, no table, no migration. No existing file of
  code changes.

## What the task left open, and what the trial settled

- **How the two are compared.** The task said "tables, columns with their
  types and whether they may be empty, keys, constraints and indexes, by
  name". All of that, and more, is in the statement SQLite keeps: that a
  table is strict, that a key is never given twice, a value of its own,
  the text of a check, what a foreign key does when its row goes, and
  over which rows an index is. Comparing the statements therefore forgets
  nothing, also nothing that a later task adds to a table, and needs no
  list of the parts of a table. The other way, asking SQLite or
  SQLAlchemy for the parts of each table and comparing part by part, has
  such a list, and is only as good as it. No further package was looked
  at: `DATABASE.md` gives the reasons against Alembic (DAT-004), and they
  stand.
- **The order of the columns counts, and so does the order of the
  constraints.** The words are compared in their order, so a column that
  stands elsewhere is a difference. That is meant: a store that was built
  in one go and one that was brought there step by step are then the same
  store, column for column. What follows from it is written into
  `DATABASE.md` by this task: a migration writes a table as its model
  makes it, and adds a column by building the table anew, because a
  column that SQLite adds in place stands after the two times. If this
  ever proves too strict, the place to change is the one function that
  gives the words of a statement, with a test for the change.
- **What the sentence shows.** Not the two statements whole, which for a
  table of twenty columns nobody reads, and not the one word that
  differs, which says too little: the words from the beginning of the
  column or constraint, in the form in which they are compared (small
  letters, no quotes, one space between them).
- **A migration can be written from the model, once.** The statements
  SQLAlchemy writes for a table and its indexes, run as text, build the
  same as the models (one test does exactly that). `DATABASE.md` says how
  to get them. A migration holds them as text and never asks the model,
  because the model changes later and the migration must not.
- **Where the function is.** In the package, not in a test file: the test
  files cannot use one another's functions (pytest runs with
  `--import-mode=importlib`), and the tasks that restore a snapshot
  (DAT-019, DAT-020) will want to compare two stores as well. Nothing in
  the pipeline calls it yet.
- **Where this ends**, each written into `DATABASE.md`: the test compares
  the newest schema only; it sees the models whose modules have been
  imported (DAT-006 sees to it that all are); and a search index or an
  index of places, which a model cannot say, is not compared yet.

### 1. `backend/src/motosphere/db/compare.py` – new, the whole file

```python
"""Comparing two stores: the schema the models describe and the one the migrations build.

The models say what the store's tables are, and the migrations build them
in every store there is. :func:`differences` says in plain words where the
two differ, so that a test can hold them together: a model cannot change
without a migration, nor a migration without its model.

It compares the statements by which SQLite itself says each table and
index is made, which SQLite keeps in the file. Two statements are the same
when they are the same words in the same order. How the words are spaced,
whether they are written large or small, quotes around a name and comments
make no difference; text in single quotes is compared letter for letter.
"""

import re
from itertools import zip_longest

from sqlalchemy import Engine

__all__ = ["differences"]

# The parts of a statement: white space and comments, which are left out;
# text in single quotes; a name in quotes of one of three kinds; a word;
# and any other sign, one at a time, but the signs of a comparison together.
_PART = re.compile(
    r"""
      (?P<nothing> \s+ | --[^\n]* | /\*.*?\*/ )
    | (?P<text> '(?:[^']|'')*' )
    | (?P<name> "(?:[^"]|"")*" | `(?:[^`]|``)*` | \[[^\]]*\] )
    | (?P<word> \w+ )
    | (?P<sign> [<>=!]+ | . )
    """,
    re.DOTALL | re.VERBOSE,
)
# How many words are shown after the first one that differs.
_SHOWN_AFTER = 5


def _statements(store: Engine) -> dict[tuple[str, str], str]:
    """Give the statement that makes each thing in the store, by its kind and name.

    The tables SQLite keeps for itself are left out: their names begin
    with ``sqlite_``, which no other name may.
    """
    with store.connect() as connection:
        held = connection.exec_driver_sql(
            "SELECT type, name, sql FROM sqlite_master WHERE name NOT LIKE 'sqlite~_%' ESCAPE '~'"
        ).all()
    return {(str(kind), str(name)): str(statement) for kind, name, statement in held}


def _words(statement: str) -> list[str]:
    """Give the words of a statement, in the one form in which they are compared."""
    words: list[str] = []
    for part in _PART.finditer(statement):
        found = part.group()
        if part.lastgroup == "name":
            words.append(found[1:-1].lower())
        elif part.lastgroup == "word":
            words.append(found.lower())
        elif part.lastgroup != "nothing":
            words.append(found)
    return words


def _from_where_they_differ(one: list[str], other: list[str]) -> tuple[str, str]:
    """Give the words of two statements that differ, around the first place where they do.

    The words begin after the last comma or opening bracket before that
    place, which is where the column or constraint begins that differs.
    Where one statement ends before the other, that place is its end.
    """
    first = next(place for place, (a, b) in enumerate(zip_longest(one, other)) if a != b)
    begins = max((place + 1 for place in range(first) if one[place] in {",", "("}), default=0)

    def shown(words: list[str]) -> str:
        more = " ..." if len(words) > first + _SHOWN_AFTER + 1 else ""
        return " ".join(words[begins : first + _SHOWN_AFTER + 1]) + more

    return shown(one), shown(other)


def differences(*, models: Engine, migrated: Engine) -> list[str]:
    """Say where the schemas of two stores differ, one plain sentence for each thing.

    ``models`` is a store whose tables were made from the models, and
    ``migrated`` one that the migrations built. The sentences come kind by
    kind (indexes, tables, triggers, views) and name by name. Stores with
    the same schema give an empty list. Nothing is written to either.
    """
    said = _statements(models)
    built = _statements(migrated)
    found: list[str] = []
    for kind, name in sorted(said.keys() | built.keys()):
        if (kind, name) not in built:
            found.append(f"Only the models have the {kind} {name}.")
        elif (kind, name) not in said:
            found.append(f"Only the migrations have the {kind} {name}.")
        else:
            one, other = _words(said[kind, name]), _words(built[kind, name])
            if one != other:
                here, there = _from_where_they_differ(one, other)
                found.append(
                    f"The {kind} {name} is not the same in both. Where they first differ, "
                    f"the models say `{here}` and the migrations say `{there}`."
                )
    return found
```

def running(*statements: str) -> Migration:
    """A migration that runs the statements, in order."""

    def migration(connection: Connection) -> None:
        for statement in statements:
            connection.exec_driver_sql(statement)

@pytest.fixture

def test_the_models_and_the_migrations_agree(store: Engine, tmp_path: Path) -> None:
    from_the_models = open_store(tmp_path / "models.sqlite3")

        Base.metadata.create_all(connection)
    migrate(store)

    found = differences(models=from_the_models, migrated=store)
