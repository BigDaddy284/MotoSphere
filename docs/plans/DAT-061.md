**Phase:** 2 – Data store and published data
**Track:** A (see `TASKS.md`, "Two tracks")
**Depends on:** DAT-059 and DAT-062 (the loading), DAT-060 (the source

## Objective

One command, `python -m motosphere countries`, loads the countries of
the reference file into the data store, and says what the loading
found.

## Why

Everything the loading needs is there and tested: the file and its
reader (DAT-012), the source of the countries (DAT-060), the loading
itself, which adds what the store does not have and changes no country
(DAT-059), the review queue for what the store says otherwise
(DAT-062), and the function that gives a command its store (DAT-063).
Nothing calls any of it. This task is the command that does, and with
it a store has its first rows of collected records: the 249 countries
of ISO 3166-1, which the tables of the tracks, the events and the
riders will refer to.

## What this task is, and what it is not

- **It is** one new module, `backend/src/motosphere/cli/countries.py`,
  with the command, and one line in `motosphere.cli.app` that puts it
  into the command line.
- **It is** 36 new tests: 17 that run the command for real against a
  real SQLite file, 17 of its sentences and its help, and 2 that run it
  in a process of its own.
- **It is** three existing tests of the help that no longer count
  blanks (see below).
- **It is** the documents: `README.md`, `DATABASE.md`, `TESTING.md`,
  `ARCHITECTURE.md`, `DATA_SOURCES.md` and `CHANGELOG.md`.
- **It is not** a change to the loading, to the source of the
  countries, to the review queue or to `store_to_work_on`. The command
  calls them as they are.
- **It is not** a change to a model or a migration. The schema stays at
  version 15.
- **It is not** the published data. What the site is given of the
  countries, and what it must say of their licence, is PUB-003.
- **It is not** a way to decide what waits in the review queue, or to
  list it: that is Phase 10.

## Design in short

`python -m motosphere countries` takes no argument. It

1. asks for the store the settings name, with `store_to_work_on`;
2. reads the reference file with `countries_of_the_project()`;
3. calls `load_countries` in one unit of work (`unit_of_work`);
4. writes what was found to standard output and ends with 0.

What it says, one line for each kind of thing (`report`):

| What was found | What is said |
|---|---|
| Always | "Of the 249 countries of release 4.20.1 of iso-codes, 249 were added to the data store … and none was there already." |
| Countries the store says something else of | "The data store says something else of 2 of them than the release does: FR, TR. They were left as they are, and what the release says waits in the review queue." |
| Countries of the store that the release does not have | "The data store has 1 country that the release does not have: XK. It was left as it is." |

The second and third line are there only when there is such a country.
"…" is the whole path of the store's file.

Nothing is loaded, with one sentence on standard error and the exit
code 1 (`EXIT_NOT_LOADED`), where the store is not ready
(`StoreNotReadyError`), the reference file is damaged
(`CountriesFileError`) or the store has a source called "iso-codes"
that is described otherwise (`CountriesSourceError`). The sentence is
the error's own.

## What the trial settled

- **The name is `countries`.** A command is named after what it works
  on, as `schema` is, and it has one thing to do with it. Commands that
  load other reference lists get names of their own.
- **The first line always adds up.** It names the number of countries
  the release has, and of them how many were added and how many were
  there as the release has them. What is left over is the number of the
  second line, which says "of them". So a person sees at once whether
  the store has every country of the release.
- **Run again, it says "none was added".** The entry of the task said
  "it writes nothing and says so". The command cannot know what the
  loading wrote, only what it found, and "none was added to the data
  store … and 249 were there already" is what a person needs to know.
  That nothing was written is held by the tests, which compare the file
  byte for byte.
- **A country the store says something else of is no failure.** The
  exit code is 0, with one such country or with many. The command did
  what it was asked to do, the loading changed nothing, and what
  follows is a person's decision in the review queue (DAT-062). An exit
  code of 1 would stop a scheduled job at a thing that is in order.
- **The codes are named, and nothing else.** Which field the store and
  the release differ in is in the review queue, item for item. The
  command names the countries by their codes of two letters, in the
  order the loading gives them: those of the release in the order of
  the file, those of the store alone in the order of their codes.
- **"The release", not "the file".** A person who runs the command sees
  no file. The sentences name the release of iso-codes, with its
  number, which is what the rows in the store name too.
- **Three refusals are caught, and nothing else.** The three errors are
  sentences made for a person, and each leaves the store as it was. Any
  other error is a fault of the program or of the store and reaches the
  caller as it is; the unit of work has then kept nothing. A test has
  the store itself refuse the last country of the file, with a trigger
  put there by hand, and finds none of the 248 before it.
- **The store is asked for first, the file is read second.** A person
  without a store is told so, not that a file of the pipeline is
  damaged.
- **One exit code for what is not loaded.** `migrate` and `schema` end
  with 1 for a store they refuse; so does this command, for each of its
  three refusals. It has a name of its own in the module,
  `EXIT_NOT_LOADED`.
- **Nothing is fetched.** The file is part of the pipeline. A test runs
  the command with the making of a network socket taken away.
- **The help of the command line gets wider.** `countries` is longer
  than the names there were, and argparse moves the column of what each
  command does two places to the right. Three existing tests held a
  command's line with its blanks counted, and fail. They now hold the
  name and what the command does, whatever the number of blanks between
  them, so that a longer name does not fail them again.
- **A damaged file is another file of the same folder.** The reader
  takes the name of the file from its module when it is called. The
  test gives it the name of the note that lies beside the file, which
  is no countries file; nothing of the reader is replaced.

## The existing tests that change, and why

Three tests of the help, one in each of `tests/unit/test_cli.py`,
`tests/unit/test_cli_migrate.py` and `tests/unit/test_cli_schema.py`.
Each held a line of the help as one text, with the blanks between the
command's name and what it does counted:
`"export    write the published data files"`,
`"version   print the MotoSphere version"`,
`"migrate   bring the data store to the newest schema"` and
`"schema    say which schema the data store has"`. With a longer name
in the list the column moves. Each test now takes the line apart at its
blanks and holds the name and the words after it. For `migrate` and
`schema` the test also holds that there is exactly one such line. No
command and no wording is dropped from what they hold.

## The new tests

`backend/tests/integration/test_countries_command.py`, 17 tests in 15
functions, against a real SQLite file that the real `migrate` command
made with the pipeline's own migrations, and with the reference file
that comes with the pipeline. What the command leaves is read with
SQLite alone:

- on a new store: the exit code 0, the first line, nothing on standard
  error; the 249 countries of the file in the store, each with its two
  codes and its name as the file has them; one source, "iso-codes",
  which every country names; nothing in the review queue;
- run again: "none was added … and 249 were there already", the file
  byte for byte as it was and nothing beside it;
- with one country and with three taken out by hand: they are added,
  and the others counted;
- with a name and a code of three letters changed by hand: the second
  line names both countries, they are as they were changed, two items
  wait in the review queue with what the file says, and run again the
  command says the same and writes nothing;
- with one such country: the second line in the singular;
- with one and with two countries put in by hand that the release does
  not have: the third line, singular and plural, and nothing written;
- all three lines in their order;
- no store: the sentence of `store_to_work_on` with its advice, the
  exit code 1, nothing on standard output, and neither the file nor its
  folder afterwards;
- a store that lacks a migration: its sentence, and the file as it was;
- a file `migrate` would refuse: what the real `migrate` command says
  of it, word for word;
- a damaged countries file: what the reader says, in one line, and the
  store as it was;
- a source described otherwise: what `source_of_the_countries` says,
  and the store as it was, with the country that was taken out still
  missing;
- the store refuses the last country of the file: the error reaches the
  caller, and no country and no source is in the store;
- nothing is fetched;
- a relative path of the store is taken from the current folder and
  named whole.

`backend/tests/unit/test_cli_countries.py`, 17 tests in 7 functions:
the first line with none, one and several countries added and there
already (7 cases); the second and third line, singular and plural, and
all three together with the codes in the order they were given (5
cases); the release is the one the loading names; the exit code; the
command in the help, its own help, and that it takes no argument.

`backend/tests/integration/test_command_line.py`, 2 new tests that run
`python -m motosphere` in a process of its own: `migrate`, then
`countries` twice, with the store read in between; and `countries`
without a store.

The backend tests go from 2552 to 2588.

+from motosphere.reference.countries_source import CountriesSourceError
+
+__all__ = ["EXIT_NOT_LOADED", "add_parser", "report", "run"]
+
+# The exit code when nothing was loaded and the store is as it was.
+EXIT_NOT_LOADED = 1
+
+
+def add_parser(commands: "argparse._SubParsersAction[argparse.ArgumentParser]") -> None:
+    """Register the ``countries`` command."""
+    parser = commands.add_parser(
+        "countries",
+        help="load the countries into the data store",
+        description=(
+            "Load the countries of the reference file that comes with the pipeline into "
+            "the data store. A country the store does not have is added. No country is "
+            "changed and none is taken out: what the file says otherwise of a country "
+            "waits in the review queue. Nothing is fetched. The store is the file the "
+            "setting MOTOSPHERE_STORE_PATH names, and it must be at the newest schema."
+        ),
+        allow_abbrev=False,
+    )
+    parser.set_defaults(handler=run)
+
+
+def _so_many(number: int, were: str) -> str:
+    if number == 0:
+        return f"none was {were}"
+    return f"1 was {were}" if number == 1 else f"{number} were {were}"
+
+
+def report(path: str, loaded: CountriesLoaded) -> str:
+    """Say what a loading into the store at ``path`` found, one sentence or two to a line.
+
+    The first line counts the countries of the release, those that were
+    added and those that were there already as the release has them. A
+    line follows for the countries the store says something else of, and
+    one for the countries the release does not have, each only where
+    there are such, with their codes of two letters.
+    """
+    otherwise = len(loaded.said_otherwise)
+    of_the_release = len(loaded.added) + len(loaded.as_they_were) + otherwise
+    lines = [
+        f"Of the {'1 country' if of_the_release == 1 else f'{of_the_release} countries'} "
+        f"of release {RELEASE} of iso-codes, {_so_many(len(loaded.added), 'added')} to the "
+        f"data store {path} and {_so_many(len(loaded.as_they_were), 'there already')}."
+    ]
+    if otherwise:
+        lines.append(
+            f"The data store says something else of {otherwise} of them than the release "
+            f"does: {', '.join(loaded.said_otherwise)}. "
+            f"{'It was left as it is' if otherwise == 1 else 'They were left as they are'}, "
+            "and what the release says waits in the review queue."
+        )
+    if loaded.not_in_the_file:
+        one = len(loaded.not_in_the_file) == 1
+        lines.append(
+            "The data store has "
+            f"{'1 country' if one else f'{len(loaded.not_in_the_file)} countries'} that the "
+            f"release does not have: {', '.join(loaded.not_in_the_file)}. "
+            f"{'It was left as it is' if one else 'They were left as they are'}."
+        )
+    return "\n".join(lines)
+
+
+def run(_arguments: argparse.Namespace, settings: Settings) -> int:
+    """Load the countries in one unit of work and write what was found to standard output.
+
+    A store that is not ready gives its one sentence on standard error
+    and the exit code 1, and so does a loading that is refused: by a
+    countries file that is damaged, or by a source called as the source
+    of the countries that is described otherwise. The store is then as
+    it was. Countries the store says something else of are no failure:
+    they are named, and the exit code is 0.
+    """
+    try:
+        store = store_to_work_on(settings)
+    except StoreNotReadyError as error:
+        sys.stderr.write(f"{error}\n")
+        return EXIT_NOT_LOADED
+    try:
+        countries = countries_of_the_project()
+        with unit_of_work(store) as work:
+            loaded = load_countries(work, countries)
+    except (CountriesFileError, CountriesSourceError) as error:
+        sys.stderr.write(f"{error}\n")
+        return EXIT_NOT_LOADED
+
+    sys.stdout.write(report(str(settings.store_path.resolve()), loaded) + "\n")
+    return 0

## Acceptance criteria

1. `python -m motosphere countries` is a command of the command line,
   with a line in the help and a help of its own, and takes no
   argument.
2. On a store at the newest schema with no country in it, the command
   ends with 0, says "Of the 249 countries of release 4.20.1 of
   iso-codes, 249 were added to the data store … and none was there
   already.", and the store then has the 249 countries of the file and
   the one source they name.
3. Run again, it says "none was added … and 249 were there already",
   and the file is byte for byte as it was.
4. A country the store does not have is added, and the first line
   counts it.
5. A country the store says something else of is named in a second
   line, is left as it is, and what the file says of it waits in the
   review queue. The exit code is 0.
6. A country of the store that the release does not have is named in a
   third line and left as it is.
7. A store that is not ready, a damaged countries file and a source
   described otherwise each give their own sentence in one line on
   standard error, nothing on standard output, the exit code 1, and a
   store that is byte for byte as it was.
8. The loading is one unit of work: where it fails in the middle,
   nothing of it is in the store.
9. No model, migration, or other command changed, and of the existing
   tests only the three named under "The existing tests that change".
10. The six documents say what the command does, what it says and what
    it refuses.
11. `python scripts/check.py` reports 19 of 19 gates, with 2588
    backend tests, and 36 tests more in all than `main` gives at the
    commit the branch starts from (3556 when that is `1e34fee`).
12. On the pull request both gates jobs are green (Linux and Windows)
    at the first attempt, and the three jobs after the gates are
    skipped.
13. Only the fourteen files under "Scope" changed.
